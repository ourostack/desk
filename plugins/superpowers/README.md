# Superpowers provider

This package contains the selected, unmodified source payload from [obra/superpowers](https://github.com/obra/superpowers) version 6.4.2, commit `8ca22dba9a94f28898bbce59f2537ff4d87c747d`. The MIT license and source notices remain intact. `upstream-sources.lock.json` records every selected source path and SHA-256; the upstream tree is `a29cb0f1f5600c82888f61eb6832025b3d9d3677`.

The root `plugin.json`, `.claude-plugin/plugin.json`, this README, and `hooks/copilot-hooks.json` are Ourostack-authored packaging, not upstream files. Copilot uses the explicit `PLUGIN_ROOT` adapter with a bounded timeout. Upstream source bytes remain locked separately from the one maintained wrapper described below.

The actual vendored `hooks/run-hook.cmd` is a generated downstream driver with no here-document. Both authored Copilot shell commands and the unchanged Claude hook declaration use that path. Unix delegates to the adjacent `hooks/run-hook-unix`; Windows retains the original batch body. This is a maintained Desk patch, not an upstream fix. Native Windows and real loaded/installed startup require separate qualification.

The original wrapper is preserved byte for byte at `hooks/upstream/run-hook.cmd`. Its existing lock entry keeps the original `sourcePath`, consumer `generatedPath`, upstream commit and upstream SHA-256, with one explicit `upstreamPath` naming those preserved bytes. When present, that path is the upstream hash/read/write target; entries without it retain their original meaning. This exception is limited to one `hooks/run-hook.cmd` evidence copy under the same vendor root. The upstream updater preserves it rather than replacing the maintained wrapper with raw source. Downstream output hashes are recorded separately and are never substituted for upstream hashes.

`scripts/superpowers-hook-compat.cjs` verifies the preserved raw hook against `upstream-sources.lock.json` before splitting its admitted layout. `hooks/run-hook-compat.provenance.json` separately records the raw source identity/hash, transform generator/hash and actual `hooks/run-hook.cmd`/Unix output hashes. Regenerate with `node scripts/superpowers-hook-compat.cjs generate`; check freshness without writing with `node scripts/superpowers-hook-compat.cjs verify`. The existing Superpowers refresh regenerates this packaging after a raw refresh and verifies it on a no-change refresh. An unknown upstream layout or stale output fails explicitly and requires requalification; no hook is silently omitted. A direct generic upstream-copy update does not qualify or regenerate downstream outputs; the maintained Superpowers refresh is the complete update path.

Generation reads all current inputs and destinations before publishing staged artifacts. Refresh prepares the raw payload, lock, compatibility artifacts and release metadata in an isolated candidate before touching the consumer tree. Publish failures restore only files still attributable to that transaction, preserving the previous complete set for a retry. If rollback cannot be verified or another writer changed a file, the error reports `UNKNOWN` and retains before-images, candidate hashes and available current bytes in the named `.superpowers-hook-transaction-*` recovery directory. Generation, verification and refresh refuse further work while that directory exists; inspect and reconcile it before retrying. This is bounded recovery, not an atomic multi-file or power-loss guarantee.

Before settlement, publishing rechecks the complete final input/output/removal map, including unchanged inputs and earlier replacements. Rollback removes newly created directories only while their observed identity, type and mode still match. Refresh retains an unresolved candidate and a consumer-root guard rather than deleting nested recovery evidence or admitting a retry after uncertain cleanup. Thrown errors include the in-memory recovery snapshot and secondary errors even when the journal cannot be persisted; inspect both the error and the retained paths before reconciliation.

Recovery-root identity is admitted before backup, evidence or journal use; rollback stages trusted in-memory before-images instead of trusting replacement backup files. A caller's guard must still exist with its original directory identity and captured journal bytes before consumer publication. Directory allocation records its attempted path before creation; failed creation or identity readback reports `UNKNOWN` without adopting a later inode. If guard rearming fails, the error explicitly states `retry BLOCKING NOT ESTABLISHED` and lists only paths observed to remain; do not infer that an absent guard protects a retry.

Guard journal transitions recheck the captured directory and previous journal bytes before writing, and advance expected content only after a successful readback. Forward replacement renews destination and caller-guard admission after parent-directory preparation; rollback verifies trusted restore bytes/mode and renews current destination ownership after restore staging, immediately before replacement. These checks refuse intervening changes without treating a correct post-write value as permission to overwrite.

The guard journal is bound to its original regular single-link file identity, not merely equal bytes. Existing transition, readback, cleanup-report and removal admissions reject symlinks, hardlink aliases and replacement files. Transition writes use an admitted non-following descriptor where supported; initial/rearm creation is exclusive. A substituted path remains untouched with `UNKNOWN` recovery.

[Journal admission](../../scripts/superpowers-hook-compat.cjs#L93-L143) acquires native BigInt path and descriptor stats before comparing exact inode/device IDs and nanosecond creation times. Those exact values belong to the in-memory authority record; persisted journal, recovery and provenance formats are unchanged. This corrects deterministic numeric precision loss, not a verified explanation of the separate Windows failure tracked in [#616](https://github.com/ourostack/desk/issues/616).

The shipped Superpowers version includes downstream packaging releases and is not the upstream payload version stated above. Owned fake-hook tests cover source declarations and copied-package paths; they do not establish native Windows qualification or successful real installed startup.

With Desk, invoke `desk:using-superpowers-with-desk` before using these skills. That contract binds plans, progress, authority, and the terminal endpoint to Desk; it does not change the upstream payload. A successful hook transport probe is not proof of engineering-method consumption, background inheritance, or complete host qualification.
