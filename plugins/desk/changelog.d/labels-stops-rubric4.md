Waste labels now say why the agent stopped, and a finished job is labeled within the hour of its finish. Labels `desk.factory.labels/3` add `stops[]`: one entry per wait for the operator the evaluator classified, `{ wait, why, confidence, evaluator_version }`, with `why` one of `decision`, `approval`, `acceptance`, `question`, `stopped_short` or `unknown`; `/1` and `/2` files stay valid ([`label-schema.js`](mcp/src/factory/label-schema.js)). The gate refuses a stop whose wait is not exactly one `human_wait` interval of the session (`evidence_unmatched`), two stops on one wait (`duplicate`), stops out of order (`order`), and a stop on a wait whose stop facts a rule already classifies, such as an API error, an interrupt or an open question tool (`inconsistent`). Stops describe waits, which are idle time, so they never enter class or waste totals. The [factory-evaluator rubric](skills/factory-evaluator/SKILL.md) is now rubric 4: it classifies each stop by whether the agent's authorization covered the next step, with worked examples, treats a "?" that asks permission the agent already had as `stopped_short`, and never copies text. The evaluator brief (`desk.factory.evaluator-brief/2`) gives each wait inside the job's own share its stop facts and the class a rule gives them as hints. Finished jobs labeled under an older rubric are labeled again once while their session logs are still on disk, but only once their facts carry stop facts (derive receipt `binding_version` 7). Labels now follow the facts: accepted labels record a fingerprint of the evidence they were made against, so a job that finished in a session that stays open is labeled once at its finish and again only when that session's facts are derived again with different evidence for the job, and an accepted run starts the job's attempts again, so a long-open session never counts as given up. The loop's evaluate step now asks for every finished job that needs labels and has no request, which recovers jobs whose request was never recorded or was settled while their sessions sat behind quarantined facts. The end of a turn and a finalize run start the loop worker when the evaluate step is due, and a new evaluation request makes the step due at once, so a finished job no longer waits for the next session start ([`evaluate-kick.js`](mcp/src/factory/evaluate-kick.js)); past the step's gap the kick starts a worker only when a job the runner can run waits, so requests this machine cannot prepare or run never keep it firing. A worker whose evaluate step labeled a job starts the next one as it ends, so the queue drains back to back, and the daily limit rises from 6 to 30 runs per machine as a safety ceiling rather than a pace; each run keeps its 1 US dollar and 15-minute limits, a job still runs at most once a day, and the sign-in probe and the per-token billing rule are unchanged. The step records the label lag, and the health record (`evaluator.label_lag_minutes`, `unlabeled_finished`, `unlabeled_unsupported`), the session-start evaluator line and a new `loop_alarm:label_lag` card, raised when the oldest unlabeled finished job is more than an hour old, all show it. The lag counts only jobs this machine can label and is still trying to: jobs with a Copilot or Codex session and jobs tried three times are named on the session-start line instead, and the alarm stays down while the evaluator cannot run at all, which has its own state.
