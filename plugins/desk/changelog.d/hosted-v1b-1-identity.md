Hosted Desk's signing key can now roll over without signing anyone out: after a rotation the gateway signs with the new key and still accepts tokens sealed with the previous one until `DESK_SIGNING_KEY_PREVIOUS_UNTIL`, 30 days later. Client ids are sealed with their own `DESK_CLIENT_KEY`, which falls back to `DESK_SIGNING_KEY` until a previous key is set, so registered clients keep working through a rotation. The gateway refuses any key holding whitespace and logs each key's fingerprint at start, never the key. See [`hosted/README.md`](../../hosted/README.md).

Hosted Desk has an accounts store for Ouro accounts, not yet used when signing in: Azure Table Storage tables for accounts, sign-in identities, invites and each account's desk binding, reached through the gateway's managed identity, with an in-memory twin for tests and local runs. An invite is a single-use link whose token the store never keeps, only its SHA-256; two people redeeming one invite at once get exactly one account mapping, an identity that already has an account can't redeem another, and an expired or used invite is refused. A 60-second account cache sits in front of the store and fails closed: every store call has a 5-second deadline, and when the store can't answer and the cached row is older than a minute, the account check refuses. The gateway tests now also run against Azurite in CI.

Hosted Desk can sign people in through the Ouro tenant (Microsoft Entra External ID), not yet switched on: the gateway sends the browser to the tenant with PKCE and a nonce, keeps the verifier and nonce in a cookie per sign-in so a code replayed through another browser is refused, validates the ID token (RS256 only, the discovery document's exact issuer, our client id, the tenant id, the nonce and a 5-minute clock skew, refetching the JWKS for an unknown key at most every 5 minutes), maps the identity to an Ouro account, redeems an invite for a new identity and checks the account's access and desk before issuing its own code. Invite links set a short-lived cookie and redirect to a token-free page. A tenant whose discovery document names another issuer stops the gateway at start; one that can't be reached shows a "try again shortly" page while GitHub sign-in keeps working. Without the tenant settings the gateway behaves as before.
