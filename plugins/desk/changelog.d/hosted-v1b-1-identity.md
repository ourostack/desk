Hosted Desk's signing key can now roll over without signing anyone out: after a rotation the gateway signs with the new key and still accepts tokens sealed with the previous one until `DESK_SIGNING_KEY_PREVIOUS_UNTIL`, 30 days later. Client ids are sealed with their own `DESK_CLIENT_KEY`, which falls back to `DESK_SIGNING_KEY` until a previous key is set, so registered clients keep working through a rotation. The gateway refuses any key holding whitespace and logs each key's fingerprint at start, never the key. See [`hosted/README.md`](../../hosted/README.md).

Hosted Desk has an accounts store for Ouro accounts, not yet used when signing in: Azure Table Storage tables for accounts, sign-in identities, invites and each account's desk binding, reached through the gateway's managed identity, with an in-memory twin for tests and local runs. An invite is a single-use link whose token the store never keeps, only its SHA-256; two people redeeming one invite at once get exactly one account mapping, an identity that already has an account can't redeem another, and an expired or used invite is refused. A 60-second account cache sits in front of the store and fails closed: every store call has a 5-second deadline, and when the store can't answer and the cached row is older than a minute, the account check refuses. The gateway tests now also run against Azurite in CI.

Hosted Desk can sign people in through the Ouro tenant (Microsoft Entra External ID), not yet switched on: the gateway sends the browser to the tenant with PKCE and a nonce, keeps the verifier and nonce in a cookie per sign-in so a code replayed through another browser is refused, validates the ID token (RS256 only, the discovery document's exact issuer, our client id, the tenant id, the nonce and a 5-minute clock skew, refetching the JWKS for an unknown key at most every 5 minutes), maps the identity to an Ouro account, redeems an invite for a new identity and checks the account's access and desk before issuing its own code. Invite links set a short-lived cookie and redirect to a token-free page. A tenant whose discovery document names another issuer stops the gateway at start; one that can't be reached shows a "try again shortly" page while GitHub sign-in keeps working. Without the tenant settings the gateway behaves as before.

Hosted Desk's tokens can now belong to Ouro accounts, switched on only when the Ouro tenant and accounts store settings are present (without them the gateway behaves exactly as before). Approving a client sends the browser to the Ouro tenant by default, or to a GitHub fallback for mapped GitHub user ids only while `DESK_GITHUB_SIGNIN=on`; both callbacks require the per-sign-in cookie. Codes and tokens carry the `accountId` and the sign-in time, and a refresh more than 30 days after that sign-in is refused, so every client signs in again at least monthly. Ari's existing connector keeps working: tokens sealed before accounts map to his account only when both his GitHub login and user id match, until `DESK_LEGACY_CUTOFF`. Every token request and MCP request checks the account, a 60-second sweep closes all sessions of an account whose Desk access is turned off, sessions are keyed by account, and a Desk child's Git author comes from the account's binding. A new `/healthz/deep` reports, by check name only, whether Ouro sign-in, the accounts store and the mapped accounts are available, and the deploy workflow now waits for it. See [`hosted/README.md`](../../hosted/README.md).

Hosted Desk has a provisioning script for the Ouro tenant, `hosted/infra/provision-identity.mjs`, not yet run against Azure: it builds or reconciles each tenant's email one-time code, Apple provider, user flow, the gateway's app registration and its 12-month client secret (written to Key Vault through stdin), the automation app for the daily identity checks, the gateway's and the checks' managed identities with their roles, the accounts storage account and the GitHub environment `identity`, and records every non-secret id in `hosted/infra/identity-<env>.json`. It also imports Apple keys, seeds Ari's account and invite, copies or clears staging's GitHub App secrets, and runs the client-key migration and the test-only signing-key rotation, logging fingerprints only. `provision.sh` now writes every Container App change as the whole app as Azure shows it (`hosted/infra/app-yaml.mjs`), so a rerun keeps the client key, the previous signing key, Key Vault references and every other secret, env var, volume and identity; it adds missing secrets without putting a value in a command's arguments, reads the Ouro sign-in settings from `identity-<env>.json`, and with `STAGE=staging` makes a scale-to-zero rehearsal app, `ouro-desk-hosted-staging`, on a pinned image. Because az drops the identity map from a YAML update and fills secret values before sending, `provision.sh` attaches the gateway identity with `az containerapp identity assign` first, and every Container App write is read back and stops unless each secret, Key Vault reference and identity is still there. Staging's gateway has its own identity, `id-ouro-desk-hosted-staging`, and the signed-in operator is given the Key Vault and accounts-storage data roles the script needs.

Staging never holds production's image-pull identity `ouro-prod-services-mi`, which also has roles on production storage and the email domain: `provision.sh` with `STAGE=staging` pulls with staging's own identity, `id-ouro-desk-hosted-staging`, creating it if missing and granting it AcrPull on the registry only (read first, so a rerun writes nothing), and both scripts refuse a staging app that holds the production identity, before and after each write. A Container App update that az can't send because Azure lists a Key Vault reference without a value now stops with a clear message instead of az's traceback, and the check after an update compares with the app as it was before the identity attach.

Hosted Desk has daily identity checks, not yet run against Azure: `hosted/infra/identity-checks.mjs` and the scheduled workflow `.github/workflows/identity-checks.yml` check, for each Ouro tenant, that the gateway's Entra client secret and the Apple client secret end more than 30 days out and that production's `DESK_LEGACY_CUTOFF` is set a day after the release. Under Apple outcome A the workflow also renews the Apple client secret on the first of each month by switching the Apple provider to the tenant's other key, never one tagged `revoked`. It records the renewal date only after Graph accepts the change. Under outcome B, `--record-apple-upload` records a manual upload instead. A failed run opens or comments on one `identity-alert` issue that holds only check names and dates. The automation app now also gets Graph's `Application.Read.All`, so it can read the gateway's client-secret expiry. When az can't send a Container App update because of a Key Vault reference without a value, the message now says which earlier writes in the run were already sent.

The identity checks now prove what they act on. An imported Apple key is tagged with its Key ID (from `AuthKey_<Key ID>.p8`, or `--apple-key-id`) and its fingerprint, and the import records the Key ID in `identity-<env>.json`. Provider creation and renewal send a key only when its tags match the recorded Key ID and the key itself. A renewal counts only when the provider, read back, shows the new Key ID. The gateway's client secret in Key Vault is tagged with its credential's keyId, and the expiry check judges that credential rather than the newest one. `--record-apple-upload` refuses under outcome A and refuses to record the slot that is already live. A renewal date in the future, or a production app that maps GitHub accounts with no cutoff and no recorded release, is now an alert. The workflow reads the Container App through plain ARM, so it no longer installs an az extension.

The identity checks now treat a renewal date more than 5 minutes ahead as an alert (it was an hour), and the gateway-secret alert names the client secret Key Vault holds instead of "the newest client secret". New tests pin the guards that keep a missing Key ID from matching an Apple provider that shows none, a replacement Apple key updating the recorded Key ID, the untagged write when a reset adds more than one credential, and the Key ID pattern in an Apple key's file name.

The hosted Desk README now covers Ouro identity: the order for turning on Ouro sign-in, the two `az` sign-ins the scripts need (Graph is blocked in the subscription's own tenant, so they use object ids there), the daily identity checks, and a table of every secret with where it lives, when it expires and how it rotates. It has runbooks for rotating the gateway's Entra client secret (which now also sets the `key-id` tag the checks read), importing, renewing, revoking and replacing Apple keys under either Apple outcome (including the first `--record-apple-upload`), and the signing key.
