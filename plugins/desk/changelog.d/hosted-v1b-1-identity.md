Hosted Desk can sign people in with Ouro accounts through the Ouro tenant (Microsoft Entra External ID), with Apple or an email one-time code. It stays off until the app carries the tenant and accounts-store settings; without them the gateway behaves exactly as before, with GitHub sign-in for `DESK_ALLOWED_LOGINS`. Once on, the consent page sends the browser to the tenant with PKCE and a nonce, the gateway validates the ID token strictly, and new people join only through single-use invite links. Accounts live in Azure Table Storage, reached through the gateway's managed identity, behind a 60-second cache that fails closed. Codes and tokens carry the account and the sign-in time, a refresh more than 30 days after sign-in is refused, every request checks that the account still has Desk access, and an account whose access is turned off loses its sessions within a minute. A GitHub fallback admits only mapped GitHub user ids while `DESK_GITHUB_SIGNIN=on`. A new `/healthz/deep`, which the deploy workflow waits for, reports by check name whether sign-in, the accounts store and the mapped accounts are available.

Ari's existing connector keeps working across the switch. Tokens from before accounts map to his account only when both his GitHub login and user id match `DESK_GITHUB_ACCOUNTS` and `DESK_GITHUB_LOGINS`, and only until `DESK_LEGACY_CUTOFF`, which is set 14 days after the release. The signing key is now a ring: a rotation signs with the new key and still accepts the previous one for 30 days, client ids are sealed with their own `DESK_CLIENT_KEY` so registered clients survive a rotation, and the gateway logs each key's fingerprint at start, never the key. A leaked key has an emergency rotation that replaces both keys at once and makes every client sign in again.

Two scripts set this up and keep it running. `hosted/infra/provision-identity.mjs` builds or reconciles each tenant's sign-in methods, app registrations, managed identities, roles, accounts storage and Key Vault secrets, records every non-secret id in `hosted/infra/identity-<env>.json`, and handles Apple key imports, Ari's account and invite, the client-key migration, signing-key rotations and the gateway's Entra client-secret rotation, which deletes the old credential only after the gateway shows the new secret. `hosted/infra/provision.sh` writes each Container App change as the whole app, so every secret, Key Vault reference, identity and setting survives a rerun; it checks the Ouro settings with the gateway's own reader before writing, waits for the new revision to be ready, and can build `ouro-desk-hosted-staging`, a rehearsal app with its own identity and the test tenant. Neither script passes a secret as a command argument or prints a production secret.

A daily workflow, `.github/workflows/identity-checks.yml`, checks that the gateway's Entra client secret and the Apple client secret end more than 30 days out and that production's legacy cutoff is set a day after release, and opens one public-safe `identity-alert` issue when a check fails. Where Graph accepts the Apple key directly (Apple outcome A), the workflow also renews the Apple client secret monthly, test a day before production, and sends only an Apple key whose tags prove it is the recorded one.
