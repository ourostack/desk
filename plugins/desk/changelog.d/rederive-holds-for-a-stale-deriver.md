A long-lived session's factory hook stays pinned to whichever cached Desk install was on disk when the session's own process started, even after a newer Desk is installed and even though the session's own plugin metadata (and so its marker and published facts) reports that newer version. A re-derivation run by that stale process was therefore applying binding logic — including a housekeeping exclusion such as [`isCardHousekeeping`](mcp/src/factory/desk-repo.js) — from whatever Desk version it actually started under, while claiming credit for a version that had already fixed the very defect it was still running into: a commit's mechanical, non-substantive touches to task cards could bind as real work again on a later, otherwise-correct republish, simply because the process doing the deriving predated the fix.

`deriveMarker` now compares the Desk version it is actually running (read from its own co-located `plugin.json`, never from the marker or an installed-plugins registry) against the "desk" entry in the marker's own declared `plugins`, and holds — publishing nothing — when its own version is older than what the marker declares. A marker with no "desk" plugin entry, or a deriver at or ahead of the declared version, is unaffected. This does not repair a session already published by a stale deriver; it stops the same stale process from doing it again on its next quiet sweep, restart or hand correction, until a fresher process picks the marker up.
