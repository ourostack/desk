A detached derivation that fails for a reason other than a missing or non-regular session log now leaves a diagnostic in the local `status.json` under `derive_failures`, keyed by the session's marker name: the time, the step that failed (`route`, `source`, `derive`, `bind`, `write_facts`, `write_jobs`, `write_receipt`, `read_marker`, `wait_quiet` or `lock`) and the error code, or the error's type name when it has no code. No error message is stored, because a message can quote a path or session text and `factory.js status` prints this record. Before, a refused write (a Windows rename over an open file, for example) was swallowed and nothing showed that a session's facts were not derived. The result of `deriveMarker` and `deriveFile` is unchanged and the marker is kept, so a later flush still retries. The session log itself missing or not a regular file is expected and records nothing; the same error on any other path is recorded. Every settled result (`written`, `not_opted_in`, `held`, `skipped`, `invalid`, `log_missing`) clears the session's record, and a result with no record to clear reads the status and writes nothing. Only the newest twenty records are kept.
