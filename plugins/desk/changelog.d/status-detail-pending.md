When the runtime's status detail misses `desk_status`'s short budget, the compact answer used to say `state: "ready"`, "Desk is ready." and `root: {path: null}`, and only `status_detail` asked for another call, so an agent could read the null root as "no desk". The summary now says "Desk is ready, but its details (root, search, sync) are still loading, so the empty fields below are not a missing desk. Call desk_status again shortly.", and the answer carries `detail_pending: true` (the full detail payload carries it too). `state` stays `"ready"`, so nothing that waits on state changes is affected. A cached detail, which is stale but complete, and a fresh one do not set the flag.
