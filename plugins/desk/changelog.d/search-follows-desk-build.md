A session now uses the search controller of its own Desk build. The build (the digest that names the runtime's source mirror) is part of the controller's identity, so a session running a newer Desk elects its own controller instead of joining one an older build started, which could refuse the newer session's meaning-based search and leave `desk_recall` waiting. Sessions on the same build and desk still share one controller. An older build's controller is left alone and exits with its own sessions. The hung-controller probe and `desk_doctor`'s `reclaim_controller` repair look at the controller of the session's own build.

Both builds still write the one search index in the desk, and each generation of the index now records the Desk version and build that wrote it. The build with the newer Desk version owns the index (the larger build digest settles a tie). When a build finds that a lower-ranked build, or an older build that records no writer, wrote the index last, `desk_recall` and `desk_similar` ask its own controller to reconcile the index again and wait within what is left of the same search deadline, and `desk_search` asks for the same while it answers from the files. A lower-ranked build leaves the index alone: its `desk_recall` and `desk_similar` say that a newer Desk session is serving meaning-based search and that restarting the session updates Desk, so two builds never take the index from each other on every query. Vectors that are still valid under the same embedding specification are kept, not embedded again, and the index keeps only its newest 8 generation records instead of one more on every reconcile. When meaning-based search cannot answer, the refusal now says so in plain words and gives the fix for its cause: start Ollama when the embedding service is down, use `desk_search` (or turn meaning-based search on in the activation config) when the desk's policy turns it off, and retry only when waiting can help. The technical reason stays in `diagnostic.detail`.

`desk_status` now says Desk is still starting only during a session's first admission, when every other tool waits for it: it names the step in plain words, says to check again in about 10 s, and says which tools work meanwhile. A background re-check of a desk that is already admitted no longer changes a ready answer. When search serves exact-word results because meaning-based search is not current yet, its note now reads "Meaning-based search is still catching up; these results match exact words and are usable." On a desk whose policy turns meaning-based search off, it says so instead.
