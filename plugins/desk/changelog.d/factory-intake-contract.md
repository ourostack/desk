The factory now writes and checks the record shapes the factory store already accepts.

- Published facts can be `desk.factory.published/3`. A commit may carry `at_ms`, the point on the session clock at which the session recorded it, so a commit can be placed in a job's time. Today only Copilot CLI records that time. It is published only for a desk known to be private and only in a session whose jobs carry segments, the same rule a controller pull request's time follows. It never runs past the session's end.
- A session that touched more than 256 tasks keeps the first 256 outcomes and flags `outcomes` `capped`, so a cut list never reads as the whole one. The published limit on `unavailable` entries is now 242 (22 fields times 11 reasons).
- The validator accepts a commit time and the `outcomes` flag only in a `/3` file and refuses them in a `/1` or `/2` file as `inconsistent`. A file with neither is still published as `/2`, so an unchanged session keeps its bytes, and every `/1` and `/2` file already in a store stays valid.
- Waste labels are `desk.factory.labels/2`, and the evaluator's rubric is version 2. Every label carries the evaluator's `confidence` (`high`, `medium` or `low`) and the `evaluator_version` that assigned it. A label may be `unknown`: time the evaluator looked at and could not tell. The evaluator's accept step takes only `/2` answers (`schema_outdated`), and `/1` labels stay valid as they are.
- The waste Pareto in `rollups/muda.json` lists `unknown` as its own row, but only once a `/2` label could say it, so a store of `/1` labels never shows a zero that means no data. Unknown time counts in the labeled time every share is taken of, but not in `muda_time_ms` or any `muda_time` measure, because it is not known to be waste. Each row lists its `evaluator_versions`. Each row also carries `confidence_ms: { high, medium, low }`, which adds up to the row's total, but only when every label behind the row recorded a confidence. A row any `/1` label speaks to has none, so it reads as not recorded and is never counted as high. A job report shows unknown time on a line of its own.
- `factory job-link --this-machine` prints where this machine's sessions of a job are reported. On a public desk, whose card carries no link, that is the report of the job ID keyed with this machine's secret. The `online-evaluation` skill now tells the reader to use it and to keep that link out of the card and anything public ([factory local capture](docs/factory-local-capture.md)).
