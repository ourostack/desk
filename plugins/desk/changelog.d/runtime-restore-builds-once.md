When several Desk servers start at once on a root whose runtime cache is new, one of them now builds the runtime cache and the source mirror, and the others wait for it and reuse the result. Before, each server unpacked the whole runtime archive and copied the source into its own staging folder first, and only then took the publication lock to learn that another server had already won, so five servers did the same work five times at once. On Windows that work took a median of about 8 seconds and up to about 20 seconds per server under that contention, and in about one of eight runs of the five-server start-up test it ran past the 30 second admission window and left sessions stuck in "admitting". The staging folder is now filled only after the server holds the publication lock and finds the destination still missing; a failed or incomplete build still leaves nothing behind.
