### Boot prints readable text, includes the desk's rules and stops ordering ceremony

`session-boot.js` now prints plain text: a status line, the desk's path, the numbered instructions, then the open tasks (each with its next step), pull requests, repos and push routes, and the desk's `AGENTS.md` (up to 16 KB, cut at a line break, with the path to read the rest when it is longer). `--json` keeps the structured result for tools and tests; `--task --json` no longer reads `--json` as the task name. Boot no longer tells the agent to read `AGENTS.md` or to confirm the Desk MCP with `desk_status`; agents skipped both in 11 of 12 acceptance runs. Instead one instruction says that if the host defers tools, Desk's may need loading, and names the Claude Code ToolSearch `select:` call that does it; the task-card guard's deny message carries the same hint.

The sync line says plainly what happened and when the local desk was last current, taken from a recorded last successful pull (a failed fetch no longer moves it): "sync failed: remote unreachable; nothing was pulled or pushed; local desk is as of ...", a conflict while restoring local changes says the pull itself succeeded, a quarantine names where the files went, and a desk with no remote or upstream says "no remote; nothing to sync".

### A local-only repo can reach done, under a rule that cannot be faked

A task whose recorded repo is local-only (a clone with no remote, so nowhere to push) can finish on a commit in that clone. Desk records `local_only: true` on the repo's card entry itself, once, when `task_create` or boot first sees the clone with no remote and the entry has no `url`; `task_update` refuses to set or change it. At `done`, only an entry that was already on the card before the call and carries the mark counts, the clone must still have no remote and sit outside the desk (and not hold it), the commit must be reachable from HEAD or a local branch, and its committer date must not be before the card's `created`. A repo with a remote or a `url` still needs a pushed commit or a pull request, and the refusal says what to do: push, open a pull request, or leave the task at `validating` and tell the operator the commit sha. One thing remains possible by design: an agent can make a new commit in a repo that really is local-only, which is real work in the recorded repo. [`task-lifecycle`](skills/task-lifecycle/SKILL.md) and [`task-card-format`](skills/task-card-format/SKILL.md) say so, never to point `non_code` evidence at the task card itself, and that a note, commit message or reply claiming tests pass must name the command that ran them. The `task_update` tool's evidence description says the same.

### The track card's Tasks table follows the task

When `task_update` changes a task's status, it sets that task's `State` in the track card's Tasks table, if the table has the documented `Slug` and `State` headings and no one has unstaged edits in the card; the row change is committed with the task card. Other columns and other tables are left alone.
