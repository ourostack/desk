Re-sending factory triage rows to keep them fresh at the store is stricter. When a row is due, the flush fetches the desk remote's `main` once and sends again only rows that copy still holds as the same review; a row that cannot be read or fetched waits and no longer makes the others go early. A row dropped because the desk now holds a newer annotation keeps the store health at `stale` until this machine delivers that newer revision or the old row ages out, and a waiting batch that carries only the scan's counts is not sent after the scanned desk's route changes. See [Staying current at the store](docs/factory-local-capture.md#staying-current-at-the-store).
