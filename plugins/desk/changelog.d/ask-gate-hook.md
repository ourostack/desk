### A mechanical gate now backs the noninteractive ask, instead of prose alone

Two real `claude -p --model haiku` reproductions against the strengthened first-run-bootstrap wording (3.2.0-alpha.117) still bound a desk and reported setup complete with nobody able to answer A3's "ask once" gate (`~/.local/state/desk-evidence/eng-workflow-v2/wrapup/ask-gate/raw/NOTES.md`). A new `PreToolUse` hook ([`hooks/ask-gate.cjs`](../hooks/ask-gate.cjs), [`mcp/src/runtime/ask-gate.js`](../mcp/src/runtime/ask-gate.js)) now denies a `Write`, `Edit`, `Bash` or `PowerShell` call that would create `desk.activation.json` under the Claude plugin data folder, but only when it can positively confirm both that nobody is attending the session and that no desk is bound yet; it stays silent on every interactive session, every rebind, and every host other than Claude Code. The noninteractive signal is `CLAUDE_CODE_SESSION_ATTENDED`, an environment variable Claude Code's own engine sets on the hook subprocess: empirically confirmed to read `"0"` for `claude -p` and for a bare `claude` invocation with non-TTY stdin, and `"1"` for a live attended session, with no Claude Code documentation describing any hook-payload field or other signal that draws the same line. It is undocumented, so the hook reads only the literal `"0"` as confirmed and treats everything else, including its absence, as "cannot confirm noninteractive" and allows the call through; any internal error also fails open rather than blocking a real setup. Shell-command inspection is best effort (a filename-plus-write-pattern match), unlike `protected-checkout`'s real command parser. Copilot is not covered: no equivalent Claude-Code-specific variable exists in its process environment today, and no other reliable signal was found for it either.
