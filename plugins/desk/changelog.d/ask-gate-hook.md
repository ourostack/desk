### A mechanical gate now backs the noninteractive ask, instead of prose alone

Two real `claude -p --model haiku` reproductions against the strengthened first-run-bootstrap wording merged in PR #72 still bound a desk and reported setup complete with nobody able to answer A3's "ask once" gate (`~/.local/state/desk-evidence/eng-workflow-v2/wrapup/ask-gate/raw/NOTES.md`). A new `PreToolUse` hook ([`hooks/ask-gate.cjs`](../hooks/ask-gate.cjs), [`mcp/src/runtime/ask-gate.js`](../mcp/src/runtime/ask-gate.js)) now denies a `Write`, `Edit`, `Bash` or `PowerShell` call that would touch a `desk.activation.json` shaped like any Claude config dir's plugin activation file, but only when it can positively confirm nobody is attending the session; it stays silent on every interactive session and every host other than Claude Code. The noninteractive signal is `CLAUDE_CODE_SESSION_ATTENDED`, an environment variable Claude Code's own engine sets on the hook subprocess: empirically confirmed to read `"0"` for `claude -p` and for a bare `claude` invocation with non-TTY stdin, and `"1"` for a live attended session, with no Claude Code documentation describing any hook-payload field or other signal that draws the same line. It is undocumented, so the hook reads only the literal `"0"` as confirmed and treats everything else, including its absence, as "cannot confirm noninteractive" and allows the call through; any internal error also fails open rather than blocking a real setup. Write/Edit matching is purely structural (`.../plugins/data/<plugin-id>/desk.activation.json`), independent of this session's own `CLAUDE_PLUGIN_DATA`, and denies whether or not the target already holds a binding: an earlier version exempted an already-bound target as "never block a human's rebind," but a live-proof incident during this change's own development (a throwaway-profile session's Write/Edit tool resolving a mis-typed `~`-relative path to the operator's real, already-bound activation file) and an independent review both showed that exemption allows exactly the failure this hook exists to prevent, since a session already confirmed unattended cannot be a human driving a legitimate rebind. Shell-command inspection is deny-by-default once the filename appears in the command text: it allows through only a short allowlist of plainly read-only invocations (`cat`, `head`, `tail`, `grep`, `jq`, `ls`, `stat`, `test -f`, `Get-Content`, `Test-Path`, `Get-Item`) with none of the tokens that can still hide a write behind them (a redirect, `-i`/`-c`/`-e` in-place-or-inline-code flags, `tee`, `of=`, or the PowerShell write cmdlets); an initial narrower, allow-by-default pattern missed `sed -i`, `perl -i`, `python -c`, `node -e`, `rsync`, `install`, `cp`, `mv` and `dd if=X of=Y`, all fixed before merge. Copilot is not covered: no equivalent Claude-Code-specific variable exists in its process environment today, and no other reliable signal was found for it either.
