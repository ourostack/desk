Every `desk_status` answer, compact or `detail: true`, now carries `runtime`: the serving process's own identity (plugin name and version, the loaded plugin folder, the source-mirror path and hash, whether the runtime is loaded, and the newest-release check when there was one). It is read in-process, never behind the slow search and index status, so a call that returns `detail_pending: true` still says which Desk answered. The answer also names exactly which fields are pending (`pending`), so a consumer no longer has to poll to tell missing metadata from an old runtime.

The `desk-web` tool descriptions match what `mine` does now: `eval`, `run-code`, raw input, storage, the console and dialogs run as given, and the stale "raw commands are refused" claims in the `browser_context` description and the `mine` open note are gone. Both descriptions are shorter. The `browser_context` open reply carries the same `runtime` identity (Desk version and loaded plugin folder), so a browser result binds to the code that produced it.
