A Desk server that is already running now picks up a newer release without a restart. The Copilot app keeps one long-lived Desk server per project folder and routes new chats to it, so a chat could run Desk tools days older than the release. On a tool call, in the background, the server compares the `release` channel with what it serves and, when the channel is newer, loads that release beside the serving one and swaps the tool implementations to it on the next call. A call already running finishes on the code it started with, and the newer runtime builds its own search engine and authority. A fetch or load that fails keeps the serving runtime and says why.

`desk_status` and `desk_doctor` report what is actually serving in `runtime`: `plugin.version`, `plugin_root` and `source_mirror_hash` follow the swap, `swapped_at` and `from` appear once it has swapped, and `refresh` shows the last check (`checking`, `current`, `ready_to_swap`, `swapped`, `failed` or `not_applicable`) with a plain reason. The check runs at most every 10 minutes and, for `desk_status`, at most every 30 seconds; `DESK_RUNTIME_REFRESH=0` turns it off and `DESK_RUNTIME_REFRESH_MINUTES` sets the interval. The session boot and the one-task boot now run from the serving runtime's own boot script, so their text comes from the newer release too.

`desk-web` follows the same path: after a newer release is found, new browsers and the tool list come from that release's controller, a browser the older controller opened stays with it until closed, and `browser_context`'s `runtime` carries the same fields.

Files Agency reads from the plugin folder it cached when the process started (hooks, skills, agents) and the server's own session layer (admission, the front door, the list of tool names) are loaded once per process and still refresh only when the Copilot app restarts. A server launched before this release has no refresh code, so only a restart brings it onto it.
