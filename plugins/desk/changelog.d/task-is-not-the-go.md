The session start's instruction for new work now says that creating the task is not the go: after it, the agent states its assumptions and what done means, and waits for the operator's go before any change, even when they left a choice to it ([`mcp/src/runtime/boot-text.js`](mcp/src/runtime/boot-text.js)). The instruction said only to create the task "before any design, plan or code". In the rerun of the cold dry run on October 12, 2026, a first message that ended "how it shows them is up to you" was read as the go: three of three Claude Code sessions on alpha.306 created the task and started changing the repository with no alignment. With the added sentence, three of three sessions aligned, changed nothing and waited. Only the first turn was measured, on one prompt and one model. Two Copilot sessions on Claude Sonnet 5.5 had also built with no alignment; the sentence was not tested on Copilot. A first message that already carries the go, and a trivial request, were not measured either.

A session with no operator gets the instruction without that sentence, because nobody is there to give the go.

The [evaluation packet](docs/evaluation-packet.md) scenario 1 said the task card appears after go; it now says the card appears before the agent aligns, which is what the session start has asked for since alpha.301.
