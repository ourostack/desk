Milestone 3a, task A3b (P0 correction to the protected-checkout guard, ourostack/desk#24): the guard now denies only a Git operation that moves a protected checkout's HEAD off its state branch, rewrites pushed history, or discards other sessions' work, and everything else passes. In a protected checkout, `add`, `rm`, `mv`, `commit`, amending an unpushed commit, every merge, `pull` and `rebase` onto the state branch's own upstream (with or without `--autostash`), non-force pushes of any branch or tag, deleting another branch on the remote, unstaging or restoring named paths (`git restore [--source <commit>] <paths>`, `git checkout -- <paths>`, `git reset -- <paths>`), config writes to another file, `worktree add`, `worktree prune`, read-only Git and plumbing pass. The [policy](mcp/src/runtime/git-guard-policy.js) still denies leaving the state branch, `reset --hard`/`--merge`/`--keep` and HEAD-moving resets, unstaging or restoring the whole tree (no path, `.`, `:/`, `*` or a magic pathspec), `clean`, `stash` (including `push`, `pop` and `drop`), forced, mirrored and pruning pushes and deleting the state branch on the remote, rebases onto anything but the upstream, force-moving or deleting the current or state branch, amending a pushed commit and forced removal of a protected worktree. Admission records the host's state branch beside the marker (`desk.stateBranch`), and it now marks a root only when it is a real desk (the desk layout, or a saved desk binding): three tests had bound `$DESK` to the checkout running the suite, which is how some code worktrees were marked protected.

Every denial names the concrete alternative, and credentials in URLs (`https://user:token@host`) are redacted from it. Only a real HEAD move, rewind or discard names the worktree command, `git worktree add --detach "$HOME/<new directory>" <ref>`, which runs as written in Bash and PowerShell; ordinary desk writes are never sent to a worktree. When the target checkout is unknown or computed (`cd "$x" && git …`), operations that are safe in any checkout still pass. Code Desk cannot read (a script file, `source`, `curl … | bash`, `eval "$(…)"`) passes; inline code it can read (`bash -c "…"`, here-documents) is inspected like any other command. Text Desk cannot parse is denied only when it names a Git operation whose rule could deny it there.

The Bash inspector now reads brace expansion, process substitution, here-documents inside `$( )`, a newline after `&&`, `||` or `|`, `case` arms in groups, `set -e`, and directories the command itself creates. PowerShell Git in a protected checkout is a closed allowlist of plain forms that never fires in an unprotected checkout. One step budget (20,000 steps) and one 7 s time budget bound all inspection, and the hook answers at 9 s. Replayed against 22,880 recorded agent commands, the guard denies 7 in a protected desk, 5 of them real HEAD moves, stashes or state-branch force-moves. The rule, threat model and command table are in the [hook header](hooks/protected-checkout.cjs) and [Protected checkouts](docs/protected-checkouts.md).
