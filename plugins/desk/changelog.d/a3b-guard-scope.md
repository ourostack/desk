Milestone 3a, task A3b (P0 correction to the protected-checkout guard, ourostack/desk#24): the guard now denies only a readable Git operation that moves a protected checkout's HEAD off its state branch, rewrites pushed history, or discards other sessions' work, and everything else passes. In a protected checkout, `add`, `rm`, `mv`, `commit`, amending an unpushed commit, `pull`, `pull --rebase` and `rebase` onto the branch's own upstream, merges, non-force pushes of any branch or tag, path-limited unstaging (`git reset [--] <paths>`, `git restore --staged <paths>`), `worktree add` and read-only Git pass. The [policy](mcp/src/runtime/git-guard-policy.js) still denies leaving the state branch, `reset --hard`/`--merge`/`--keep` and HEAD-moving resets, whole-index unstaging, `restore --source` and `--staged --worktree`, `clean`, `stash`, forced, mirrored or deleting pushes, rebases onto anything but the upstream, `--autostash`, force-moving or deleting the current or state branch, amending a pushed commit, `worktree prune` and forced removal of a protected worktree. Admission records the host's state branch beside the marker (`desk.stateBranch`).

Every denial names the concrete alternative. Only a real HEAD move, rewrite or discard names the worktree command, `git worktree add --detach "$HOME/<new directory>" <ref>`, which runs as written in Bash and PowerShell; budget, timeout, parse and unresolved-value denials never send an agent to a worktree. When the target checkout is unknown or computed (`cd "$x" && git …`), operations that are safe in any checkout still pass: `add`, `commit`, `pull --rebase` or `--ff-only` from the upstream, merges and non-force pushes, except under the configuration and URL overrides that are denied anyway.

PowerShell Git in a protected checkout is a closed allowlist: `git <arguments>`, `$name = git <arguments>`, or `git <arguments>` piped to a fixed set of formatting cmdlets, joined by `;`, new lines, `&&` or `||`, with literal or plain `$variable` arguments. The allowlist never fires in an unprotected checkout unless the statement could move where Git runs (`-C`, `--git-dir`, `Set-Location`, `worktree`, `GIT_DIR` and similar). Bash parses `@{upstream}` and other brace words that are not reserved words, and `{a,b}` expansions fail closed. One step budget (20,000 steps) and one 7 s time budget bound all inspection, and the hook answers at 9 s. The rule, threat model and command table are in the [hook header](hooks/protected-checkout.cjs) and [Protected checkouts](docs/protected-checkouts.md).
