Hosted Desk's native Linux job now proves two-account isolation end to end on the production image (`DESK_NATIVE_ISOLATION=1`). Account A, acting through the same paths production uses, cannot reach account B. A binding that names the wrong App installation gets no token, and one that names B's repository gets no realm. A's processes run with no capabilities and NoNewPrivs, and cannot switch user. B's token socket, clone and realm, and the realms folder, refuse A with EACCES. `desk_save` refuses a `..` or absolute path into B. Commit evidence from a card whose `local_path` is B's clone is refused by the hosted Git guard before any Git runs. No answer A gets names B or shows B's content unless A's own request did. B's desk is unchanged afterwards. A cross-platform test also checks that one account's sealed GitHub repository choice or desk-init offer is refused in another account's session.

Fixed: in an isolated hosted realm, `task_create` failed with "Desk Git context refused" whenever a repo entry had a `local_path` outside the desk and no `url`, which is any card naming a cloned code repository. The local-only check now treats such a clone as no repository, so the card is created and the entry is never recorded as local-only.
