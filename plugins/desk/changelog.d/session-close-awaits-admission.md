Closing a Desk session now waits for a running admission attempt, for at most 2 seconds, before it reports closed. Before, a closed session could still be running Git or other admission work in the desk folder, so a caller that removed the folder right after close could fail on Windows, where a folder in use cannot be deleted. The wait is bounded, so it does not guarantee that all admission work has finished: an attempt still running after 2 seconds is left behind. The readiness controller now closes alongside that wait rather than after it, so the shutdown limit is not spent waiting on admission first. The admission machine's `dispose()` returns the running attempt, and the session's `dispose()` waits for it ([`src/runtime/admission.js`](mcp/src/runtime/admission.js), [`src/runtime/desk-session.js`](mcp/src/runtime/desk-session.js)).
