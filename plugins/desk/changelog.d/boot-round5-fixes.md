Boot and status fixes from the fifth Haiku acceptance round. A desk sync that fails now says why: an unreachable origin, refused credentials, a diverged history, a timeout or a real conflict each get their own instruction, where every failure used to read as "resolve the git conflict" and sent agents to a `git status` that looked clean. An unreachable or refusing remote no longer moves stray files to `_cache/` either. The boot `instructions` now carry the push route for the named (or every active) task's repos whenever it is a fork, goes through a non-active account, or no account can deliver, naming repo, account and route.

`desk_status.readiness.state` is now one word (`ready`, `converging`, `degraded`, `unavailable` or `not_checked`) about the search index only, with the controller's own state name and convergence snapshot under `readiness.detail`; the raw `RECOVERING` beside an admission `ready` no longer reads as an outage. The task-status guard now denies any direct Edit, Write or MultiEdit that changes a task card's `status:` (not only `done`) and names the exact `task_update` call; body edits and new cards stay allowed. `superpowers-context.js` compares real paths when it decides it was started as a script, so it no longer exits silently when run through a symlinked path.
