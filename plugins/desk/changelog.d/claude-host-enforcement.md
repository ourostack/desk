Claude Code now denies the host surfaces that let an agent build durable state or a decision loop outside the desk: `AskUserQuestion`, plan mode (`EnterPlanMode`/`ExitPlanMode`), the persistent host task tools (`TaskCreate`, `TaskGet`, `TaskList`, `TaskUpdate`), and Artifacts (`Artifact`, `ArtifactComments`, `ArtifactData`, `ArtifactCheck`, and every `mcp__claude_ai_Claude_Docs__*` tool). A new `PreToolUse` hook, [`host-enforcement.cjs`](hooks/host-enforcement.cjs), denies a call to any of these with a reason naming the desk equivalent to use instead (`desk_save`, a task card, plain chat). In-session tools such as `TodoWrite` are never touched, and neither are `TaskStop`/`TaskOutput`, which manage an already-running background shell or subagent rather than any durable task state; only durable or alternative-UI surfaces are denied.

The denial has one escape hatch: when the operator explicitly names one of these surfaces in a chat message — not a negated mention such as "don't use an artifact" — that surface stays allowed for the rest of the session. A new `UserPromptSubmit` hook, [`desk-naming.cjs`](hooks/desk-naming.cjs), reads every operator message for that naming and records it in a small per-session file under Desk's own state directory; [`host-enforcement.cjs`](hooks/host-enforcement.cjs) reads it back on each later tool call. Both hooks fail toward their safe side on an internal error: the deny hook lets the call through, and the naming hook records nothing and never blocks the prompt.

`desk_status` and the boot checks now verify that `host-enforcement.cjs` is actually registered in the running plugin's `hooks.json`, and report a missing registration as a `Desk problem:` block rather than letting the gap stay silent. The block's `file:` field is filed through a single swappable function, [`fileHookRegistrationProblem`](mcp/src/runtime/host-enforcement-registration.js), which a later change can point at Desk's real problem filer; until then it reports the registration gap honestly as `not filed: filer_unavailable` rather than pretending to file anything. The deny decision and the naming match live in host-agnostic modules, [`host-enforcement.js`](mcp/src/runtime/host-enforcement.js) and [`naming-allowlist.js`](mcp/src/runtime/naming-allowlist.js): `evaluateDeniedTool` takes the calling host alongside the tool name, and each denied surface lists its own tools once per host in that host's own naming convention (an MCP server's whole tool family denies together via a `server__*`-style entry), so a later Codex or Copilot CLI wrapper calls the same function with its own host id and its own tool list, filled in on top of the empty lists this change ships for them, rather than reimplementing the decision.
