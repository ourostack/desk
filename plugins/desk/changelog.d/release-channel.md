Desk now ships to Agency through a `release` branch. The release workflow moves it to each stable release in the same push that puts the release on `main`, after `main`'s full CI passed, so an install of `github:ourostack/desk:plugins/desk@release` no longer runs merged changes that are not released yet. Install and dependency coordinates for Desk itself change from `@main` to `@release` ([README](README.md#under-copilot-cli)); Superpowers, Plain Language and Crew stay on `main`. `scripts/check-dependency-channels.cjs` requires `@release` for a dependency on Desk.

An existing install moves by itself. The new `03-desk-release-channel` session-start migration rewrites an explicit `github:ourostack/desk:plugins/desk@main` entry in agency.toml, following each other entry's whole dependency graph through Agency's cache (CIT brings MS Desk, which brings Desk): where another entry in the same list already brings Desk, the explicit entry gives way to it on those engines, and anywhere else it moves to `@release`, so the migration itself never selects Desk under a second spec. It leaves the entry as it is, and says why, while any manifest in that graph is not cached yet. It replaces agency.toml whole, under a lock and only if nobody changed it meanwhile, after a one-time copy to `agency.toml.pre-desk-release`. The `01-move-to-ourostack-desk` migration takes the same step right after its own move. Session-start migrations run after Agency has loaded the session's plugins, so a machine whose entry was still on `main` when MS Desk moved to `@release` loads two Desk roots once; that session's migration fixes the entry, and the next session loads one.

The stale-Desk check compares a Desk with its own channel: a `@release` install with the `release` branch, an older `@main` install with `main`, so a release candidate on `main` no longer makes a released Desk look stale. Its manual step names the exact Agency cache spec the session was loaded from, and the background refresh removes that same spec.
