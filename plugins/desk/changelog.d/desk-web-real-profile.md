`desk-web` can now drive the operator's real, signed-in browser profile, silently, in a window of its own. A plugin turns it on by declaring `"desk": { "browser": { "channel": "msedge" | "chrome", "profileAccountDomain": "<domain>" } }` in its `plugin.json` (the last plugin listed wins); with no declaration nothing changes, and the headless, isolated browser stays the default, installed and behaving as before ([`web.cjs`](mcp/web.cjs), [`web-real-profile.cjs`](mcp/web-real-profile.cjs), [`web-proxy.cjs`](mcp/web-proxy.cjs)).

With a declaration, the launcher finds the profile whose signed-in account ends in `@<domain>` in the browser's own `Local State` (the `user_name` field of `profile.info_cache`), reads the Playwright Extension's connection token from a temporary copy of that profile's local storage, and starts `@playwright/mcp --extension --browser <channel> --profile-dir-name <profile>` with the token in its environment. The copy is deleted at once. The token is never printed, stored or put in Desk's own command lines, and the proxy replaces it with `<redacted>` in everything it writes to the host or to stderr, because the extension's connect address carries it. The token reader, `classic-level@1.4.1`, is installed beside `@playwright/mcp` only when a declaration needs it; if it cannot be installed (for example, no prebuilt binary for the platform) the browser is installed without it, the install is marked so it is not retried at every launch (a marker older than 24 hours is retried once), and the first browser call answers `browser_token_unreadable`.

The agent works in a window of its own, on every platform and with no browser scripting, wrapper or shell. Before the first browser call reaches Playwright MCP, the launcher starts the real browser executable directly with `--new-window --profile-directory=<profile>` and a small holding page, in an environment without the token. The running browser opens that as a new focused window, and Playwright MCP's connect page lands in it as a tab. The holding tab closes itself within 30 seconds (sooner if it is hidden). A connection counts as used only after a browser call succeeds. The browser puts the connect page in its last active window, so if the operator focuses another window in the second between the two starts, the connect tab lands there; the skill text states this as a known limit.

When the agent calls `browser_close`, the launcher lists the tabs the agent's connection controls with `browser_tabs` once and closes that many (closing a window's last tab closes the window), then answers `browser_close` itself without passing it on, because Playwright MCP would otherwise open a new connect page, and a new window nobody owns, for a connection with no page left. It never lists tabs again after the last close, because listing makes Playwright MCP create a tab when none is left. The next browser call opens a new window and connects again. The same cleanup runs when the host closes stdin or stops the launcher, bounded by a per-call and an overall time limit and only if the connection was used since the last close, so ending a session after `browser_close` does nothing more to the browser. `browser_tabs` lists only the tabs that connection controls, so the operator's own tabs and windows are never touched and the browser is never quit. Two sessions each close only their own tabs.

If the declared profile has no matching account, if the Playwright Extension is not installed in it, if the browser is not installed or if the token cannot be read, `desk-web` still starts and its first browser call answers with one degraded line (`browser_profile_not_found`, `browser_extension_missing`, `browser_not_installed` or `browser_token_unreadable`, or `browser_declaration_invalid` for a declaration it cannot use) that names what was looked for and the fix. It never falls back to the isolated browser silently, and the next call checks again, so installing the extension needs no restart. These codes are new; the handshake and the existing codes do not change.

The extension can reach the whole browser, so the rule that an agent works only in its own window is in the [`cdp-headed-browser` skill](skills/cdp-headed-browser/SKILL.md), which now describes this mode, tells the agent to call `browser_close` when done, and limits its "never bring a window to the front" rule to brokered leases and the operator's existing windows.
