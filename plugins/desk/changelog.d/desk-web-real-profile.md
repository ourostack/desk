`desk-web` can now drive the operator's real, signed-in browser profile, silently, in a window of its own. A plugin turns it on by declaring `"desk": { "browser": { "channel": "msedge" | "chrome", "profileAccountDomain": "<domain>" } }` in its `plugin.json` (the last plugin listed wins); with no declaration nothing changes, and the headless, isolated browser stays the default ([`web.cjs`](mcp/web.cjs), [`web-real-profile.cjs`](mcp/web-real-profile.cjs), [`web-proxy.cjs`](mcp/web-proxy.cjs)).

With a declaration, the launcher finds the profile whose signed-in account ends in `@<domain>` in the browser's own `Local State` (the `user_name` field of `profile.info_cache`), reads the Playwright Extension's connection token from a temporary copy of that profile's local storage, and starts `@playwright/mcp --extension --browser <channel> --profile-dir-name <profile>` with the token in its environment. The copy is deleted at once. The token is never printed, stored or put in a command line, and the proxy replaces it with `<redacted>` in everything it writes to the host or to stderr, because the extension's connect address carries it. Installs of `@playwright/mcp` now also install `classic-level@1.4.1`, which reads the token; an existing install without it is replaced the first time a declaration needs it.

The agent works in a window of its own, on every platform and with no browser scripting. The launcher passes Playwright MCP a small wrapper as `--executable-path` (a shell script, or a `.cmd` file on Windows, written to `launchers/` in Desk's browser state folder) that starts the real browser with `--new-window` first, so the request to open the connect page becomes a new window instead of a tab in the operator's frontmost window. When the agent calls `browser_close`, the launcher lists the tabs the agent's connection controls with `browser_tabs` once and closes that many (closing a window's last tab closes the window), then answers `browser_close` itself without passing it on, because Playwright MCP would otherwise open a new connect page, and a new window nobody owns, for a connection with no page left. The next browser call connects again in a new window, and ending the session after a `browser_close` does nothing more to the browser. It does the same when the host closes stdin or stops the launcher, bounded by a per-call and an overall time limit, and only if the connection was used. `browser_tabs` lists only the tabs that connection controls, so the operator's own tabs and windows are never touched and the browser is never quit. Two sessions each close only their own tabs.

If the declared profile has no matching account, if the Playwright Extension is not installed in it, if the browser is not installed or if the token cannot be read, `desk-web` still starts and its first browser call answers with one degraded line (`browser_profile_not_found`, `browser_extension_missing`, `browser_not_installed` or `browser_token_unreadable`, or `browser_declaration_invalid` for a declaration it cannot use) that names what was looked for and the fix. It never falls back to the isolated browser silently, and the next call checks again, so installing the extension needs no restart. These codes are new; the handshake and the existing codes do not change.

The extension can reach the whole browser, so the rule that an agent works only in its own window is in the [`cdp-headed-browser` skill](skills/cdp-headed-browser/SKILL.md), which now describes this mode, tells the agent to call `browser_close` when done, and limits its "never bring a window to the front" rule to brokered leases and the operator's existing windows.
