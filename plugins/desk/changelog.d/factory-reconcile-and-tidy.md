A controller that works several jobs in one session no longer has its whole time copied into each of them. The binder now records, for each of the controller's jobs, the spans of the session its own evidence gives that job (Desk tool calls, file writes, desk commit windows and its spawns), the factory pipeline counts only those spans of the controller's time toward the job, and a pull request the controller opened goes to the job whose span holds its creation time. The controller's tool calls are split the same way, by the span that holds each call's start. Evidence that names two jobs at the same moment, such as one desk commit touching two task folders, makes the time that follows shared by both, and only a shared span is counted in both jobs and marked `worker_shared`. Facts written before this change keep their old numbers, and a public desk publishes neither the spans nor the pull request times.

`factory reconcile --desk <absolute path> --since <time> --until <time> [--store <directory>]` compares a desk's real task activity over a window with the factory's jobs and prints every mismatch with a reason code (`no_marker`, `not_opted_in`, `route_changed`, `held`, `log_missing`, `stale_binding`, `not_delivered`, `quarantined`, `pr_open`, `card_missing`, `invalid_status`, `mechanical_only`, `store_only`). It reads the desk's Git history, the local factory state and, with `--store`, a local checkout of the store; it never writes, and it prints task names only for the desk it is given and never prompt text or the machine secret. The commit rule that decides which commits count for a task, housekeeping edits and sweeps excluded, is now one function shared by the binder and reconcile.
