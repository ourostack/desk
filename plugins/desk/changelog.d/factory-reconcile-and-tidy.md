A task card's status must now be one of the eight lifecycle states: `task_create` (`status`) and `task_update` (`frontmatter.status`) reject any other value and list the valid ones. A new agent-work migration, `03-normalize-task-status`, finds cards that carry a ghost status and prints one `task_update` for each. It folds case and the separators `-`, `_` and space, then maps `active`, `doing` and `in progress` to `processing`, `planning` and `backlog` to `drafting`, `needs review` to `collaborating`, and `waiting` to `blocked`. A value it does not know is reported and left alone, because the migration never guesses.

The factory's publish guards now cover model ids and plugin names the way they already covered agent names: a model id that cannot be published becomes `unknown`, and a plugin whose name cannot be published is hidden. One predicate decides this for both the public token check and the published-field check. A token count that is not a safe integer is now `null` with an `unavailable` entry on every host, `requested_model` is left out when it equals `model`, and the helpers the three host derivers shared now live in one module. A rejection the store reports for a file with no local key now quarantines nothing and is only counted.

A session marker written by a hook older than the one that started recording each plugin's source now gets its plugin sources filled in when the facts are derived. A plugin takes the source of the installed plugin with the same name and exact version in the host's plugin registry, but only when exactly one such entry exists; a different version, a conflicting entry or an unreadable registry leaves the source empty and the plugin hidden, so a backfill never publishes a name it cannot vouch for.

A Codex session no longer routes to the public store on a guess. Codex markers record no plugins, so a Codex marker whose route comes from the default, because the desk has no `_meta/factory.json`, is held with the reason `route_unverified` until a Claude Code or Copilot CLI marker for the same desk, within 30 days, also routed by default; that marker's plugin registry was checked, so an overlay would have shown. A desk that declares its store routes Codex at once. Kaizen filing ignores a Codex route that was never proven.

A controller that works several jobs in one session no longer has its whole time copied into each of them. The binder now records, for each of the controller's jobs, the spans of the session its own evidence gives that job (Desk tool calls, file writes, desk commit windows and its spawns), the factory pipeline counts only those spans of the controller's time toward the job, and a pull request the controller opened goes to the job whose span holds its creation time. The controller's tool calls are split the same way, by the span that holds each call's start. Evidence that names two jobs at the same moment, such as one desk commit touching two task folders, makes the time that follows shared by both, and only a shared span is counted in both jobs and marked `worker_shared`. Facts written before this change keep their old numbers, and a public desk publishes neither the spans nor the pull request times.

`factory reconcile --desk <absolute path> --since <time> --until <time> [--store <directory>]` compares a desk's real task activity over a window with the factory's jobs and prints every mismatch with a reason code (`no_marker`, `not_opted_in`, `route_changed`, `held`, `log_missing`, `stale_binding`, `not_delivered`, `quarantined`, `pr_open`, `card_missing`, `invalid_status`, `mechanical_only`, `store_only`). It reads the desk's Git history, the local factory state and, with `--store`, a local checkout of the store; it never writes, and it prints task names only for the desk it is given and never prompt text or the machine secret. A task with no bound session is always `no_marker` (detail `unbound_markers_<n>`), and a top-level `unbound_markers` list gives each unbound marker in the window its own reason, so a marker is never blamed on a task. A `pr_open` read from the last flush without `--store` has the detail `pr_<n>_unchecked`, and a `store_only` row for a job this desk cannot map prints `job: null`. On a keyed (public) desk, `store_only` fires only for jobs with local facts on this machine. The commit rule that decides which commits count for a task, housekeeping edits and sweeps excluded, is now one function shared by the binder and reconcile.

A job whose sessions are all split among several jobs no longer reports tool retries and API retries as a measured zero: neither can be attributed to a worker, so both are now unavailable (`worker_split`). Compactions of an all-split job now report the same reason (`worker_split`) instead of `partial`. With some whole sessions they are the sum over those sessions and marked partial, and both measures now carry the same `worker_shared` flag as the job's time.

When a delivered file's session now routes to a different store, the next flush to the old store deletes the file in its intake pull request. A desk that moved to a private or internal store, or that now declares one, no longer leaves its old sessions in the public store. The flush resolves each session's current route the way the sweep does, from the session marker's desk root, and deletes only when that route is positively a different store. A missing marker or desk root, an unreadable or invalid declaration, a held session, a Codex default route nothing has verified, and a default route with no recorded overlay check are all unknown, and unknown keeps the file. A retraction removes the session's facts file and every labels file this machine delivered for it, at the paths recorded when they were delivered, so a machine-keyed name is deleted exactly as it was published. A flush with only deletions still opens the pull request, whose body adds a line such as `Retracted: 2 files (route_changed)`; the line gives a count and never names the other store or a session. A session is never published and deleted in the same pull request. A file is deleted only when the store holds, at the recorded path, the blob this machine delivered, and store names compare without regard to case. The delivered records stay while the pull request is open and are removed, with the local files that produced them, once the store's default branch no longer has the file, so a merged delete is not retried. If the session routes back to the store before the delete merges, the next flush closes the delete pull request and resets the intake branch, so the file stays; after a merged retraction, routing back publishes the session as new. A delete the store refuses is counted as `retractions_refused` in the flush status and is not retried while the route stays elsewhere. The store's `validate-pr` accepts the deletion of a file at a facts or labels path, with no content to check, only from a maintainer (owner, member or collaborator), so a contributor without that association cannot retract and is refused as `removal`; a maintainer's retraction is not held as maintenance, and renames are still refused. Git history keeps the deleted content.
