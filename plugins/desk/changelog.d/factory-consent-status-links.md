Desk now asks each machine once whether to contribute to its desk's factory store. [`desk:session-start`](skills/session-start/SKILL.md) Step 2.7, and [`desk:first-run-bootstrap`](skills/first-run-bootstrap/SKILL.md) at its endpoint, ask when `desk_status` reports the resolved store as `undecided`, in plain words: what is published (durations, counts, tool kinds, plugin and model versions, public references), what never is (prompt, assistant or tool content, names, dates and times of day), that the store is public, and that the contributor's GitHub account is the visible author of the intake pull requests. The account is never assumed from gh's active account: the new `factory.js account --store <store>` asks GitHub about the store with each signed-in account's own token, prefers push permission, then an account that can fork, and never picks an Enterprise Managed User account for a store outside its enterprise; when no signed-in account can deliver, it names each account's reason and nothing is asked. `factory.js consent` now accepts an Enterprise Managed User login, which a work store needs, and a flush whose account cannot fork the store stops with the new code `account_cannot_deliver` instead of waiting on a fork that will never exist. Yes and no are both recorded with `factory.js consent`, and a recorded decision is never asked again; a noninteractive session neither asks nor records. The startup hook's boot line asks exactly when `desk_status` reports `undecided`, because both read the decision with the same code; `held`, `unreadable`, `yes` and `no` never ask.

`desk_status` and `desk_doctor` now report `factory`: the bound desk's store and how it was chosen, consent per store, undelivered and quarantined counts and the last flush result code, from a read-only [local status](mcp/src/factory/local-status.js) that carries no path, secret, account, intake ID, token, time or content; `desk_doctor` adds it as a `Factory` summary section. The MCP server reads the host's plugin set with the end hook's own scan, loaded from the installed plugin root because an installed server runs from a source mirror without `hooks/`. The [entrypoint](mcp/index.js) now names that root in `DESK_PLUGIN_ROOT` on every host, so Copilot and Codex, whose MCP configs pass no environment, route a desk to the same store as Claude and the hooks instead of reporting `plugin_scan_incomplete`; a test launches the server exactly as `.mcp.copilot.json` does. On the transition to `done`, `task_update` and `task_archive` write `factory_report: <link>`, the task's `factory.js job-link`, into the card when the resolved store has consent; the link resolves once the store merges, and done never waits for delivery. [`desk:task-lifecycle`](skills/task-lifecycle/SKILL.md) says so and [`desk:task-card-format`](skills/task-card-format/SKILL.md) documents the optional field. Cards without consent, `cancelled` cards and edits of a done card are written as before. See the [factory doc](docs/factory-local-capture.md#consent-status-and-the-report-link).
