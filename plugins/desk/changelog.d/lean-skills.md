Skills are leaner. Each skill description now says only when to load the skill, which cuts the skill list every session reads by more than half on both hosts. The `status` skill now lives in `session-start` as "Status on request". The vendored `humanize` guidance is now `human-voice.md` under `operator-voice-comments`, which owns the voice rules. A short `humanize` skill stays and points there, so overlays that call `humanize` by name keep working; it will be removed once those overlays point to `operator-voice-comments`. The observer skills (`evaluate-release`, `factory-evaluator`) and `factory-task-context` now say in one line who they are for.

The largest skill bodies (the pull request skills, `operator-voice-comments`, `git-hygiene`, `pr-surface-hygiene`, `interaction-style`, `evidence-discipline`, `session-start-migrations`, `task-lifecycle`, `preflight-actions`, `repo-handling` and `friction-management`) drop repetition, history and anecdotes but keep every rule. Together the skill bodies shrink by about a third. `task-lifecycle` now points to `task-card-format` for the rules on evidence a task needs before it can be marked done, so those rules have one owner, and `repo-handling` hands pre-work sync to `git-hygiene`. Every send in the operator's name now waits for their approval: `operator-voice-comments` no longer lets a validator stand in for it, `pr-feedback-on-own-pr` shows its thread replies in one batch and posts only what the operator approves, and `peer-pr-review` posts comments and casts votes only with approval.
