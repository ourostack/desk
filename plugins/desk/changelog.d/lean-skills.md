Skills are leaner. Each skill description now says only when to load the skill, which cuts the skill list every session reads by more than half on both hosts. The `status` skill now lives in `session-start` as "Status on request". The vendored `humanize` skill is now `human-voice.md` under `operator-voice-comments`, which owns the voice rules. Both still trigger as before. The observer and factory skills now say in one line that they are only for `desk:observer` or a Factory run.

The largest skill bodies (the pull request skills, `operator-voice-comments`, `git-hygiene`, `pr-surface-hygiene`, `interaction-style`, `evidence-discipline`, `session-start-migrations`, `task-lifecycle`, `preflight-actions`, `repo-handling` and `friction-management`) drop repetition, history and anecdotes but keep every rule. Together the skill bodies shrink by about a third. `task-lifecycle` now points to `task-card-format` for the rules on evidence a task needs before it can be marked done, so those rules have one owner, and `repo-handling` hands pre-work sync to `git-hygiene`. `operator-voice-comments` no longer lets a validator stand in for the operator's approval before a send, and `peer-pr-review` posts comments and casts votes only with the operator's approval.
