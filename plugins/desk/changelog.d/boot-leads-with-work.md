Desk's plain-text boot now leads with the work and carries only what applies to this boot. Agents in acceptance rounds F to L kept finding the task summary after nine instructions, each push route told twice, a cryptic "sync ok", and the factory-consent script in boots that did not need it.

The boot opens with one status line: the status, the desk path, the host and the sync state in plain words ("Desk synced with origin", or "Desk could not sync: <why>; local state shown"). The stale-Desk line follows when there is one. The active tasks come next, grouped by state with `BLOCKED` first, each with its next step or blocker and its push route on a `push:` line, so a route is told once and a repo with no GitHub remote prints nothing. Open pull requests and repos follow, then a short numbered list of only the instructions that apply: the desk path, the host's tool names, what to report when no task is named, one closing rule (say what is missing and stop, say `done` only for a done task, do not print skill step headings) and, only while factory consent is undecided, one line to end the reply with. The consent script moved to "Factory consent" in the session-start skill's [`details.md`](skills/session-start/details.md). On the "where were we" acceptance fixture this cut the boot from 5221 to 4052 characters.

`--json` is unchanged: it keeps every instruction, the push-route instructions, the three consent instructions and `sync_summary`. The shorter wording is a text-only field, `text_instructions`, which the CLI leaves out of `--json`.

Boot no longer hard-stops on a GitHub sign-in check that merely failed. With several agents booting at once, `gh auth status` (an online check) hit rate limits and network errors, boot reported `auth_error`, and agents refused to list tasks. Boot now asks gh offline first (`gh auth token`, which reads the stored token and cannot be rate limited) and skips the online check when that shows a token. If it must ask online, a rate limit, network error, timeout or unrecognised failure gets one retry after 750 ms and then a warning line ("Could not verify GitHub sign-in (rate limited); continuing; pushes may fail until it clears"), never a hard stop. Only gh's own "not logged in" or "token no longer valid" output still stops the boot, now naming what gh said and the fix. The three attempts share the old 8 s budget, so a slow GitHub cannot make boot slower than before. The trade-off: the offline check cannot see a token GitHub has revoked or an invalid `GH_TOKEN`, so boot learns that from the first GitHub call it makes anyway (the open pull request lookup, or the push-route check) and shows it as a warning that says what gh said and the fix (`gh auth login --hostname github.com`, or unset or replace `GH_TOKEN`), never a hard stop.

The status line leads a degraded boot with what failed, such as `Desk boot: degraded (sync failed: remote unreachable; showing local state)`, and says "synced" only when the sync worked. The session-resumption, session-start, adopt-inflight-work and pr-reviewer-audit skills now say their steps are for the agent and are never named in replies. The boot-acceptance harness no longer counts a question, or a "complete" opener beside a bold status statement, as a delivery or done claim.

Agents kept copying "Step N:" skill headings into their replies, so the session-resumption, session-start, adopt-inflight-work and pr-reviewer-audit skills now use plain verb headings ("Read the task card", "Check the repo workspaces") with no step labels. Session-resumption no longer carries its own clone procedure: for a repo that is not on this machine it defers to the instruction boot prints, so there is one owner. The factory consent line is now a statement the agent relays once, "Desk can contribute measurement data about finished tasks to <store>; say 'factory details' to see what it sends.", never a question; the script runs only after the operator says "factory details". The harness no longer counts a clone as invented when the boot lists that repo as present on the machine.

When the named task's repo is not on this machine and cannot be cloned from anywhere, boot now prints one instruction instead of a hand-off followed by a blocker: ask the operator where it is cloned and stop, then clone or record the path, save it with `task_update`, and only then hand off to `desk:session-resumption`. A repo that can be cloned keeps its optional clone line after the hand-off. The startup line that says the boot has not run is now an imperative first action: run the exact command before anything else, including the first reply or any search of files or folders, and nothing else counts as the boot (Copilot's per-prompt line says the same). The harness no longer counts a leading condition ("Once the branch is pushed to the fork, I can open the PR") as a delivery claim.
