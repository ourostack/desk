Waste evaluation and the coming improvement triage now share one crash-safe count of headless launches, inside the existing 30-a-day ceiling, instead of evaluation owning it alone. Each UTC six-hour window holds one triage opportunity that evaluation cannot take until the window ends unused, so both queues keep moving across days, and triage still waits six hours between actual launches. A launch is reserved before it starts and never given back. The count lives in a ledger, a guard and a high-water mark in the status file, written in that order and read back, so a crash at any point either seals that UTC day as spent or completes the reservation, and a restored backup of the ledger or of the status file blocks launches rather than refunding them. The evaluator keeps its own counts, attempt limits and failure gaps, and gains a `maxRuns` limit for the loop. Restoring all three files together is outside what one machine can detect, and Desk does not claim it. See [Shared launch ledger](docs/factory-local-capture.md#shared-launch-ledger).
