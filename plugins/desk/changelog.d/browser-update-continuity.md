Desk updates the signed-in browser by itself, never moves it back to an older release, and sessions carry on through a native host restart.

On 2026-10-12, sessions answered `degraded:NATIVE_BROWSER_GENERATION_MISMATCH` and then `ECONNRESET` and `ECONNREFUSED` after the native host restarted. Every session also refused the browser whenever the Desk copy that started it shipped a different native runtime or extension than the browser had loaded, until a person closed every owned tab and ran the update by hand. Several Desk copies share one browser (one per host and release), so this happened at every release.

- **A session uses what the browser runs.** A session whose Desk copy ships another native runtime or extension source works through the provider and extension the browser has loaded, whichever installed copy put them there ([`mcp/native-messaging-prepare.mjs`](mcp/native-messaging-prepare.mjs)). Extension source that no Desk release shipped (its files do not match the digest it declares) is still refused.
- **Updates are automatic and never go backwards.** Desk records which release installed each native runtime and extension source in a private `versions.json` ([`mcp/native-messaging-versions.mjs`](mcp/native-messaging-versions.mjs)). The browser's native host registration is never moved to an older release's runtime ([`mcp/native-messaging-install.mjs`](mcp/native-messaging-install.mjs)). A session whose copy is newer retries the guarded update every minute in the background: it waits while any session owns tabs or has an operation under way, reloads only the Desk extension and never the browser, and sessions move to the new provider on their next call ([`mcp/web.cjs`](mcp/web.cjs)). `web.cjs --desk-native-update` runs the same update by hand and refuses to move the browser to an older release.
- **Sessions reattach after the native host or the browser restarts.** A session waits for the provider to come back and resumes its ownership; when the provider no longer holds it, or the same browser profile restarted, the session takes new ownership for the same owner. A different browser, profile or user is never adopted ([`mcp/web-native-messaging.cjs`](mcp/web-native-messaging.cjs)).
- **Load tests stay off the operator's browser.** Load, soak and concurrency tests run in CI or against a throwaway profile, never the operator's real browser profile or Desk state ([`skills/cdp-headed-browser/SKILL.md`](skills/cdp-headed-browser/SKILL.md), [`skills/evidence-discipline/SKILL.md`](skills/evidence-discipline/SKILL.md), [`docs/evaluation-packet.md`](docs/evaluation-packet.md)). A CI test now replays the incident end to end with the real provider, extension and session code: dozens of sessions, ownership left by sessions that are gone, a page flooding the host, and the host killed mid-call; every live session recovers by itself and nothing is left behind.

Desk copies released before this change do not read `versions.json`: they can still point the registration back at their own runtime, and their sessions refuse the browser once it runs newer extension source, until those copies update.
