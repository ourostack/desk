Follow-ups to the code-repo done evidence check. A `pr` or `commit` URL must now have exactly the host's own shape: `https://github.com/<owner>/<repo>/pull/<N>` (a sub-page, query or fragment may follow), an Azure DevOps `.../_git/<repo>/pullrequest/<N>` URL, or, for any other host, a host that one of the recorded clones has a remote on. A repo name smuggled into another URL's path, or on an unrelated host, no longer matches. A commit that does not resolve, or is not pushed, now tells the agent to run `git fetch` in the recorded clone first, because a squash-merged PR's commit reaches the default branch only after a fetch. A card whose `repos:` lists plain names (`repos: [widgets]`) counts as naming code repos. A relative `local_path` is resolved against the desk root, not the process's working directory.

`task_update` refuses to remove every repo from a card that names them unless the same call sets `status: cancelled`, so one call can no longer empty `repos` and a second finish the task on `non_code` evidence. This was chosen over recording a `repos_removed_at` marker because the refusal is immediate and says what to do, while a marker would leave a task that looks code-free but is still held to the code rule.

The readiness state directory's resolved parent must now belong to the current user or root and not be writable by group or others unless sticky (not checked on Windows). `task-lifecycle`, `session-start` and `codex-onboarding` now say `desk_status` returns `sync` and the index and database fields only with `detail: true`, and the `using-superpowers-with-desk` routing table separates its two plan rows (subagent-driven or inline) so `executing-plans` is reachable.
