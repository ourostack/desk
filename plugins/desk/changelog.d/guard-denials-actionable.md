### Every Desk denial opens with the fix

Hosts cut a denial at about one line (Copilot's UI showed one line of a real denial on Windows, so the agent never saw the fix and spent turns on it). Every denial and block Desk shows an agent now opens with a first sentence of at most 120 characters that says what to do instead, with the exact command or tool call where Desk can build it from the agent's own input, and gives the reason after it. This covers the protected-checkout guard in Bash and PowerShell (every policy message, the fail-closed "could not resolve" and budget messages, and the hook's own 9 s deadline and crash messages), the task-card guards for Edit/Write and for shell commands, the pre-commit card guard, the done-claim Stop gate, host enforcement, the ask gate and the test-isolation refusals. The protected-checkout reasons now put the checkout last ("Desk protects this checkout: <path>") instead of first.

A denied PowerShell command Desk can fix is answered with the fixed command in the first line, for example `Run this instead: $deskGitOutput = git status; $deskGitOutput | Format-Table` for `git status | Format-Table`, or `git log 'HEAD..@{u}'` for the unquoted `HEAD..@{u}` (PowerShell passes that to Git as `HEAD..@` and a script block). Desk offers a rewrite only after the guard itself allows it, so a suggestion is never a command the guard would deny. A denied direct edit of a task card now opens with the exact `task_update` call carrying the fields the edit tried to set, named the way the host calls it: `mcp__plugin_desk_desk__task_update` on Claude Code, `desk-task_update` on Copilot CLI. The pre-commit card guard's first line is `git restore --staged "<card>"` for the staged card, followed by the `task_update` call.

A test now builds every denial the code can produce and fails when a first sentence is longer than 120 characters or does not start with a verb or the command to run; it also fails when a guard file gains or loses a denial site, so a new guard must add its messages to it.

The guard also closes three gaps the new probe corpus found. A string piped to `cmd`, `bash` or another shell inside an assignment (`$y = 'git checkout topic' | cmd`), a known variable piped to `Invoke-Expression` (`$s | iex`, with or without an assignment), and `git fetch --upload-pack=<program>` in a protected checkout are now denied; each only adds denials. The other gaps the corpus found are listed there as known gaps.
