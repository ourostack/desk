Stop abandoned browser leases from piling up and from stopping the native browser provider.

A session takes a lease on the signed-in browser when it connects, whether or not it ever uses the browser, and a session that is killed never releases it. Nothing removed such a lease: while the provider ran, its proxy kept the lease from expiring, and each provider start restored and renewed every recorded lease, expired or not. On 2026-10-12 one registry held 82 leases, all hours past their expiry and 81 of them never used. Restoring was also all or nothing, so one lease that could not be restored ended the provider's start; no readiness file was written, and every browser tool answered `degraded:ENOENT`.

- **A provider start removes expired leases that hold nothing in the browser** instead of restoring them, and a lease that cannot be restored no longer stops the start: it stays recorded and is not renewed, or is removed when it had also expired ([`browser-context-broker/src/native-provider.mjs`](browser-context-broker/src/native-provider.mjs)). A lease with a recorded window or tab is still restored, expired or not, because its tabs may still be open.
- **Each new lease first releases the abandoned ones.** A session now sends its process id when it takes a lease. Before the provider grants a lease, it releases every lease that holds nothing and whose session process is gone, or that has expired. A release that fails is tried again at the next lease and never fails the one being granted.
- **A provider that is not running is named.** When the readiness file is missing, the browser tools answer `degraded:browser_native_provider_not_running` with the file's path and what to check, instead of a bare `ENOENT` ([`mcp/web-native-messaging.cjs`](mcp/web-native-messaging.cjs), [`mcp/web.cjs`](mcp/web.cjs)).
