Factory consent is now the boot's last instruction by construction. Every other instruction is collected first, the consent block is built in one place, and one join puts it after everything else in both the text boot and `--json`, so a new boot line can no longer land after consent. Three packages had broken the rule the same way, by appending their own line after consent. A test reads [`boot.js`](mcp/src/runtime/boot.js) and holds the consent calls and the join to those single places.

A subagent brief now carries its `Desk-Task: <track>/<slug>` line by structure, not by reminder. A go-and-see of the public factory store found 87 of 250 public pull requests credited to no task, because one lead session wrote 181 of its 199 briefs with no line while it held no task. On Claude Code a new hook ([`hooks/brief-task-line.cjs`](hooks/brief-task-line.cjs)) adds the line from the task the main agent declared with `task_focus` (or `task_create` with `focus: true`). The changed input carries no permission decision, so Claude Code's normal permission check still runs on it: the hook tags the brief and approves nothing. Otherwise it denies a brief with no line, once, asking for the line or for `Desk-Task: none`, and says why it could not add one: the focus was cleared, Desk has no record of one, the record could not be read, or the held task's name would not read back as a `Desk-Task:` line. A subagent spawning its own subagent is asked to copy its own brief's line. On Copilot the hook denies only, because Copilot's `preToolUse` cannot change a tool's input; a held focus already credits the subagent through the spawn-time rule. Codex hooks are not trusted by default, so on Codex the brief line that [`work-orchestration`](skills/work-orchestration/SKILL.md) now requires is the only mechanism.

The done-claim gate now tracks `task_signoff`. A refused sign-off moves the task back to `processing`, so a "Done." after a refusal is gated like any other task short of done. A delivery is also not an acceptance: while a task this turn touched is `done` with no verified acceptance (an `accepted` record without `verified: true` does not count), the gate blocks, once, any reply that uses an acceptance word (accept, accepted, acceptance, signed off, sign-off complete, approved by) unless it also states the honest state ("delivered, not accepted", "awaiting sign-off", "unsigned", "unverified", or the packet's "accept or send back"). It judges words rather than phrasings, because no list of phrasings is complete. For an unsigned delivery the reason asks the agent to say "delivered, not accepted" and to ask the operator in the sign-off packet; for an acceptance recorded as unverified it asks the agent to say so, and never to ask the operator again. `task_signoff`'s own sentence for an unverified answer passes.

A resumed or compacted session is no longer asked twice for the same sign-offs. Boot keeps a small session-scoped record of the unsigned deliveries it listed, keyed by the session id the host puts in the environment (`CLAUDE_CODE_SESSION_ID`, `COPILOT_AGENT_SESSION_ID`); a later boot of the same session with nothing new says they were already listed and asks for no second raise. A host with no session id (Codex) gets the plain line, as before.

A subagent's denied `task_signoff` call no longer removes the main agent's waiting sign-off ticket for the same task and outcome, so the main agent's real call is still witnessed.

The headless evaluator's allowlisted environment now keeps proxy and certificate settings (`HTTPS_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE` and their kin), so runs on a proxied machine reach their service. A loop step whose last success is dated more than 72 hours ahead of the clock now reads as stale instead of fresh until the clock catches up.
