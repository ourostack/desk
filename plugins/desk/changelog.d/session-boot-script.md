`desk:session-start` now boots with one call instead of a hand-run chain of separate steps. A new `mcp/scripts/session-boot.js` (backed by `mcp/src/runtime/boot.js`'s `bootOnce`) resolves `$DESK`, probes this host's identity, checks `gh`/`jq`/`gh auth status`, syncs the workspace, reads the cheap filesystem task index, validates every open task card's frontmatter, and resolves a push-capable GitHub account for every task repo — all in one JSON result printed on one line, which always exits 0 so a boot failure never blocks the session on its own crash.

The result carries a single `status` word (`ready`, `degraded` or `setup_required`) and a `degraded` list, so the agent never has to reconcile two disagreeing state signals; a `pending` list carries whatever the wall-clock budget didn't let finish (never blocking on a slow check); and `actions` names concrete next steps against a task, repo or file instead of leaving the agent to re-derive its own remediation prose. `active_tasks` stays the same cheap, filesystem-only index the status block already used, never gated behind the slower checks. `card_validation` replaces a bare "N cards have problems" count with the specific defect on each malformed card — including the numeric-string-keyed-object corruption a bad write can leave behind — named by its redacted track/slug/desk and stable handle. `push_accounts` resolves, ahead of time, which signed-in GitHub account (if any) can push each open task's repos, reusing the same per-store account resolution the factory consent step already uses, rather than assuming `gh`'s active account.

`session-start/SKILL.md` shrinks accordingly: the old five-part prerequisite probe, the standalone workspace-sync command, and the separately-maintained active-task/push-account logic are replaced by "run the boot script and act on its result," placed right after the migration auto-heal step so a stale pre-migration `$DESK/` is never scanned or synced under the wrong path. The skill keeps a minimal, root-independent host-identity probe as its very first step (safe to run before migrations), now written to durable state only when the host actually changes rather than every session; adds a short path for a session that already knows which task to resume, so the full status block doesn't have to print before handing off; asks the agent to re-confirm Desk MCP tool availability after a context-compaction resume, not only at the very first message of a session; and explains what the startup hook's "workspace-tidy budget exceeded; deferred" line means and how to run its repair by hand.
