The factory now fails closed wherever a fail-open scan found an unknown state permitting something. A plugin manifest that cannot be read or parsed no longer falls through to the public default store: it holds the route as `invalid_declaration`, with its code in `desk_doctor`, because it may be the overlay that declares a private store. A missing Claude Code plugin registry holds the route too. Every reader of a session marker checks a route recorded with such a warning again: it stays held until the named manifest reads, then goes to the store that manifest declares. A marker an older Desk wrote with the default route after skipping a broken overlay is corrected the same way at the next sweep or flush, and if its facts already sat in the public store's outbox they are frozen there, and retracted once the overlay reads and names another store. Such a default route also no longer proves a Codex session's default route.

Andon no longer reads as clear when it was not looked at. A store whose `factory.json` is missing is `config_missing`: the session-start refresh records that failure instead of an empty list, and the loop does not observe the andon kind. An andon issue still open but dropped from a shrunken plugin list stays present. A failed refresh is recorded beside the last good one, and session start prints `Factory: andon state unknown for <store> since <date> (<code>)` when the record is missing or unreadable, is more than 72 hours old or dated in the future, or when the last refresh failed after the last success.

A flush that ends before it reaches the account (`nothing_pending`, `offline`, `locked`, `deadline`, `rate_limited`, `unexpected`) keeps the store's standing account fault as `account_fault`, so the loop never counts a broken account as recovered. Every `*_check_unavailable` rejection is a stale batch that waits and goes again, never a quarantine. After `status.json` loses a store's entry, a machine that delivered there before goes online once to find its open intake PR.

A Desk problem the filer could not file or whose known hit it could not record is now a drop, so verification reads `not_recorded` for a window that includes it, never a measured "no hit". A drop before the window no longer blocks it.

A sign-off on a card with no readable delivery time is unverified as `no_delivery_time`, and one in a session that lost its stop record (more than one prompt, no stop) is unverified as `no_stop_record`. A cached repository visibility stamped more than five minutes in the future is stale.
