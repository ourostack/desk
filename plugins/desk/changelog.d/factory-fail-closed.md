The factory now fails closed wherever a fail-open scan found an unknown state permitting something, and a privately routed session never reaches the public store on any path. A plugin manifest or plugin folder that cannot be read, a missing folder, a symlinked Copilot plugin folder, a missing or unreadable Claude Code plugin registry, a registry that does not list the running Desk (a `--plugin-dir` session) and a scan cut short all hold the route as `invalid_declaration`, because the unread plugin may be the overlay that declares a private store. Every reader checks a route recorded with a warning again, and it goes to the store the manifest declares once it reads. A hold is released only by something that declares a store for that session (the desk's own `_meta/factory.json`, or a manifest the session itself loaded that now reads); another session's plugin scan never routes it to the default store, so a hold whose cause cleared without a declaration waits. A Desk updated while a session ran (a sibling version in the same cache folder) still counts as listed. A marker from an older hook with the default route and no plugin list is treated as held. A held marker is kept for 90 days, and every hold is visible in `desk_doctor` and at session start with its path, reason and remedy (including links and `--plugin-dir`); a held session pruned at 90 days is reported there too. Without a current marker, a session goes only to the store this Desk last checked positively for it (`checked_route` on its derivation receipt): an older Desk's receipt, or none, freezes the copy on this machine, never publishing it. A copy frozen because its desk folder was briefly gone returns when the folder does. Such a default route also no longer proves a Codex session's default route.

Andon no longer reads as clear when it was not looked at. A store whose `factory.json` is missing is `config_missing`: the session-start refresh records that failure instead of an empty list, and the loop does not observe the andon kind. An andon issue still open but dropped from a shrunken plugin list stays present. A failed refresh is recorded beside the last good one, and session start prints `Factory: andon state unknown for <store> since <date> (<code>)` when the record is missing or unreadable, is more than 72 hours old or dated in the future, or when the last refresh failed after the last success. An unreadable `consent.json` prints `Factory: andon state unknown (consent_unreadable)` instead of hiding the line.

A flush that ends before it reaches the account (`nothing_pending`, `offline`, `locked`, `deadline`, `rate_limited`, `unexpected`) keeps the store's standing account fault as `account_fault`, so the loop never counts a broken account as recovered; a flush that reached the account clears it. Every `*_check_unavailable` rejection is a stale batch that waits and goes again, never a quarantine. After `status.json` loses a store's entry, a machine that delivered there before keeps looking for its open intake PR on every flush until a look succeeds.

A Desk problem the filer could not file or whose known hit it could not record is now a drop, so verification reads `not_recorded` for a window that includes it, never a measured "no hit". A drop before the window no longer blocks it. A filing that started and has not ended (the filer died mid-run), or a filer launched that never started, counts as a drop too: the launcher's throttle stamp stays pending until the filer records an outcome.

A sign-off on a card with no readable delivery time is unverified as `no_delivery_time`, and one in a session that lost a stop record (more prompts than stops, beyond the turn still running, so a stop from an earlier turn no longer covers a later one) is unverified as `no_stop_record`. A cached repository visibility stamped more than five minutes in the future is stale.
