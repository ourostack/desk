A machine with no Node.js now gets a plain message at session start instead of only `Failed to connect to MCP server "desk" … program not found`. The session-start command in both hook manifests checks for `node` in the host's own shell before anything else (`command -v node` in bash or Git Bash, `Get-Command node` in Windows PowerShell). Without it, the shell prints one message from [`hooks/node-missing.sh`](hooks/node-missing.sh), or the matching PowerShell text in [`hooks/copilot-hooks.json`](hooks/copilot-hooks.json): Desk needs Node.js 20 or newer, the install command for the platform (`winget install --id OpenJS.NodeJS.LTS …` on Windows, `brew install node` on macOS, the distribution package on Linux), and that the person must open a new terminal and start a new session because tool servers load only when a session starts. The check runs shell builtins only and installs nothing.

When the hook's `node` is older than Desk needs and no newer Node is installed, both session-start hooks now give the same message with the version they found and the install command `desk_status` would name, instead of the usual startup context ([`hooks/lib/node-required.cjs`](hooks/lib/node-required.cjs)). The startup context is unchanged whenever Desk can run.
