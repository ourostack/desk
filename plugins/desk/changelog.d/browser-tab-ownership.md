Keep the signed-in browser working: tab ownership no longer piles up, never stops the browser provider, and never blocks a browser call or an update.

On 2026-10-12 every browser call in the operator's sessions answered `degraded:ENOENT`. The native host had restarted while the browser's extension stayed loaded, the new provider tried to bind tab ownership records the extension still held and refused, and the provider exited at every start. 82 ownership records, all expired and 81 never used, were restored and renewed at each start, and one record whose session had gone kept an extension update refused for good.

- **A restarted provider binds what the extension already holds.** A record with nothing in the browser that the extension still holds from the previous host is taken as bound instead of ending the start ([`browser-context-broker/src/native-cdp.mjs`](browser-context-broker/src/native-cdp.mjs)). One record that cannot be restored never stops the start; it stays recorded, unrenewed, and is tried again.
- **Ownership is cleaned up when its session is gone.** A session records its own process with the provider. Every minute, after each start and after each new lease, the provider releases the ownership of a session whose process has exited, closing exactly the owner window and tabs recorded to it, the same way the session does at exit ([`browser-context-broker/src/native-provider.mjs`](browser-context-broker/src/native-provider.mjs)). A lease is now renewed only while its session's browser client is connected, so a session whose process cannot be judged loses its ownership within one five-minute expiry of going away; a provider that has just started first gives such a session one expiry period to reconnect. The decision is taken again under the record's own lock, a failed release is retried, a record whose tabs cannot be reached for an hour past its expiry is dropped, and a record of a browser that has since restarted is removed once it expires. There is no limit on how many sessions or tabs can be owned.
- **Many sessions can start together.** Waiters in the provider took the shared lock in no order and gave up after 5 seconds, so about 80 sessions starting at once refused some of them. They now queue in order, and the timeout covers only waiting for another process ([`browser-context-broker/src/lock.mjs`](browser-context-broker/src/lock.mjs)).
- **A session takes ownership at its first browser call, not when it connects,** so a session that never uses the browser leaves nothing behind ([`mcp/web.cjs`](mcp/web.cjs), [`mcp/web-proxy.cjs`](mcp/web-proxy.cjs)). A session whose ownership the provider no longer holds takes a new one for the same owner instead of failing.
- **An expired record never holds an update back.** Abandoned ownership is released before an extension update is prepared, and an expired record no longer counts as an active owner.
- **The native host survives a busy page.** It took at most 256 queued messages and 1 MiB per message from the browser and ended its transport past either, which a page such as Teams can exceed in one read. Input is now paused and resumed instead, messages up to Chrome's own 64 MiB are accepted, and one failed process read no longer ends the host ([`browser-context-broker/src/native-host.mjs`](browser-context-broker/src/native-host.mjs)). The host keeps its diagnostic codes in a private `native-host.log` beside its state, since the browser discards its stderr.
- **A stopped provider is waited for and then named.** A session waits for the provider's readiness file, tries once more, and then answers `degraded:browser_native_provider_not_running` with the file's path, never a bare `ENOENT`; the deliberate native update names it the same way ([`mcp/web-native-messaging.cjs`](mcp/web-native-messaging.cjs), [`mcp/native-messaging-prepare.mjs`](mcp/native-messaging-prepare.mjs)). No other window or profile is ever used instead.
