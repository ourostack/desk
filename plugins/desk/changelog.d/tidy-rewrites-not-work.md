**A Desk-driven tidy that only rewrites a task card's frontmatter quoting, or updates a reference to a path the same commit renamed, no longer credits a session with a job.** [`isCardHousekeeping`](mcp/src/factory/desk-repo.js) (PR #75) already ignored a bare-card edit that changed only `title:`, `track:` or `updated:`, but a real tidy commit still bound most of the task cards it mechanically touched, for two reasons a live run against 22 task cards exposed. First, a move or rename tool re-serializes YAML without changing any value — `created: "…"` becomes `created: '…'`, `requester: "ari"` becomes `requester: ari`, a quoted list item loses its quotes — and that byte-level difference alone made the card look edited. Second, the same commit often rewrites other cards' references to a path it renamed, in frontmatter lists and body text alike, and that rewrite alone also made the referencing card look edited. `isCardHousekeeping` now normalizes a frontmatter scalar's matched surrounding quotes before comparing (an escaped quote or an embedded backslash is left alone, compared literally, so a real escaping change still counts), and applies the commit's own rename pairs — file-to-file, and directory-to-directory wherever a renamed file's old and new paths share a trailing segment — to the old card's text before comparing it, so a reference to a path the same commit moved reads as unchanged too. A reference that only starts with a renamed directory's name, or a change the commit's own renames don't explain, still counts as real work. A commit with an unreasonable number of rename pairs is never treated as housekeeping, rather than spend unbounded time deriving substitutions from it.
