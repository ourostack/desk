Copilot CLI sessions now mark a pull request as created when the session's own `gh pr create` call finished with exit code 0 and printed it, and such a pull request carries the time of that result ([`derive-copilot.js`](mcp/src/factory/derive-copilot.js)). Only the first pull request URL in that result is read. A Copilot CLI wait after a turn that ended on an error the agent did not recover from now says `rate_limit` (status 429, or a rate-limit or used-up quota error) or `api_error`, instead of a normal end. Reconcile and capture coverage now compare receipts with the last version that changed the binding (6), not with the re-derive version (7), so a session whose transcript was gone before it could re-derive no longer reads as stale; the re-derive version and its meaning are unchanged. The earliest finish day is now defined once, in the published-facts gate, and the publishing transform imports it. The RFC's privacy statement now lists the public references that published facts carry, and says each pull request the session named is placed on the task clock, with whether the session created it. The store playbook says that a session re-derived after its first `/4` send is sent once more.
