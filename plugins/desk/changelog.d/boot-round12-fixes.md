### A task card cannot be rewritten through the shell and committed by hand, and boot says to stop when something is missing

Round E of the boot acceptance runs showed an agent rewriting a live task card with a node script run through Bash and committing it by hand, which skipped every check `task_update` makes. Two layers now close that. First, the desk gets its own git `pre-commit` hook ([`mcp/src/desk/card-commit-guard.js`](mcp/src/desk/card-commit-guard.js)): a commit that adds or edits a live card (`<track>/<slug>/task.md`, or the same under `desks/<alias>/`, including a rename that also edits it) is refused unless Desk itself is committing, and the refusal names `task_update` and the ToolSearch line that loads it. Deleting a card and a pure rename still commit by hand, so archiving by `git mv` is unchanged. Desk installs the hook at boot, in the one-time tidy and when the index opens, and installing again changes nothing. A `core.hooksPath` is respected, a pre-commit hook that was already there is kept as `pre-commit.desk-chained` and runs after Desk's check, and a hook that cannot be installed shows as one `card guard:` line in the boot's degraded list. Desk's own commit path (`task_update`, `task_create`, `task_move`, `task_archive`, `track_*`, `friction_add`, `lesson_add`, `desk_save`) sets `DESK_TOOL_COMMIT=1` for its git call, and so does the tidy's final hand commit in `migrations/02-tidy-desk.md`. `desk_save` now refuses a task card path, so a card cannot ride through the one commit path the hook trusts. Setting `DESK_TOOL_COMMIT=1` or `--no-verify` by hand is a deliberate override and out of scope: the hook stops the accident, it is not a lock.

Second, the task-status guard now also reads `Bash` and `PowerShell` calls, best effort. A command that names a live card of the bound desk and writes it is denied with the same `task_update` instructions: a redirect (`>`, `>>`), `tee`, `sed -i` and the other in-place editors, `mv` or `cp` onto it, `git checkout` or `git restore` of it, and a script that writes files (`writeFileSync`, `appendFile`, Python `open(..., 'w')`, `write_text` and the like). Reading a card with `cat`, `grep`, `head`, `git diff` or `git log` passes, and so does `git restore --staged`. A path built in pieces passes unless the command also names a live card's slug as a whole word. The hook answers a Bash call that never says `task.md` without loading anything.

The boot's numbered instructions gain one line: "If the next step needs something that is not on this machine (a branch, a file, a clone), say what is missing and stop; never recreate or simulate it." A round E run had invented the branch and a fake fork.

The `archive-workflow` skill now updates a card's `iterations:` block with `task_update` instead of a hand edit and commit.

The boot-acceptance harness fails any Bash command that writes a live card and any hand `git commit` of one (a hook-denied attempt is a note), fails a succeeded clone of the fixture's own desk origin that lands under another repository's name, fails "I've cloned <repo>" in a reply, card note or commit message when no succeeded clone of a real repository backs it, and fails a bare repository or a remote other than `origin` that points at a folder, labelled "simulated a remote". Rescoring round E, wrong-push-account run 1 now fails (it cloned the fixture's origin as `claude-code` and said so), run 2 gains the clone and simulated-remote failures, and resume-named-task run 2 gains the card write and hand commit failures; the invented push claims from round E were already caught by the delivery check. A reply that opens with a check mark or bullet before "Done" ("✓ **Done:** wired the check") now counts as a done claim; the live check of resume-named-task had passed one.

Review fixes to the card guard. The hook now sets `DESK_CARD_GUARD_RUNNING` and exits 0 when it is entered again, runs a chained hook as a child instead of `exec`, and never chains a file that carries the Desk marker, so the pre-commit framework (which moves the hook it finds to `pre-commit.legacy` and runs it from its own hook) cannot recurse. The hook passes while a merge, cherry-pick or revert is in progress, and for a staged card whose frontmatter does not parse; its refusal now ends with the human escape hatch (`DESK_TOOL_COMMIT=1 git commit ...`), documented in `task-lifecycle` and the README with how to remove the guard (`uninstallCardGuard`). When a foreign tool rewrites `pre-commit` later (husky), the next install replaces the stale chained hook, keeps the old one as `pre-commit.desk-chained.bak-<timestamp>` and puts Desk's hook back in front instead of failing; a `core.hooksPath` that holds tracked files is never modified, and boot reports one non-degraded `card guard not installed` note with the manual remedy. The hook reads paths with `git diff --cached -z --name-only`, so unusual file names are safe, and is written with LF endings (an installed copy with CRLF is rewritten). `git checkout --ours|--theirs <card>` and `git checkout <ref> -- <card>` pass the shell guard while the card is conflicted, and the tidy-undo revert in `02-tidy-desk.md` carries `DESK_TOOL_COMMIT=1`.

The Bash and PowerShell guard has fewer false positives: a script counts as writing a card only when the card is the write target of the call (`writeFileSync`, `copyFile`, `rename`, `open(.., 'w')`, `Path(..).write_text`, `shutil`, `[IO.File]::WriteAllText` and the like), inline or through a variable, so a script that only reads the card passes; a PowerShell cmdlet counts only when the card is its `-Path`, `-LiteralPath`, `-FilePath` or `-Destination` operand or its positional target outside a parenthesised sub-expression. `recordLocalOnlyOnCards` (boot's local-only record) now commits the card through the same commit path as every other card write, and leaves a card with unstaged edits unrecorded; the `repo-handling` skill corrects a baked-in absolute `local_path` with `task_update` instead of a hand commit. The harness also catches `git remote set-url` of any remote to a folder and `gh repo clone`, lets explicit non-card pathspecs keep a staged card out of a hand commit, and counts a clone as backing a clone claim only when it cloned the repository the claim names.
