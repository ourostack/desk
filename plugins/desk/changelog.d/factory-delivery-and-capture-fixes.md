The capture record now tells the store which host a machine could not count. A host whose listing was capped or unreadable goes in as exactly `{"not_counted": true}`, and the other hosts keep their true counts, so the record never replaces a host's real numbers with a gap and never says zero for a host it could not count. Before, one uncounted host stopped the whole record. The loop slot's check is now exactly as strict as the store's `loop_slot_v1` (version 1, only the known keys, counts or null), so a record Desk accepts is a record the store accepts instead of one that waits a week for the store's refusal. When the store's own check cannot read the commits (`capture_check_unavailable`), Desk treats the pull request as stale and sends the record again in its normal turn instead of backing off for seven days. The local `frozen_by_reason` count no longer counts an orphan twice.

A job whose sessions are held back for a visibility answer is no longer reported as delivered, so the task tool's sync at done keeps its request until the files really go. A deadline that falls during the fresh visibility question now ends the flush as a deadline and leaves the last recorded count of waiting sessions as it was. Finished retractions' tombstones are removed after 90 days, but only when no local copy of that session is left for the store, and a kept copy with no record and no positive route stays away even if `status.json` is lost. The outbox copy of a delivered session is removed only when its transcript is gone, its record is over 90 days old, and it is the very copy that was delivered (a delivery recorded by an older Desk keeps its copy). `factory.js status` now shows what the sweep pruned (or that pruning failed) and a store whose own capture check keeps failing. A current orphan no longer takes one of the orphan pass's slots, so a long list of them does not make new work wait.
