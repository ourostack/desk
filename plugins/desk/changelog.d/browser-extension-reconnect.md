Keep the browser extension reconnecting to Desk after its native host stops. The browser stops an idle extension service worker after 30 seconds and its timers with it. When the extension could not reach its host (its profile token document failed), its reconnect delay grew to 30 seconds, so the worker could stop with nothing to reconnect it, and every browser call failed until a browser event happened to wake the extension. When the host itself failed as it started, the extension relaunched it every second, forever. The delay now backs off to at most 10 seconds and resets only once the host answers, a wake whose start fails is retried, and a 30-second `chrome.alarms` alarm wakes a stopped worker, which reconnects if its native port is gone ([`browser-extension/background.js`](browser-extension/background.js)). The extension gains the `alarms` permission, which shows no warning.

This changes the extension's source, so on an installed machine the extension must be reloaded once. Until it is, desk-web answers `browser_native_messaging_update_required`. The reload runs through the existing deliberate update, `node "<Desk plugin>/mcp/web.cjs" --desk-native-update`: it waits until no session owns tabs, publishes the verified source, reloads only the Desk extension and attests the reconnected provider. It never restarts the browser.
