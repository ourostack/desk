A Desk commit that times out no longer reports a failure when it actually landed. Git runs its hooks inside the commit call, the card guard before it and Git LFS after it, so on a busy shared checkout the 10-second bound could end the call after the commit was already in `HEAD`. `lesson_add` then said the lesson was not in effect and never scheduled the push, so the commit stayed on one machine (#561, and the same for `task_update`, `task_archive` (#556) and every other tool that commits). After a commit times out or errors, Desk now reads back whether `HEAD` holds exactly the paths it committed with the content it wrote. A commit that is there counts as committed and its push is scheduled. One that is not there is reported as failed. When Desk cannot tell, it reports `unknown` and never commits again blind; Git commands that change the repository still run once per call ([read-back](../mcp/src/util/git-stage.js)).

Every result that leaves a change uncommitted now carries `route_around`: the exact steps to finish that commit by hand, starting with a read-back, plus a read-back for "committed here" and a separate one for "published to the remote". A live task card is committed through `task_update`, because the card guard still refuses a hand commit of it. A file that already held another session's edit is committed from a temporary worktree, so that edit stays uncommitted. A route never stashes, forces, adds with `-f`, `-a` or `-A`, skips hooks or names a remote ([routes](../mcp/src/util/route-around.js)). Improvement cards report the new `commit_unknown` code beside `commit_failed`.
