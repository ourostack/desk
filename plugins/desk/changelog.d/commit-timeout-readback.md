A Desk commit that times out no longer reports a failure when it actually landed. Git runs its hooks inside the commit call, the card guard before it and Git LFS after it, so on a busy shared checkout the 10-second bound could end the call after the commit was already in `HEAD`. `lesson_add` then said the lesson was not in effect and never scheduled the push, so the commit stayed on one machine (#561, and the same for `task_update`, `task_archive` (#556) and every other tool that commits). After a commit times out or errors, Desk now reads back whether `HEAD` holds exactly the paths it committed with the content it wrote. A commit that is there counts as committed and its push is scheduled. One that is provably not there is reported as failed. When Desk cannot tell, or the commit landed but `HEAD` no longer holds it, it reports `unknown` and never commits again blind; Git commands that change the repository still run once per call ([read-back](../mcp/src/util/git-stage.js)).

Every result that leaves a change uncommitted now carries `route_around`: steps that start with a read-back, a read-back for "committed here", and a separate one for "published to the remote". A route never commits whatever the paths hold now, because later bytes there may be another session's. When Desk captured the change before its commit call (each entry's mode and blob, the `HEAD` and the branch), the route finishes exactly that change with `scripts/finish-commit.js`. It changes nothing unless every check passes. It then builds the commit from a private index, runs the repository's commit hooks through Git, and moves the branch by one compare-and-swap against the `HEAD` it checked, so another writer's commit is never undone. The finish runs from a shell, outside a tool call's budget, so its hooks and branch update get 600 seconds while its reads keep 10; a tool's own commit keeps its 10-second bound. A cut-off is reported as `unknown`, and nothing is ever repeated. Without a captured change the route is held: it reads, stops and reports. A live task card is still committed only through `task_update`, because the card guard refuses a hand commit of it. A file that already held another session's edit is left as it is, staged selection included: the route reads it and commits through `desk_save` only once it holds nothing else. A commit Desk cannot classify stays `unknown` in every field and sentence. A route never stashes, resets, adds, forces, skips hooks or names a remote ([routes](../mcp/src/util/route-around.js), [finish](../mcp/src/util/finish-commit.js)). Improvement cards report the new `commit_unknown` code beside `commit_failed`.
