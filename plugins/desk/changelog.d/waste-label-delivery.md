Accepted waste labels now reach the store, and finished tasks without labels are noticed at session start. The [flush](mcp/src/factory/flush.js) delivers local labels in the same intake pull request as facts: each becomes `labels/<job>/<session-id>.json` through `toPublishedLabels`, with the job keyed as its session's facts are, and passes the labels gate; a refused one is quarantined under its local key. A rejected intake PR quarantines its labels with its facts, and a stale one sends them again. Labels go only with their session's facts, already on the store's default branch or in the same batch, so a batch cap can never send labels the store would refuse for missing facts.

Labels whose session's facts are quarantined can never be delivered, so they no longer wait forever: the new outbox helper `holdLabels` quarantines them as `facts_quarantined`, with the quarantined facts file named in the record. The flush applies it before batching and after reading rejections, and the [evaluator](mcp/src/factory/evaluate-run.js) applies it to a session whose facts are quarantined, which then gets no brief and no longer keeps its job's evaluation request pending.

A new `labels` [boot check](hooks/boot-checks.cjs), second in the registry, runs when a store has consent. For retained evaluation requests it returns `Factory: N finished tasks have no waste labels yet; run the evaluator for them in the background` and starts a detached `factory.js evaluate --pending` through the compatible-Node launcher. For finished jobs with quarantined labels it returns `Factory: N finished tasks have quarantined waste labels that will not be delivered; tell the operator (desk:session-start)`, without a repair, and a request whose every session has quarantined labels is counted there rather than as waiting. [`desk:session-start`](skills/session-start/SKILL.md) Step 4.8 now owns what the agent does with these lines and with any `evaluate` answer, including starting one background `desk:observer` per ready job; [`desk:task-lifecycle`](skills/task-lifecycle/SKILL.md)'s done step points there.
