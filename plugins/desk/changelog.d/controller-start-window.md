On Windows, the readiness controller now gets 15 seconds to start instead of 10. Besides loading the runtime and scanning the workspace, which take the same on every platform, a Windows controller reads its own process start time through PowerShell, and that read is capped at 5 seconds. On a loaded machine a lone controller could spend the whole cap on the read and then miss the flat 10 second window, so a session failed with "readiness controller child startup timed out" (issue 255). The window is now the base 10 seconds plus the read cap, so the cap and the window cannot drift apart. macOS and Linux keep 10 seconds.
