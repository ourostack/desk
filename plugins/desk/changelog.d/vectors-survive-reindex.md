Meaning-based search (`desk_recall`, `desk_similar`) now becomes ready on a busy desk that older Desk builds also write to. Desk stored each section's embedding by the section's row number, and re-indexing a card gives every section a new row number even when its text is unchanged. On a desk where an older session re-indexed a busy card every minute or so, each pass embedded thousands of sections only to lose them at the next re-index, so recall never became ready and the index file kept growing. Embeddings now live in a new `text_vectors` table, keyed by the section's text and the embedding settings that made them, so they survive any re-index; an edit embeds only the sections whose text is new, and re-indexing a card rewrites only the sections that changed, so an append to a long card writes one row instead of rewriting them all. A vector is saved only while a section with its text still exists, and vectors no section uses are removed after an hour. When the index moves on while recall waits or reads, recall waits for the index to catch up and reads again instead of refusing, until one read is current from start to finish or its deadline runs out; it never answers from an index that moved on.

The first start of this build copies the old table's embeddings into the new one without asking the embedding service for anything, and copies only those whose section still exists. The old row-keyed `chunk_vecs` table stays for older builds on the same desk, which keep working; this build removes the old rows no build can read, in short batches, without rewriting the database file.

When Ollama answers that a section is too long, in either its older ("input length exceeds the context length") or newer ("input (N tokens) is too large to process") wording, Desk halves the section's text and sends it again, up to six times, so the start of the section stays searchable. A section refused at every length is recorded as skipped for these embedding settings and is not sent again at each catch-up. Shortened and skipped sections count as covered, so they no longer keep meaning-based search from becoming ready. `desk_status` says in plain words how many sections were shortened or skipped, names their cards, and says that exact-word search (`desk_search`) still finds them in full. A failure of the embedding service itself still stops the pass, and nothing is recorded as skipped.
