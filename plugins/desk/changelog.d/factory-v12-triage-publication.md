Factory triage annotations can now reach a factory store. An annotation this machine wrote and the desk's remote acknowledged goes to the store this desk routes to, as one immutable `triage/<batch>.json` file in the existing intake pull request, built only from closed codes, random IDs and pointers the flush has just found public. Nothing is sent until the store's default branch holds a `triage.json` of exactly `{"triage":1}`, read again in every flush that publishes, and only from an account with push permission on the store. A refused batch never quarantines facts, and a batch counts as delivered only when the store's default branch holds its exact bytes; a path that holds other bytes gets a fresh batch, never a change. `status.json` gains a `triage_publication` summary per store, which `factory.js status` prints, and the factory status that `desk_status` reports gains a `triage_publication` health entry per contributing store (`held`, `not_published`, `source_incomplete`, `stale` after 72 hours, or `current`). See [Publishing triage to the store](docs/factory-local-capture.md#publishing-triage-to-the-store).
