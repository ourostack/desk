Desk Browser `mine` reads pages that contain iframes, such as amazon.com product pages, instead of refusing them with `AUTH_FRAME_COVERAGE_REFUSED`. The [owned reader](mcp/web-auth.cjs) reads the main document. Each iframe, frame or embedded object shows as an empty `frame` node, its child document, fallback content and controls are never read, and the result's `framesOmitted` counts them. Anything that may have been typed in a same-process frame (field values and editable text) is still redacted wherever the main document repeats it. Only the main frame's own navigation invalidates a read, so busy ad frames no longer do.

Large real pages read too: the main document may now have up to 100,000 nodes (it was 20,000) and the native packet up to 2,000,000 values (it was 200,000). Two kinds of value no longer count as possibly typed. Hidden (`display: none`) text now takes the editing mode of its nearest rendered ancestor, or of `contenteditable` set on an element between them. Values under 8 characters in hidden, submit, button, reset and image inputs are page codes. Before, those values redacted every matching letter or digit on the page, so "USB 5.0" read "[redacted]B 5.[redacted]". Typed values, editable content and typeable fields (text, number and the rest) stay protected as before.
