A live tidy run on a weaker model exposed three ways the one-time organization tidy could damage a desk: `track_empty` counted a track holding only `_meta`/`_planning` files as empty (it archived `friends`, a who's-who layer, on exactly that basis), `name_shape` forced a rename of an already-good one-word track name such as `clippy` or `spoonjoy` and a weak session then invented a worse name to satisfy it, and `--write-record` wrote the tidy record even when the session skipped the printed procedure's own step 7 checks.

`track_empty` now walks the whole track directory: any file anywhere under it besides `track.md` itself — including inside `_meta/` or `_planning/` — means the track is not empty. `name_shape` now accepts 1-6 lowercase kebab-case words instead of requiring a second word, so an established one-word name is valid shape on its own. `--write-record` now runs step 7's own checks in code before it writes anything: it refuses when this session's own desk still has an unstaged or untracked change, when nothing at all is staged, or when a track directory (among the ones this run touched) holds a task card whose `track:` field still names a different track — the mark a track folder moved by a raw `git mv` leaves behind instead of going through `track_rename`. The printed procedure also now says plainly, in its own step, that a raw `git mv`, a bare `git add -A` or folder/pattern add, and deleting `.git/index.lock` are forbidden, and that a track or task only ever moves through `track_rename` or `task_move`.
