The factory's visibility lookup for a referenced repository, a plugin's install source, or the store's own remote asked the account's own token once and cached a 403 or a 404 as "unknown" for seven days. A fine-grained personal access token scoped away from a repository, or an organization's SSO enforcement withholding it from that token alone, still answers 403 or 404 for a repository that is genuinely public, so a plugin whose source lived there stayed hidden behind `refs.private.plugins` for a week even though its source was public.

A 403 or a 404 is now retried once with a plain, unauthenticated HTTP request before it is accepted, never through `gh`: unsetting `gh`'s token environment variables still leaves it free to fall back to its own stored login, which answers for whichever account happens to be signed in there instead of for no one. A repository that is truly private or gone still answers 403 or 404 to that unauthenticated request; one only the account's own token could not see now resolves public and its plugin is named. Only the exact confirmed answer, public, private, or still unknown after both tries, reaches the cache. A network failure, a 5xx, or a rate limit on either try, including a rate-limited 403 recognized by its exhausted `x-ratelimit-remaining` budget or its message, still stops the flush outright instead of ever being cached as unknown.
