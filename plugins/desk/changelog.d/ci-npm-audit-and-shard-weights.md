CI installs no longer wait on npm's advisory audit. Each workflow that installs dependencies sets `npm_config_audit=false`, and the hosted image's `npm ci` passes `--no-audit`. The audit only printed a report and gated nothing, but when the registry's audit endpoint stalled it held every `npm ci` for about seven minutes, so the hosted gateway job ran past its ten-minute limit and each coverage shard spent fourteen minutes installing. The coverage shard weights in [`mcp/config/coverage-shards.json`](mcp/config/coverage-shards.json) are refreshed from two recent passing runs, taking each file's longer duration, so the slowest shard is predicted at about six minutes instead of eight and a half for the default test set, and about seven and a half when changed files also select the offline evals, inside the shard's ten-minute watchdog.
