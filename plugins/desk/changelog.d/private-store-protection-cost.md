Desk's private-store writes are much cheaper, on Windows and on macOS, with the same protection. Every factory write used to start an operating-system tool to protect and verify its folders and file: Windows PowerShell on Windows, which takes several hundred milliseconds to start, and two `chmod` and `ls` processes per path on macOS. A factory flush made thousands of those calls, so one Windows test file ran for about twenty minutes.

On Windows, Desk now keeps one Windows PowerShell per process and sends it each protection request on a line of its input, so the start-up cost is paid once instead of once per write. Every request still rewrites each path's access list to exactly one rule for the current user with inherited rules cut off, reads it back and proves it, and a path owned by someone else, a reparse point or a failed check still refuses the write. The helper answers one request at a time. A request that times out (the 20 second limit is unchanged and now applies to one start per process instead of one per write), produces too much output, answers with anything but one line, speaks out of turn or exits is refused, and the helper is stopped and replaced for the next request. It never keeps Desk alive, it ends when Desk ends, and it stops by itself after a minute without a request. A native Windows micro-benchmark of 100 new and 100 rewritten private files fell from about 520 ms to about 33 ms per write.

On macOS, Desk lists a path's access list first and clears it only when an entry is there, so a clean path costs one process instead of two. A folder or file this process already found clean is not listed again while its identity and change time are unchanged, and any change to it, including adding an access entry, lists it again. A path that still has an entry after clearing is still refused. The same benchmark fell from about 27 ms to about 10 ms per write. Linux does nothing here and is unchanged.

Sixteen first callers of one state root no longer fail on Windows with "inherited access rules still apply". They share one process, and their protection requests used to run as separate PowerShell processes that rewrote the same folder at the same time; now they reach the helper one at a time. When a different process rewrites the same folder at the same moment and this call reads back a half-applied list (inherited rules not yet cut off, or a rule not yet removed), Desk protects and verifies once more before refusing. Any other refusal is final.
