### What a session must not take with it stays on the desk

Coordinators kept their rulings, lane owners and evidence pointers in the host's session folder or `/tmp`, which goes when the session does, and handed work to each other by those paths. A successor then asked the operator again or contradicted them. This change gives that state a cheap home and says where the line is.

- **The line.** [`using-desk`](skills/using-desk/SKILL.md) now asks of anything you would write down: if this session vanished now, would anyone, a successor included, lose it? If so it goes on the desk or in the product repository and is named by that path or URL; if not, it is scratch and nothing outside the session may point at it. It overrides a host's instruction to keep notes in its session folder.
- **A cheap append.** `task_update` takes `log`: a dated entry in `log.md` beside the card. The entry is in the file when the call returns, and entries written close together share one commit and one push, so a burst of rulings no longer costs a commit each. [`tests/desk/mcp/bench/card-appends.mjs`](../../tests/desk/mcp/bench/card-appends.mjs) measures it: ten rapid appends left ten commits and ten scheduled pushes, at about 5.2 s and 21 Git processes per append on a machine under heavy load, and now leave one of each, at about 0.25 s and 2.4 Git processes per append.
- **No refusal while a save is publishing.** On a repository that publishes through checked pull requests, every write after the first was refused with `content_home_unpublished_base` until the first one had merged, which takes minutes. A purpose policy now accepts a checkout that is ahead of its published base only by commits Desk's own write tools made, with the same policy file and no merge. A commit made any other way still stops the write. In the bench, nine of ten rapid appends were refused before and none are now.
- **One small append is one call.** A 300-byte append to a repository that publishes through checked pull requests took five calls and about four minutes, and each step is now handled where it happens. A checkout that is only behind its upstream is fast-forwarded the way `git checkout` would (a file another session changed holds it, and the write still goes ahead). The upstream is resolved from the branch's own settings when `@{upstream}` cannot map it, and a Git call the clock cut off is asked again with more room before it counts as an answer. A commit the clock cut off is read back and run once more rather than handed back with route-around steps. A branch another writer moved while a commit was being qualified is qualified again on its new tip inside the same call, and a publication whose base moved during its checks is rebuilt on the new base, qualified again and its abandoned pull request closed, with no hand-back to the agent. `log` itself waits on none of it: it writes the entry and returns.
- **A warning, never a refusal.** `task_update`, `task_create` and `desk_save` answer with `scratch_paths` when the text names a path in a host session folder, a harness's history folder or a temp folder; the warning leads with the fix. Boot lists each active card that names such paths, and `desk_status` carries the count per task.
- **Hand-off by Git.** A file `desk_save` writes under a task's `handoffs/` folder comes back with `handoff_references`: its repository URL, which resolves once the push lands. Pass that, never a local path.
- **Resume from the desk.** `task_focus` shows the task's log (its path, entry count and newest entry) beside the next step, and the session-start and resumption skills say to resume from the card and its log, not from a host's checkpoints. Cross-session messages and lane prompts are outside Desk's reach; the foundation sentence and [`session-resumption`](skills/session-resumption/SKILL.md) cover them.
