`task_focus` now survives an idle release of the Desk server. When the idle proxy ends the server child, it keeps the declared focus (or the deliberate clear) in its own memory and, over a private parent-child channel that is not an MCP method, hands it to the next child. The new server restores it only after checking that the root and write scope are unchanged and that the card still exists, and it writes nothing to the desk to do so. When the focus cannot be restored (the card moved, the scope changed, the restore timed out, or the old server crashed), `task_update` and the other task tools now say the earlier focus is unknown and to declare it again, instead of the misleading "no task in focus" hint. The focus is still memory-only: it is lost when the proxy or host ends, and an older server that does not speak the channel behaves as before. See [mcp/README.md](mcp/README.md).
