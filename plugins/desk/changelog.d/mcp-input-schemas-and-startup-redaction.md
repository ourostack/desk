Every Desk MCP tool now advertises a real JSON input schema ([tool schemas](mcp/src/tool-schemas.js)), with its properties, required fields and `additionalProperties: false`. Before, 17 of the 18 tools were listed as `{ properties: {}, additionalProperties: true }`, so Claude Code had no shape to build arguments from and sent `task_update`'s `frontmatter` as a JSON string, which the tool spread into the card as one key per character (`"0": "{"`, `"1": "\""`, ...). A test now fails if any tool is registered without declared properties or with a required field it does not declare.

`task_update`, `track_update` and `desk_search` also check their object arguments themselves ([object input](mcp/src/util/object-input.js)): a plain object is used as is, a string that holds a JSON object is parsed, and anything else is refused with a clear error before the card is read or written, so a corrupted card can no longer be written.

Session start no longer repeats a folder name that carries a secret's value. The `Desk startup:` and `Desk boot:` lines both hooks inject now redact each path segment, branch name or word that looks like a password value, a 16+ character secret run, a known token prefix or an IPv4 address to `<redacted segment>` ([redaction](mcp/src/util/redact.js)); the machine's own home and temporary folders are exempt, and the boot line is withheld rather than shown unredacted if the redaction cannot load. `desk:session-start` now builds its status block from a new [active-task listing](mcp/scripts/active-tasks.js) that redacts track, task and desk names and titles the same way and counts what it hid, instead of globbing task cards and echoing each folder name, and it never recovers or quotes a redacted name. This closes the live finding where a session-start status quoted the user and password in two task folder names. A topic word such as `token` or `password` alone is not redacted, per the name rule.
