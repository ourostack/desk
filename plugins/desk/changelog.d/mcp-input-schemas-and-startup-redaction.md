Every Desk MCP tool now advertises a real JSON input schema ([tool schemas](mcp/src/tool-schemas.js)), with its properties, required fields and `additionalProperties: false`. Before, 17 of the 18 tools were listed as `{ properties: {}, additionalProperties: true }`, so Claude Code had no shape to build arguments from and sent `task_update`'s `frontmatter` as a JSON string, which the tool spread into the card as one key per character (`"0": "{"`, `"1": "\""`, ...). A test now fails if any tool is registered without declared properties, with a required field it does not declare, or with an object or list field that has no type. Object and list fields are typed: `repos` entries carry `name`, `local_path` and `mode`, and the work ledger's `operator_go`, `task_ref`, `carry_forward` and path lists have their shapes. Only the degraded server that runs when no compatible Node is found still lists tools with an open schema, on purpose, because every call there answers with the reason and the fix.

`task_create` now accepts and keeps `initiated_by` (`operator` or `agent`) and `origin_note`, which `desk:start-task` asks for; before, both were silently dropped. `desk:start-task` also says that `created`, `updated` and `schema_version` are set by the tool.

`task_update`, `track_update` and `desk_search` also check their object arguments themselves ([object input](mcp/src/util/object-input.js)): a plain object is used as is, a string that holds a JSON object is parsed, and anything else is refused with a clear error before the card is read or written, so a corrupted card can no longer be written. A bad `desk_search` filter says that nothing was searched and shows a filter example.

Session start no longer repeats a folder name that carries a secret's value.

- The `Desk startup:` and `Desk boot:` lines both hooks inject redact to `<redacted segment>` each path segment, branch name or word that looks like a password value, a 16+ character secret run, a known token prefix or an IPv4 address ([redaction](mcp/src/util/redact.js)). A path segment is judged whole, spaces included, so a folder named `set pw hunter2` is caught, and a sentence's closing full stop stays outside the marker. The machine's own home and temporary folders are exempt, and the boot line is withheld rather than shown unredacted if the redaction cannot load.
- `desk_status` now serves the active-task listing as `active_tasks` ([listing](mcp/src/desk/active-tasks.js)): non-terminal tasks by track, with track, task and desk names, titles and repository paths redacted the same way, a count of what it hid, and each task's repositories. `desk:session-start` and `desk:status` build their status blocks from it instead of globbing task cards, so hosts that gate shell commands do not prompt for it, and they never recover or quote a redacted name.
- The session-start desk sync is now `git pull --rebase --quiet`: without `--quiet` the pull printed a diffstat and a `create mode` line naming every folder another machine had created.
- Every task and track has a stable handle (`task-` or `track-` and ten hex characters, [handles](mcp/src/desk/handles.js)) in the listing, in `desk_doctor`'s organization findings and in the tidy report. `task_move` takes `handle` in place of `track` and `slug`, and `track_rename` takes `handle` in place of `track`, so a redacted folder gets an outcome name without anyone reading the old one; the tidy renames by handle instead of listing the folder's parent. A handle is a keyed hash of the folder's path; the key lives in Desk's state folder on this machine, not in the desk. `task_move` and `track_rename` also redact credential-like names in their results and errors.

This closes the live finding where a session-start status quoted the user and password in two task folder names. A topic word such as `token` or `password` alone is not redacted, per the name rule. Out of scope: `desk_status` still reports the desk root unredacted in `root`, because the agent needs the real path to work in the desk.
