`task_update` now refuses a transition to `status: done` unless the call also supplies `evidence: { kind, ref }` — `kind` one of `pr`, `commit`, `ci_run` or `non_code`, `ref` the PR URL, a commit on a remote branch, the CI run's own URL, or a stated non-code outcome's own proof link. A bare `done` is rejected with an error naming exactly what to supply, and the accepted evidence is recorded on the card as `evidence: { kind, ref, recorded_at }`. `task_archive`'s own implicit bump of a non-terminal task to `done` on archive is unaffected: it is a separate, non-`task_update` path, and archiving a task is itself the record of intentional closure.

A new `PreToolUse` hook (`task-status-guard.cjs`, Claude Code only for now) denies a direct `Write`/`Edit` to a task card's `task.md` that sets its `status:` frontmatter to `done` outside `task_update`, pointing the agent at `task_update` and its evidence requirement instead. Both close the same gap: an agent asked to resume a task that instead edited the task card's `status` directly, wrote a fabricated "Completed work" section describing tests and a merge that never happened, and committed it. `task-lifecycle/SKILL.md` gains a short "Resuming a task" section stating the same contract directly — report the recorded state, continue the recorded next step, never declare completion without evidence.
