**The MCP test suite could write into a developer's real `~/.local/state/ouroboros-skills/desk/factory/` instead of a temporary one.** `tests/desk/mcp/__tests__/tools/_helpers.js` (and `_search_helpers.js`) built each test's throwaway desk root with a bare `fs.mkdtemp`, without loading the global test-isolation setup (`_isolated_env.mjs`) the way `_temp_roots.js` and `factory/_session_helpers.js` already do. Under `npm test` or the coverage runner that made no difference, since both preload the setup for every test file regardless of what the file itself imports — but a file run on its own with a bare `node --test <file>` (a common way to re-run one failing test while debugging) got no isolation at all, and `task_update`/`task_archive` default their `env` argument to the real `process.env`. Driving a task through `done`/`cancelled` in that shape recorded real `finalize/<job>.json` and `evaluate-requests/<job>.json` files naming a `desk-test-*` temp fixture as the job's `desk_root` — the exact leak found on a developer machine (26 such `evaluate-requests` files, all from one such run). Both helpers, and `feedback/_helpers.js`, now import `_isolated_env.mjs` themselves, so a test file built on them is isolated whichever way it runs; `tests/desk/mcp/__tests__/test_isolation.test.js` gained a guard test that runs `task_archive.test.js` standalone against a fake "machine" home and asserts nothing lands there.

As defense in depth, [`factoryStateRoot`](mcp/src/factory/outbox.js) now also refuses a `deskRoot` that resolves under the OS temp directory when the state home it resolved does not also resolve there — a throwaway desk paired with a persistent state home is exactly the shape of an isolation failure like this one, whatever produces it. A real desk, never bound under the OS temp directory, is entirely unaffected.
