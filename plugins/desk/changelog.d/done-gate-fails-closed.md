The done-claim gate now fails closed on acceptance. It reads a card's sign-off with the same reader the rest of Desk uses (`outcome.js`), so the gate and the record can no longer disagree about a card. A reply that says a task was accepted, approved or signed off is now blocked once when the task's card is done with no sign-off block, a malformed one, or an acceptance recorded as `verified: false` in YAML flow form (`signoff: { state: accepted, verified: false }`), which the gate's own block-only reader used to miss. A card that cannot be read at all (gone, a folder, no frontmatter) also counts as unaccepted for an acceptance claim instead of skipping the gate. Stating the honest state ("delivered, not accepted", "unverified", "accept or send back") still clears the block, and the block still happens once: the retry passes.

The gate also no longer passes silently on its own error. When the Stop hook fails after a turn that touched a task (for example, the reply transcript cannot be read), it blocks once with a reason that names the error, and the retry is let through, so the agent is never trapped. A turn that touched no task, and a subagent's stop, still pass. A failure while recording a touched task is still quiet.
