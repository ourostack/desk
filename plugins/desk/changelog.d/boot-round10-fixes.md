### Boot prints next steps and blockers whole, names the push account and says when a card is not done

The boot text no longer cuts a task's next step: it prints each in full and caps the number of tasks shown (15, then a count) instead of the characters. A blocked task prints the reason its card records (a `## Blocker` or `## Waiting on` section, or a `Blocker:` line) and falls back to its next step; a card that records neither says "no next step recorded", so agents stop inventing filler. `active_tasks` carries the same `blocker` field and the whole `next_step`.

The push route line now names the account every time and the fork when the route is one: "push as arimendelow via fork arimendelow/widgets; the active gh account (work) is not the push account for this repo". The matching instruction tells the agent to push with that account's token and never to write the active account into a card as the push account.

Every Desk skill an agent can open first (`repo-handling`, `session-resumption`, `task-lifecycle`, `start-task`, `status`, `work-orchestration`, `using-superpowers-with-desk`, `git-hygiene`, `adopt-inflight-work`, `archive-workflow`) now starts with one line: if the boot has not run in this session, run `session-boot.js` first. `task-lifecycle` also says a reply over committed but unfinished work reports the real state ("committed <sha>; task is at validating; next: ...") and never "Done". A `task_update` that adds a note or changes the status without `next_step` now answers with the card's current next step and "next_step unchanged — update it if this work changed it".

The Superpowers artifact mapper's missing-path errors say exactly what to pass, with an example under the task's folder, and that the mapper creates nothing. No Desk tool leaves an empty folder behind on a failed call: a missing person folder is created by the write that needs it instead of by the path check, and a failed `task_move` or `task_archive` removes the destination folders it made.

The boot-acceptance harness reads git's argv (a commit message that says "push" is no longer a push), counts test claims only when they are the agent's own, treats a reply that opens with "Done." over an unfinished card as a failed claim, checks the account a note names as the push account against the boot's route, flags writes outside the fixture desk, the task's clones and the run's temp folders, and retries its temp-folder cleanup instead of ending the round.
