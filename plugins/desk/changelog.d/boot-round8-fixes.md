Boot acceptance round A found seven problems, fixed together.

Every write to an existing task card now goes through `task_update`. A fresh agent had edited a card's body to say "Push routing confirmed ... scenario is handled", committed and pushed it, and told the operator the task was completed, with no pull request and no check behind it. The card guard (a Claude Code `PreToolUse` hook) now denies any Write, Edit or MultiEdit of an existing `task.md`, not only a `status:` change, and its message names the call to use. `task_update` gains `note` (a dated line under the card's `## Progress log`) and `next_step` (replaces the recorded `**Next step:**` paragraph) beside `frontmatter` and `body_append`. A new card path is still `task_create`'s, and Desk's own tools, tidy and migrations write cards through the file system, which the hook never sees. Copilot and Codex have no equivalent hook yet; the `task-lifecycle` skill says so and states the rule for them.

"Resume `<task>`" now continues the card's recorded next step. `using-superpowers-with-desk` says a next step that is one small, clear change needs no plan document, and that a plan that is genuinely needed goes in the task's own iteration folder in the desk, never in the operator's code repository or the desk root. The agent chooses subagent or inline execution itself instead of asking the operator, and the adapter states that Superpowers' `writing-plans` is not the host's Plan mode.

`desk_status` and the session-start boot script now share one health word (`runtime/health.js`). The boot script's `sync` result is recorded after each pull, so `desk_status` reports `degraded` with the same `sync: unresolved (...)` line and a fix when the last sync failed, instead of "ready" and "in sync" beside a boot that said `degraded`. A later good sync or a successful push clears it.

The startup hook's `Desk startup:` line now says the boot has not run and gives the exact command with its absolute path (`node <plugin>/mcp/scripts/session-boot.js`, with `--task` when the operator names one), and the hook's own checks are labelled `Desk boot pre-checks:`, so neither reads as a finished boot. The `session-start` skill shrinks to what the boot instructions do not already say, and shows how to derive the same absolute path when the line is not in context.

A task card's `repos` entry may carry a `url`. When a recorded local clone is missing, the boot instruction gives the exact `git clone <url> <path>` (or `gh repo clone owner/repo <path>`), and when there is no url it says exactly what to ask the operator and where to save the answer.

The boot-acceptance harness only flags a push to a remote other than the desk's own origin, lists the injected task in the fixture's track card, and uses a fixture desk and prompts that read like a real operator's, with no harness wording and no "Never enter Plan mode" rule.

Review fixes on the same change. The card guard now denies only a live card of the bound desk (`<desk>/<track>/<slug>/task.md`, matched by real path, case-insensitively, with `~` expanded, and by inode for a hard-link alias); a `task.md` outside a desk is untouched, an archived card keeps the status-only guard, and a card whose frontmatter no longer parses may be repaired by hand, which the deny message says. When the bound root cannot be determined the guard falls back to the nearest parent folder with the desk marker (`_meta/` plus `_archive/` or `desks/`). The clone instruction accepts only strict `https://`, `ssh://` and `git@host:path` urls, shell-quotes both arguments and runs `git clone -- <url> <path>`; anything else gets the ask-the-operator text. `note` and `next_step` skip fenced code blocks, end the next-step paragraph at a blank line, list item or heading, replace the first marker and drop later duplicates, keep CRLF, and date notes in the operator's local time zone. The recorded pull failure carries a timestamp and `desk_status` treats it as cleared once a later fetch or push succeeded, or after 24 hours; the status file is written by temp file and rename, and concurrent writers are last-writer-wins. The harness counts MultiEdit, and judges a bare `git push` by the folder it runs in.
