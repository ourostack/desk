### Own the stack: file it where it lives

`using-desk`'s "Own the stack" rule now says to work around a tool that can't do the job, then file the tool's bug with evidence: `friction_add` with `about: "system"` and `plugin` set to the tool opens an issue on that tool's repo, where its issue drain picks it up. Ari's agents own those tools; other people's agents file the issue and ping Ari. Before, the rule read as "work around it, then move on", and a refused `m365crawl` call went unfiled.

`friction_add` now files a real GitHub issue for every tool owned in ourostack besides Desk (`m365crawl`, `shepherd`, `housesitter`, `hackamore`, `ouroboros`) on `ourostack/<tool>`, labeled `bug` and `tool-friction`, with the title and body as the issue, so the body carries the evidence. The text is held to the kaizen filer's scrub (no credentials, home paths or email addresses; a refusal comes back with paste-ready text), the same failure is never filed twice (a fingerprint marker, open or closed), and at most five issues a day per repo are filed from one machine. No Desk improvement card opens for it. A duplicated paragraph in `using-desk` is gone, which keeps the always-on text under its budget.
