Desk Browser `mine` screenshots refuse a child frame they could not read, and `type` sends keys only to a target that still has the focus ([#679](https://github.com/ourostack/desk/issues/679)). A screenshot reads out-of-process frames strictly: a closed shadow or a failed read in one refuses the picture and leaves no file, and a frame the browser gives no way into is masked whole by its owner. `type` no longer waits after focusing its target. Before every key it checks that the target, or the editing host inside it, still holds the focus. If the page moved focus before the first key, `type` focuses the target once more. If focus moves away again, or moves during typing, typing stops with `AUTH_FOCUS_MOVED`, so no key reaches the element that took the focus. A refusal for a closed shadow no longer suggests `screenshot`, which refuses it too.
