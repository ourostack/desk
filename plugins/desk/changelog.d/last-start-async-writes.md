A Desk session now writes `last-start.json` and the root's own start record without blocking its event loop ([`mcp/src/runtime/last-start.js`](mcp/src/runtime/last-start.js), [`mcp/src/runtime/desk-session.js`](mcp/src/runtime/desk-session.js)). Each admission state change used to write both records synchronously. On Windows, creating the temporary file waited 139 ms on one runner, so a `desk_status` call that arrived during the write answered in 260 ms instead of about 100. The records are now written in order with asynchronous I/O and an asynchronous rename retry (`renameWithRetryAsync` in [`mcp/src/util/rename-retry.js`](mcp/src/util/rename-retry.js)), and closing a session waits for them. A record can therefore land a few milliseconds after the tool call that reported the state; readers in other processes, such as the boot checks, were already reading it later.
