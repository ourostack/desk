Two fixes to the steps in `task_update`. The `step_note` that says which steps are "now ready" is now read from the card after the refresh, so a step the call added and the refresh then found already delivered is no longer called ready, and a step the refresh unblocked still is. A step with no repo (`—`) can no longer take a GitHub PR as its evidence on a card that has repos: the call is refused and asks for one of the card's repos first, because Desk would otherwise derive the step's state from a PR it cannot place under any repo of the card. The card does not record which GitHub repository each repo name stands for, so a step that has a repo is not compared with its PR's repository.
