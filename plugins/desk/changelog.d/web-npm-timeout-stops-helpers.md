The default browser launcher now stops everything npm started when an npm call times out, not just npm itself. A timed-out `npm install`, `npm view` or registry lookup used to be ended with a kill of the npm process only, so helper processes it had started could stay behind. On macOS and Linux the launcher now ends npm's whole process group, and on Windows it runs `taskkill /T /F` from the Windows folder named by `SystemRoot`, never from `PATH`. The same stop is used when a stop signal ends a first install. Nothing the launcher emits to a host changes.
