Tell the operator once per store, not once per session, that Desk can contribute measurement data.

While a store's contribution decision is undecided, the session start gives an interactive session one sentence to say after the operator's work is done. "Say it once" was only wording, so every session got the same instruction: in the Agency dry runs of 2026-10-12 one session said the sentence twice and the next session said it again, although the contract is that the question is asked once at setup ([RFC](docs/agentic-engineering-v2-rfc.md), section 4).

The session that says the sentence now records it with `factory.js consent --store <store> --mentioned yes`, a command the session start names beside the sentence. It decides nothing and writes one small file for the store in Desk's state folder ([`mcp/src/runtime/consent-mentioned.js`](mcp/src/runtime/consent-mentioned.js)). While that record exists and the store is still undecided, the session start's consent line says the operator was already told and must not be asked again; "factory details" still leads to the full question. The session start itself records nothing, because it cannot know the sentence was said: a session that ends before its work is done never reaches it, and the next session still gets it.

A session with no operator in it is unchanged: it gets no consent line and reads no record. `desk_status` still reports the store as `undecided` until the operator answers yes or no.
