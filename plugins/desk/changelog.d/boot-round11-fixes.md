### A task_update on an unfinished task says how to report it, boot says to report the real status, and remote-only repos are cloned only when needed

A `task_update` that leaves a task at any status other than `done` or `cancelled` now returns `report_as` ("Task <slug> is at validating (not done): <next step>") and `report_note` ("Do not tell the operator this task is done; it is at validating."). The cue sits in the response the agent has just read, because agents did not reopen `task-lifecycle` when they replied, and four acceptance rounds in a row ended with "Done." over a card still at `validating`. The boot's numbered instructions gain one line: "When you report on a task, say its real status; say 'done' only for a task whose status is done."

A repo recorded as `mode: remote`, or with no local path, is no longer cloned by default. When the operator names a task that has such a repo, the boot says: do not clone it unless the next step needs its code; if it does, clone into the operator's code location (`defaults.clone_root` in `.machine-local.yml`, default `~/code/`), never `/tmp`; and record the clone on the card through `task_update` (`local_path`, `mode: local`). `session-resumption` (Step 2) and `repo-handling` say the same, and the instruction for a recorded clone that is missing from this machine now begins "only if the next step needs its code". The named task in the boot's JSON result carries `remote_repos`.

The boot-acceptance harness now allows writes only in the fixture desk, the isolated HOME and the run's own temp folder (plus `/dev/null` and the standard devices), not all of `/tmp`; skips tool calls a hook denied in every claim and write check; fails any `git clone`, `fetch`, `pull`, `ls-remote`, `remote add` or `gh repo clone` that reaches a real host, and rewrites GitHub fetches to a dead local path in the run's git config so one fails at once; fails an unsupported "the active account cannot push" claim that the boot never made, and no longer reads "implementation complete and task transitioned to validating" as a done claim.
