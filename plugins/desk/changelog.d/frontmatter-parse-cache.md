A task card whose frontmatter is not valid YAML is now treated as broken every time Desk reads it, instead of only the first time in a process: the tools that edit a card refuse it, and the scans skip it or count it as unreadable ([`mcp/src/desk/organization.js`](mcp/src/desk/organization.js), [`mcp/src/util/fm.js`](mcp/src/util/fm.js), [`mcp/src/indexer/discover.js`](mcp/src/indexer/discover.js)). The YAML library remembered each text before parsing it, so the second read of a broken card came back as a card with no frontmatter: `desk_status` stopped counting the card as unreadable after its first run, and a second attempt to patch a card with a duplicated key wrote a new frontmatter block above the old one and dropped the other fields. Desk now parses without that cache, so each read also gets its own data.
