Work stays out of a host's own folders. Copilot's system prompt offers the session folder, `~/.copilot/session-state/<id>/files/`, as a place that "persists across checkpoints for artifacts that shouldn't be committed", and one agent left about 2,800 research files there; another invented a `~/.<app>` folder for its work. Agents work across sessions and machines, so work kept in one machine's private folder is lost to the rest. The always-on foundation ([`skills/using-desk/SKILL.md`](skills/using-desk/SKILL.md)) now says to keep no work in a host's session folder or a new `~/.<name>` folder, and the host-command table in [`skills/interaction-style/SKILL.md`](skills/interaction-style/SKILL.md) maps the session folder (and Claude Code's `~/.claude/projects/` and Codex's `~/.codex/sessions/`) to the repository for code and docs and the desk for private work product, and an invented dot folder to the operating system's app-data folder, the repository or the desk. To keep the session-start context within its budget, the foundation's AI-attribution sentence is shorter and keeps the same rule.

On Copilot CLI the launcher can make this structural, next to `--excluded-tools=ask_user`: `--deny-tool="write(${COPILOT_HOME:-$HOME/.copilot}/session-state/*/files/**)"` refuses Copilot's file tools under `files/` even with `--allow-all-tools`, while Copilot's own session writes go on. It does not cover the shell, and Copilot has no setting for it, so only the launcher can add it; Desk adds no tool-call hook. See [the session folder on Copilot CLI](docs/agent-files.md#the-session-folder-on-copilot-cli). The always-on evaluation contract gains two cases that tempt the agent to use the session folder or a new dot folder.
