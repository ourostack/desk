Agents can now record the worktrees and branches they create on the task card, and Desk reminds them to clean each one up when the work's state says it is due. `task_update` takes `resource: {identity, step?, intended?, disposition?, details?}`, which adds or updates one row of the card's `## Resources` table (the six-column table in `task-lifecycle`, created after `## Steps` or `## Outcome` when absent). `identity` is `worktree:<absolute path>` or `branch:<owner/repo>#<name>`; `step` writes `step <id>` in the owning column; `disposition` (`removed-and-absent`, `named transfer` or `retained-with-trigger`) and `details` go into the terminal column. A row with an empty terminal column is due when its step is delivered or dropped, or the task is done or cancelled; a due worktree whose path is gone from this machine is reported as a `stale row`. The `task_update` answer that makes rows due lists them with why and the safe action, and session start adds `Cleanup due: N items on M cards` (and `cleanup due: N` under the task) when any exist. Desk never removes anything and makes no network call for this. For now rows are written on `task.md`, not an iteration's `doing.md`; a card with no Resources table is unchanged.
