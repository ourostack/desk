Fix three session-start defects found by the cold dry runs of 2026-10-12, two of them on Copilot CLI.

- **New work described in the first message gets a task before any design.** The session start's instructions covered a named task and "no task named: ask which one to resume", but not a first message that describes new work: one session ran the session start and went straight to design, with no Desk tool call and no task card. Both instructions that ask which task to take up are now followed by one that says a description of new work is the answer, and that the task is created with `task_create` and `focus: true` before any design, plan or code ([`mcp/src/runtime/boot-text.js`](mcp/src/runtime/boot-text.js)).
- **On Copilot, the session start says to ask in chat and never through `ask_user`.** Copilot's `ask_user` tool describes itself with "Never ask questions via plain text output", and sessions used its form right after being told to ask which task to resume. An interactive Copilot session now gets one line that names the tool as not to be used. Desk still registers no hook on Copilot's tool calls.
- **Desk's Copilot session start turns off Copilot's AI co-author commit trailer, once.** Copilot asks its agent to end commits with `Co-authored-by: Copilot` unless `includeCoAuthoredBy` is `false` in the operator's Copilot settings (`~/.copilot/settings.json`, or `settings.json` under `COPILOT_HOME`). When the setting is unset, the session start sets it to `false` and says so in one line; a value the operator gave, on or off, is left alone, and so is a settings file that changed while the hook ran, is not a JSON object, or has comments or trailing commas (Copilot accepts those, and a rewrite would drop them; one line then says what to add) ([`mcp/src/runtime/copilot-commit-trailer.js`](mcp/src/runtime/copilot-commit-trailer.js), [`hooks/copilot-session-start.cjs`](hooks/copilot-session-start.cjs)). Copilot reads the setting before the hook runs, so it takes effect from the next session.
