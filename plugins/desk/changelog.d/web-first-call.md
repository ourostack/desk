The first browser call after a fresh install now succeeds, or at worst waits, instead of failing. Before, `desk-web` held its whole handshake while `@playwright/mcp` installed, and an install that outlasted its 25-second limit left the browser tools listed as unavailable for the rest of the session. Copilot CLI also refuses a call when the tool catalog it holds has changed, which is how a first browser call failed with "MCP tool catalog changed before tool ... could be invoked". Now a launch with no installed copy answers `initialize` and `tools/list` at once from a snapshot of Playwright MCP's own tools (`mcp/web-catalog.json`, same names and input schemas), installs in the background for up to 110 seconds, holds any `tools/call` that arrives meanwhile for up to two minutes, and then passes calls through to Playwright MCP. The tool list is the same for the whole connection, `notifications/tools/list_changed` is never sent (including when Playwright MCP sends one), and an install that fails answers each call with the failure code and the fix. A launch with an installed copy still hands stdio to Playwright MCP directly. A test now fails when the inline `.mcp.json` launcher's degraded tool names drift from `BROWSER_TOOL_NAMES` or from the snapshot.
