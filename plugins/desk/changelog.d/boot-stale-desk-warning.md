### Boot says when the running Desk is behind main, and refreshes it

Hosts cache plugin downloads (Agency keeps them for 24 hours), so a session could run a Desk many releases old while the fix for the bug in front of it had already shipped, with nothing saying so. Boot now compares the running plugin's version with `plugins/desk/plugin.json` on `main`. When it is behind, boot starts a refresh of the host's cached copy in the background and prints one line near the top, for example `Desk 3.2.0-alpha.153 is 19 releases behind main (3.2.0-alpha.172); refreshing the Agency plugin cache in the background, so a new session will run 3.2.0-alpha.172.` The `--json` result carries the same finding as `stale_desk` (`running`, `latest`, `behind`, `channel`, `refresh`, `auto_refresh`, `line`), or `null`.

Boot never waits for the refresh. It writes its output first, then starts a small detached runner and exits. The runner runs the host's command in its own process group, kills the whole group after 8 seconds so no launcher or npm shim child survives, records the outcome in `desk-refresh.json` and `repairs.log` in Desk's state directory, and releases its claim. The attempt is claimed atomically before anything is spawned and happens at most once an hour per machine, so agents that boot together start one refresh. The commands are the host's own: on Agency, `agency plugin cache remove -f <spec>`, where the spec is the `ourostack/desk` plugin on `@main` for the session's engine (`AGENCY_ENGINE`, else the agent host), read from Agency's cache index and matched to the running version; on Copilot, `copilot plugin update desk`, only when Desk is installed under Copilot's `installed-plugins` directory (`$COPILOT_HOME` or `~/.copilot`), never for a `--plugin-dir` or a development checkout; on Claude Code, `claude plugin update desk@<marketplace>`, with the marketplace read from where Desk is installed. Where no command can be derived, or the last attempt in the hour failed or is still recorded, the line names the manual step instead (`/plugin` on Claude Code; `copilot plugin update desk` or `agency plugin cache remove "copilot:github:ourostack/desk:plugins/desk@main"` on Copilot). `auto_refresh` says what boot did: `started`, `failed` (the recorded attempt failed), `skipped` (an attempt in the last hour), `unavailable` or `disabled`.

Versions compare as semver, so `alpha.9` is older than `alpha.10`; the release count appears only when both versions share the same `major.minor.patch-alpha` line, and otherwise the line says just "behind". The remote version string is capped at 64 characters, the response at 4 KB, and numbers above the safe-integer range are rejected. The version lookup never slows or breaks boot: it starts in parallel with the rest of boot, is cut off after 1.5 seconds, sends no credentials, caches its answer in the state directory (`latest-version.json`) for an hour (a failed lookup for 10 minutes), and says nothing on any error, timeout or offline machine. `DESK_BOOT_VERSION_CHECK=0` turns the check off and `DESK_BOOT_AUTO_REFRESH=0` turns only the refresh off; both are also off inside node:test runs and in the boot-acceptance harness's child environment.
