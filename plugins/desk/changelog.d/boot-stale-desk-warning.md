### Boot says when the running Desk is behind main, and refreshes it

Hosts cache plugin downloads (Agency keeps them for 24 hours), so a session could run a Desk many releases old while the fix for the bug in front of it had already shipped, with nothing saying so. Boot now compares the running plugin's version with `plugins/desk/plugin.json` on `main`. When it is behind, boot refreshes the host's cached copy itself and prints one line, for example `Desk 3.2.0-alpha.153 is 19 releases behind main (3.2.0-alpha.172); refreshed the Agency plugin cache, so a new session will run 3.2.0-alpha.172.` The `--json` result carries the same finding as `stale_desk` (`running`, `latest`, `behind`, `channel`, `refresh`, `auto_refresh`, `line`), or `null`.

The refresh runs after the boot text is written, at most once an hour per machine, with an 8 second timeout. It is the host's own command: on Agency, `agency plugin cache remove -f <spec>`, where the spec is read from Agency's own cache index (the entry for this engine and a `desk` plugin folder whose cached copy has the running version; nothing is hard-coded, and an ambiguous match refreshes nothing); on Copilot run directly, `copilot plugin update desk`; on Claude Code, `claude plugin update desk@<marketplace>` with the marketplace read from where Desk is installed. If the command is missing, fails, times out or cannot be derived, the line names the manual step instead (`/plugin` on Claude Code; `copilot plugin update desk` or `agency plugin cache remove "copilot:github:ourostack/desk:plugins/desk@main"` on Copilot) and the failure goes to Desk's `repairs.log` in the state directory, not to the agent. `auto_refresh` says what happened: `refreshed`, `failed`, `skipped` (an attempt in the last hour), `unavailable` or `disabled`.

Versions compare as semver, so `alpha.9` is older than `alpha.10`; the release count appears only when both versions share the same `major.minor.patch-alpha` line, and otherwise the line says just "behind". The version lookup never slows or breaks boot: it starts in parallel with the rest of boot, is cut off after 1.5 seconds, sends no credentials, caches its answer in Desk's state directory (`latest-version.json`) for an hour (a failed lookup for 10 minutes), and says nothing on any error, timeout or offline machine. `DESK_BOOT_VERSION_CHECK=0` turns the check off and `DESK_BOOT_AUTO_REFRESH=0` turns only the refresh off; both are also off inside node:test runs and in the boot-acceptance harness's child environment.
