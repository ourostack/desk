Fix seven Desk defects found by the cold dry runs of 2026-10-12 on Claude Code and Agency.

- **The tidy migration no longer stages files in the folder it was started from.** Its steps are printed from a heredoc the shell expands, and three phrases in them were in backticks, so the shell ran `git add -A` there as a command: started from a project repository, the migration staged every untracked file in it. The backticks are now escaped, and a test refuses a backtick or `$(` in any migration's expanding heredoc ([`migrations/02-tidy-desk.md`](migrations/02-tidy-desk.md)).
- **`desk_status` says what Desk repaired at the session's start.** A checkout that Desk switched back to its state branch was reported only by `desk_status` with `detail: true`, `last-start.json` and `repairs.log`. The compact answer now carries the line, for example `repaired: detached HEAD → main (was 0123456789ab)`, in `notes` ([`mcp/src/runtime/status-compact.js`](mcp/src/runtime/status-compact.js)).
- **The first `desk_status` of a session names the desk.** When the runtime's status detail misses the call's time budget, the answer is still `detail_pending: true`, but `root` now holds the path and source the session already admitted instead of `null` ([`mcp/src/runtime/desk-session.js`](mcp/src/runtime/desk-session.js)). It stays empty while the destination itself is being verified.
- **`desk_save` with `tidy: true` commits a tidy that moved files other than task cards.** It ran `git add` on every such path at once, and Git refuses the whole call for the old side of a move (`pathspec ... did not match any files`), so a tidy that moved a track card or a loose file could not be committed. It now stages only the paths that hold unstaged work ([`mcp/src/tools/desk-save.js`](mcp/src/tools/desk-save.js)).
- **`task_update` commits a card that already held uncommitted changes.** It used to write such a card and skip the commit without saying so. A card can be committed only through Desk's tools, and the desk's pre-commit hook sends the agent to `task_update` after taking a card out of a hand commit, which left the card with no way in. The answer's `included_uncommitted_changes` says when the commit took earlier changes along ([`mcp/src/tools/task.js`](mcp/src/tools/task.js)). `task_signoff` and a disposition on an archived card keep the old rule.
- **`desk_doctor` no longer fails on a desk with a stale `_cache/` entry.** The Organization section did not list the `stale_quarantine` finding and threw on it. The code is listed, a code the section does not know is printed in its own group, and the tidy treats a stale quarantine as reported only, as it does a stale task ([`mcp/src/tools/doctor.js`](mcp/src/tools/doctor.js), [`mcp/src/desk/tidy.js`](mcp/src/desk/tidy.js)).
- **Session sync never moves `_cache/` into itself.** On a desk whose `.gitignore` has no `_cache/` line, earlier quarantines were listed as stray paths and moved into the new quarantine folder. Paths under `_cache/` are now never stray ([`mcp/src/runtime/session-sync.js`](mcp/src/runtime/session-sync.js)).
