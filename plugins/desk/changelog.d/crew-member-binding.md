A member's session in a joined Crew workspace now knows who the member is and which desk it is in, on Copilot and Claude Code alike, with no launch setting. In a Crew workspace with no authority provider, the person comes from `--person`, then `DESK_PERSON`, then the roster row whose `identity` is the GitHub login the session acts as: the accounts signed in to gh, read from gh's own `hosts.yml` with no network call; GitHub is asked once per process only when several of them are on the roster (which can push to the workspace, the choice `crew.js` makes for its pushes) or when gh lists none. Writes then land only under that member's `desks/<alias>/`. An account that is not on the roster can still read and search, and every write is refused as `degraded:crew_member_unknown` with one plain message: join with `crew:join-crew`, or sign in to gh as the account that joined. The boot line, `desk_status` (`write_scope.person` and `write_scope.source`) and `crew.js status` (`session`) all report the same person from the same resolver ([crew-member.js](mcp/src/desk/crew-member.js)).

A session started in a Crew workspace clone now binds that clone even when a user-wide `DESK` or the saved binding names the member's personal desk. Before, the boot script ranked the folder it started in below `DESK`, so on Copilot a member's team session bound and wrote to the personal desk. The boot script and the tool server now resolve the desk with the same code ([startup-resolve.js](mcp/src/runtime/startup-resolve.js)); a personal desk as the start folder still ranks below `DESK`, so existing bindings keep working. `first-run-bootstrap` no longer tells Copilot users to set `DESK` for a desk Desk finds by itself.

Every child process Desk starts (Git, gh, the background sync worker's push, hooks) now passes `windowsHide: true`, so no blank console window flashes up on Windows, and a repository test keeps it that way. `task_signoff` on a task that is not delivered now says what to do instead, and the delivery guidance in `task-lifecycle`, `interaction-style` and `crew:join-crew` asks for acceptance only once the task is at `done`; a join is delivered only after `crew.js status` reports `session.ready`.
