### Exact file identity, and a ready status that never sits next to an older detail

Desk now compares file identities as exact BigInts. On Windows a file id can exceed 2^53 (one was measured at 10414574139658612), and above that a JavaScript Number cannot tell two neighboring ids apart, so two different files could be judged the same file. The checks that guard against a swapped or replaced file now read stats with `{ bigint: true }`: the readiness change journal's file checks, the worktree resource claim, the workspace tidy's task-card read, the outbox's marker directory, marker leaves and orphaned-secret cleanup, the marker reader, the flush lock's stale-lock check and the browser context broker's lock fingerprint. The shared helper is [`util/file-identity.js`](mcp/src/util/file-identity.js), and it refuses a stat that was not read with `{ bigint: true }` instead of comparing lossy Numbers. The worktree closeout receipt in `desk-closeout.json` still accepts `identity.dev` and `identity.ino` as Numbers; it now also accepts decimal strings, which stay exact above 2^53. Nothing Desk writes changes shape.

`desk_status` now stamps a runtime detail it computed itself with the admission state it saw when the call started. Before, a call that started while Desk was still admitting, computed the detail while the readiness controller was converging, and finished after admission reached ready could report `state: "ready"` next to a `LEXICAL_CONVERGING` controller with nothing marking the detail as old. The next call reports the newer state. A detail served from an earlier computation is unchanged: it still says `cached` and carries `status_detail_from`.
