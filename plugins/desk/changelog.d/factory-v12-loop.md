The improvement loop now keeps a triage recommendation on open improvement cards. Its worker runs route, triage, evaluate, mirror, reconcile, verify, measure, and starts at most one agent run per generation: a triage run or one evaluation, never both. See [The triage step](docs/factory-local-capture.md#the-triage-step).

The new [triage step](mcp/src/factory/triage-step.js) first refreshes annotations with no agent: a review whose card, claim, rulings, evidence or versions changed is marked stale and keeps its last valid review, and a removed card's annotation is withdrawn. It then starts one bounded run only when the shared launch ledger leaves a triage launch, the host can run the owned-catalog runner (macOS only; other hosts report `runner_unavailable` and raise no alarm), a card needs a review, this machine's runner qualification record loads and a whole 15-minute run still fits before the worker's deadline. Until a qualification record is installed at `triage/qualification/qualification.json` in the protected factory state, the step launches nothing.

A run's candidate is accepted card by card, only after the live basis is read again and found unchanged, and a card counts as reviewed only when its write is acknowledged. The full result stays in protected factory state; Git gets the closed safe review only. Refused, missing or unacknowledged rows leave the last valid review in place.

When triage takes the agent slot from an evaluation that was due, the worker leaves one evaluation continuation and starts the next worker once after it releases its lock. A continuation never bypasses the gap after a real evaluation failure. With no evaluation request waiting, the end of a turn now starts the worker when triage is due, at most once an hour and never for a runner this host cannot start.

`factory.js triage --desk <absolute desk root> [--person-prefix desks/<alias>]` runs the step once. `status.json` gains a `triage` record and the health record a `triage` section (result, runner codes, review counts); the capture record's loop slot is unchanged. `loop_alarm:step_stale:triage` is a new alarm code the card writer accepts, with no change to card fields, states or claim limits; cards carrying it are read by earlier Desk versions. A triage route is a recommendation: it never claims a card or authorizes work.
