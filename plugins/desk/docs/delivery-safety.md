# Delivery and shared source

This contract is for Desk runtime maintainers. **Remote delivery does not advance the shared checkout.** Private replay and the existing Desk text-conflict policy remain unchanged; delivery only observes whether the source ref already equals the delivered tip. Otherwise it returns `checkout: { state: "behind", reason: "source_follow_deferred" }`. It does not unlink an identical untracked path, rewrite the source index/files, move `HEAD` or attempt restoration. `current` means ref equality, not a clean working tree or ready binary consumers. [Implementation](../mcp/src/runtime/deliver.js), [real-Git regressions](../../../tests/desk/mcp/__tests__/runtime/delivery_residuals.test.js).

## One captured destination

Delivery captures the upstream ref, resolved fetch and push destinations, branch and effective Git/credential-route configuration before network effects. It uses captured destinations rather than resolving a mutable remote name again at push time. Native URL-scoped credential helpers and SSH configuration still apply; credentials are not copied or replaced, and no active account is switched. The fingerprint observes configuration and known Git, GitHub, GCM and Azure credential-selector environment variables, not a frozen copy of an external credential store. [Route capture](../mcp/src/runtime/deliver.js).

**An executable pre-push hook at Git's effective hook path, or a configured pre-push hook event, blocks delivery before network effects.** A literal-URL push changes the hook's native remote-name argument; a named-remote push can update the current remote-tracking alias despite a concurrent origin change. Neither bypassing the guard nor changing its policy is permitted. An empty `core.hooksPath` directory or non-executable file does not itself block delivery. Hooks are not deleted, disabled or reinterpreted. Existing LFS pre-push users therefore remain unsupported until both native arguments and tracking isolation are qualified; this is not general Desk LFS readiness. Private replay's existing isolated hook policy is unchanged. [Policy gate](../mcp/src/runtime/deliver.js), [real origin-conditional guard and inactive-policy controls](../../../tests/desk/mcp/__tests__/runtime/delivery_residuals.test.js).

The supported route has exactly one fetch URL and one push URL naming the same canonical destination. An explicit `pushurl` is accepted when it resolves to that same destination. Multiple or split destinations, URL rewrite rules, credential-bearing URLs and unqualified named-remote transport overrides are explicitly blocked. Desk does not strip required policy to make an ambiguous route work. [Route validation](../mcp/src/runtime/deliver.js), [policy and credential-origin fixtures](../../../tests/desk/mcp/__tests__/runtime/delivery_residuals.test.js).

Context is checked before effects, and a successful push requires readback from its captured destination. If context changes after the push, that destination may already have accepted the commit. The result retains an unconfirmed pinned observation without making another network call under the changed context. It does not mark the new current origin delivered, alter its tracking alias or reuse the old target's acknowledgement ledger. Unknown readback is not proof that nothing reached a remote. [Delivery and worker](../mcp/src/runtime/deliver.js), [bookkeeping](../mcp/src/runtime/sync-worker.js).

A failed push exit code does not prove rejection: receive-pack can update the branch before its successful response is lost. Ambiguous transport failures retain the candidate/ref/original-commit pin as `push_outcome_unverified` at any exit status, without acknowledging delivery or automatically replaying it. Only a complete all-rejected Git porcelain result without transport ambiguity is retried; unambiguous authentication denial and explicit initial DNS/connect refusal remain distinct. A later bounded fetch can establish that the candidate already arrived without pushing or duplicating it. [Native accepted-then-reset, authentication-denial and all-ref-rejection controls](../../../tests/desk/mcp/__tests__/runtime/delivery_residuals.test.js).

## Scoped evidence

Fetched and candidate objects use `refs/desk/delivery/<root-key>/upstream` and `candidate`; this operation does not rewrite a configured remote-tracking alias. A `deliverySnapshot` binds the observed tip/ref to its route fingerprint. Resolved-copy acknowledgements are used only with a matching snapshot. Legacy or malformed unscoped entries require destination reconciliation rather than silently authorizing replay suppression for a new origin. [Evidence handling](../mcp/src/runtime/sync-worker.js).

The existing 5,000-entry acknowledgement budget now refuses new delivery before fetching when the result could exceed capacity. It never silently drops older acknowledgements while source following stays deferred. A missing common history or a remote tip that no longer contains the previously acknowledged tip is `source_history_changed`, not permission to replay unrelated histories or reset local work. No migration map or rollback asset is inferred. [Capacity and ancestry gates](../mcp/src/runtime/sync-worker.js), [delivery](../mcp/src/runtime/deliver.js).

Tool, boot and compact-status text distinguish an unverified destination from commits known only locally, and name deferred source following separately. Healthy private delivery and the existing conflict policy are preserved. This boundary does not complete tracked-history source recovery, qualify every concurrent metadata writer or establish LFS materialization/readiness. The fixtures cover native local and authenticated loopback HTTP routes; installed consumers, other authentication providers and platform CI require their own qualification. [Consumers](../mcp/src/runtime/boot-text.js), [status](../mcp/src/runtime/status-compact.js), [fixtures](../../../tests/desk/mcp/__tests__/runtime/delivery_residuals.test.js).
