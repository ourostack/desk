# Protected checkouts

Desk's [Claude `PreToolUse`](../hooks/hooks.json) and [Copilot `preToolUse`](../hooks/copilot-hooks.json) plugin hooks guard shell calls for every agent using the plugin, without a parent-agent or subagent exemption. Claude registers both native `Bash` and `PowerShell`; tool names select the corresponding grammar. The hooks leave ordinary host permission checks in place and install no Git hooks, shell aliases or terminal configuration. A human invoking Git directly is unaffected. The [executable command table](../../../tests/desk/mcp/__tests__/runtime/protected_checkout.test.js) and [review regressions](../../../tests/desk/mcp/__tests__/runtime/protected_checkout_review.test.js) exercise registered commands with parent and child payloads, compare HEAD and the reflog, and then invoke Git directly.

## Threat model

The guard stops well-intentioned agents from accidentally moving a shared checkout off its state branch or discarding other sessions' work. It is not a sandbox against a determined adversary. It denies every spelling an agent would plausibly produce, fails closed only where a value it cannot compute decides a checked Git operation, and always answers within the hosts' 10 s hook deadline: all Bash and PowerShell inspection of one command, with its Git reads, shares one 7 s budget and one 20,000-step budget and is denied, with a reason that names the budget, when either runs out; inspection yields to the event loop as it goes, and the [hook entry point](../hooks/protected-checkout.cjs) answers "deny" at 9 s whatever happens. Allowed and read-only commands make no inspection reads.

## Policy

A protected checkout is shared by sessions. The [guard](../mcp/src/runtime/protected-checkout.js) keeps its HEAD on its state branch and keeps other sessions' work in place; it does not block the desk's normal write protocol of committing and pushing the state branch. The [policy](../mcp/src/runtime/git-guard-policy.js) applies only when the **target checkout's saved local configuration** has `desk.protected=true`; every other checkout is unaffected.

The rule: the guard denies only what moves a protected checkout's HEAD off its state branch, rewrites pushed history, or discards other sessions' work. Everything else is allowed.

| Allowed in a protected checkout | Denied in a protected checkout |
| --- | --- |
| Read-only Git: `status`, `log`, `diff`, `show`, `fetch`, `rev-parse`, `ls-files`, branch listing, `remote -v`, `config --get`, `stash list`/`show`, `bisect log`, and plumbing such as `merge-tree`, `commit-tree` and `hash-object`; `update-ref` of any ref other than `HEAD`, the current branch and the state branch; `symbolic-ref HEAD <current or state branch>` | `checkout` or `switch` to another branch, a tag or a detached commit, including `-b`, `-B`, `--orphan` and `--detach`; `bisect start` and other bisect steps; `symbolic-ref HEAD <another ref>` and `symbolic-ref -d HEAD`; `update-ref` of `HEAD` (with or without `--no-deref`), the current branch or the state branch |
| `add`, `rm`, `mv`, `commit`, and `commit --amend` of a commit that no remote-tracking branch contains; `reset --soft HEAD` | `reset --hard`, `--merge` or `--keep`, and a `reset <commit>` that moves HEAD; `checkout -f` and `switch -f` or `--discard-changes` |
| Unstaging or discarding **named** paths: `reset [<commit>] [--] <paths>`, `restore --staged <paths>`, `restore [--source <commit>] [--staged] [--worktree] <paths>`, `checkout [<commit>] -- <paths>`, `checkout-index -f <paths>`, including globs that name files (`'*.txt'`, `'sub/*'`) and absolute paths inside the checkout | The same commands for any pathspec that covers the checkout root: no path, `.` or `..` spelled any way (`./.`, `.//`, `sub/..`), `:/`, a pattern made only of wildcards (`*`, `**`, `*/`), a `:(…)` magic pathspec, exclude magic (`':!x'`, `':^x'`, `':(exclude)x'`), the checkout root or an ancestor as an absolute path (`"$PWD"`, `"$(pwd)"`, `"$(git rev-parse --show-toplevel)"`), `--pathspec-from-file`, and `checkout-index -f` with `-a` or `--stdin`; `read-tree -u` with `--reset` or `-m` (a whole-index `reset` or `restore --staged .` unstages everything) |
| `push` of any branch or tag without force, including `-u`; deleting a branch other than the state branch on the remote (`--delete topic`, `:topic`) | `push --force`, `--force-with-lease`, `--force-if-includes`, `--mirror`, `--prune`, `+` refspecs, and deleting the state branch on the remote; `commit --amend` of a pushed commit |
| `pull`, `pull --rebase` and `pull --ff-only` from the state branch's own upstream (`<remote>/<state branch>`), and any merge-mode pull | `pull --rebase` off the state branch, from another repository (a URL, a path, `.`) or another branch |
| `fetch`, into remote-tracking refs | `fetch --update-head-ok`, and fetch refspecs whose destination is the current or state branch |
| `config` reads; writes outside the sections below; writes to another file (`--file`, `-f`, `--blob`); `branch -u <remote>/<state branch>` | `config` writes to the checkout's own `desk`, `alias`, `include`, `includeIf`, `remote`, `push`, `branch`, `rebase`, `pull`, `merge`, `fetch` and `url` sections; `branch -u` of the current or state branch to anything else |
| `rebase` and `rebase <its upstream>` on the state branch, and `rebase --continue`, `--abort` and `--skip`; every `merge` | `rebase` onto anything else, `--onto`, `--root`, `--exec`, `--quit`, a second operand naming another branch |
| `--autostash`, or a `-c rebase.autoStash=…`/`merge.autoStash=…` override, on any allowed pull, rebase or merge (it re-applies the stash within the same command) | `clean`; `stash` and every `stash` subcommand except `list` and `show` |
| `worktree add`, `worktree list`, `worktree prune`; `checkout`/`switch` to the current or state branch | `branch -f`, `-d`/`-D`, `-m`/`-M` or `-C` of the current or state branch; `worktree add -B` of either; `worktree remove --force` of a protected checkout |

Separately from any protected checkout, the same hook denies a `git clone`, `git fetch` or `gh repo clone` of a repository that a task card in the desk marks as living on another machine (the card's next step or blocker says "my other laptop", "only on the other laptop", "not on this machine" and so on, and the card names that repository). The denial leads with "Record <branch> as pushed with task_update if the operator said so; else ask them to push it.", then says not to clone or fetch to look for it, and that an operator message in the conversation that already says it is pushed counts, so the agent records it and retries without asking again. It reads the desk's cards only for a command that names `clone` or `fetch` together with a repository URL, and a clone of any other repository passes.

Push, pull, rebase, fetch and merge trust Git's configuration, so they are denied under a `-c`, `--config-env`, `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n` or `GIT_CONFIG_PARAMETERS` override of `remote.*.mirror`/`push`/`fetch`/`url`/`pushurl`/`tagopt`, `push.*`, `branch.*.merge`/`remote`/`rebase`/`pushRemote`, `rebase.*`, `pull.*`, `merge.*` (except `rebase.autoStash` and `merge.autoStash`, which only select `--autostash`), `fetch.*` or `url.*.insteadOf`. A plain push also reads the saved `remote.<name>.mirror`, `remote.<name>.push` and `push.default`: a mirror, a forced or other-branch configured refspec, or `matching` is denied. Aliases come from saved configuration and from every override source, case-insensitively, and are expanded with the issuing command's options (`-C`, `--git-dir`, `--work-tree`, `-c`); a shell alias inherits the location and `-c` settings Git exports to it.

The state branch is `desk.stateBranch` from the marker file, written when the host names one (`--state-branch` or `desk.state_branch`); when none is recorded, the current branch is the state branch. `-h` and `--help` are always allowed. The [option parser](../mcp/src/runtime/git-guard-options.js) follows Git 2.54's full option lists (hidden options included): unambiguous abbreviations such as `--sour`, `--forc` for `branch` and `--autost`, negations such as `--no-source`, and option values such as `branch --format -f`. When one mode option overrides another (`reset --hard --mixed`, `merge --ff-only --no-ff`), the last one wins, as in Git. Force-removal checks the checkout being removed with its own Git identity, without the issuing command's location overrides.

Every denial opens with what to do instead (the first sentence is at most 120 characters, because hosts show only about the first line), then the reason, then the checkout last. Only a real HEAD move, rewind or discard names a worktree; ordinary desk writes are never sent to one. For example:

```text
Use your own worktree: git worktree add --detach "$HOME/<new directory>" <ref>. This would move HEAD off the checkout's branch. Desk protects this checkout: /path/to/desk
Commit only your own paths with git commit <paths>, and pull with git pull --rebase --autostash. git stash takes other sessions' uncommitted work out of the shared checkout. Desk protects this checkout: /path/to/desk
Restore only your own files by name: git restore <paths>. This would discard uncommitted changes in every file, including other sessions' work. Desk protects this checkout: /path/to/desk
```

In PowerShell, a denial that Desk can fix mechanically starts with the fixed command, for example `Run this instead: $__deskGitOut = git status; $__deskGitOut | Format-Table`. Desk offers it only after the guard itself allows it, and only when it is certain to mean the same thing: it quotes an argument such as `HEAD..@{u}` that PowerShell would split, and it splits a pipe into a known PowerShell command (never a native program such as `tar`, which reads raw bytes) when the Git command has no redirect.

Credentials are replaced with `<redacted>` in every denial and in the hook's own error message: a URL's user information (`https://user:token@host`), the user part of a `url.<user>@host:` key or of an scp-style address whose user looks like a token (`ghp_…@github.com:`, anything with a `:` or longer than 23 characters; `git@github.com:` stays readable), `Authorization` header values, and bare tokens with a known prefix (`ghp_`, `github_pat_`, `glpat-`, `sk-`, `xoxb-`). A `url.<base>.insteadOf` override whose base only adds credentials to the same URL (`url.https://x-access-token:<token>@github.com/.insteadOf=https://github.com/`) is not treated as an override, because the command reaches the same remote.

Use the task's approved source ref and an owned worktree. The [Desk-to-Superpowers adapter](../skills/using-superpowers-with-desk/SKILL.md) passes this rule into both implementer and reviewer briefs:

> verify or validate in your own worktree; never in a checkout your task does not own

## Bound roots and local configuration

[Desk admission](../mcp/src/runtime/desk-session.js) marks a resolved root before activation can fail, but only when the root is a real desk: it has the desk layout (`_meta/` plus `_archive/` or `desks/`) or a saved desk binding names it. A root bound any other way (`$DESK`, `--root` or a host root pointed at a code checkout) is served but never marked, because the marker would make the guard refuse ordinary work there ([regression](../../../tests/desk/mcp/__tests__/runtime/admission_marks_only_desks.test.js)). This applies to the common admission path used by both launchers, including explicit roots supplied by overlays; no host-profile edit is needed. A non-Git root is left alone. A failed configuration write is an admission error and is retried by the existing admission machinery rather than reported as protected.

The [marker writer](../mcp/src/runtime/protected-checkout.js) writes `desk.protected=true` to `<actual-git-dir>/desk-protected.config` and includes that file from local Git configuration under an exact `includeIf.gitdir:<actual-git-dir>.path` condition. This avoids both shared `.git/config` inheritance and Git's copying of `config.worktree` into new worktrees. It does not enable `extensions.worktreeConfig` or migrate repository settings. Paths are taken from Git, with pattern metacharacters escaped. [Regression coverage](../../../tests/desk/mcp/__tests__/runtime/protected_checkout.test.js) proves that a new worktree is usable until it is itself bound. When the host names a state branch, admission records it as `desk.stateBranch` in the same file; binding without one removes it.

An operator may also opt a repository and its linked worktrees into the guard directly:

```sh
git config --local desk.protected true
```

That explicit shared setting applies to all its worktrees; prefer Desk's checkout-specific marker when only the bound checkout should be protected. The guard ignores global and command-scope policy values, so `git -c desk.protected=false ...` cannot override the saved marker. It also honors worktree-scope configuration where that Git feature is already enabled. See [Git's configuration scopes and conditional includes](https://git-scm.com/docs/git-config).

## Shell boundary

The [Bash inspector](../mcp/src/runtime/shell-commands.js) tokenizes commands without executing them. It follows quoted and escaped words, ANSI-C `$'...'` literals, unquoted variable field splitting, home-directory expansion, `cd`, repeated `git -C`, Git directory options and environment assignments, command lists, `&&`/`||`, pipelines, background commands, groups, conditionals, `case`, literal loops and functions, shell wrappers and positional arguments, Git aliases, substitutions and here-documents. All leading assignment words remain scalar, including later words such as `A=1 P=$X`; ordinary command arguments still expand in the preceding shell environment. Logical and physical directory state are separate: [native physical traversal](../mcp/src/runtime/shell-paths.js) follows symlinks before `..`, while default logical `cd` uses its logical path. `CDPATH` is modeled. Literal quoted text and quoted here-document bodies are not treated as commands; unknown external exit statuses retain both possible conditional paths. It also reads brace expansion (`{a,b}`, `{1..3}`, nested and stepped forms, expanded as text), process substitution (`<(…)`, `>(…)`), here-documents inside `$( )` whose bodies hold quotes or parentheses, a newline after `&&`, `||` or `|`, and `case` arms inside groups. `set -e` (and `-o errexit`) is modeled: a failed command that is not tested by `if`, `while`, `!`, `&&` or `||` ends the script, so `set -e; cd /missing; git …` never reaches Git. Directories the command creates (`mkdir`, `git worktree add`) can be entered later in the same command, and `mkdir -p` and `rm -f` always succeed. Valid non-Git `case` expressions remain non-applicable, including multiline and empty forms. An unmatched or empty case succeeds independently of the preceding command's status. [Tests](../../../tests/desk/mcp/__tests__/runtime/protected_checkout_review.test.js) compare both symlink directions and mutation/read-only controls against real Bash and Git.

The [PowerShell inspector](../mcp/src/runtime/powershell-commands.js) runs each Git call through the same policy as Bash, wherever it appears. A PowerShell command that names `git` as a word (case-insensitive, quotes and backticks ignored, including `git.exe` and paths ending in `git` or `git.exe`) is read statement by statement, joined by `;`, new lines, `&&` or `||`. Git inside a `( )`, `@( )` or `$( )` group (also inside a double-quoted string), a `{ }` script block, a control statement (`if`, `foreach`, `while`, `switch`, `try`), a function or filter body at each call, `Invoke-Command { }`, `& git`, `& 'git'`, a call of a variable whose known value is Git (`$g = 'git'; & $g stash`), and a literal `Invoke-Expression`, `[scriptblock]::Create` or shell script runs as a statement of its own (replay ruling, 2026-09-27). A statement is judged by the Git it runs, so `$top = git rev-parse --show-toplevel; Set-Location $top; git status` and `if (git status --porcelain) { … }` pass, while `& git checkout topic`, `try { git stash } …` and `function Go { git checkout topic }; Go` are denied in a protected checkout.

A statement that names Git in its own text (outside its groups, script blocks and the quoted scripts it evaluates) must be one of these forms:

| Allowed form | Example |
| --- | --- |
| `git <arguments>` or `& git <arguments>` | `git push origin main`, `git log -1 > $null` |
| `$name = git <arguments>`, with a plain `$name` | `$s = git status --porcelain` |
| `git <arguments> \| <cmdlet>`, where each cmdlet is `Out-String`, `Select-String`, `Select-Object`, `Where-Object`, `ForEach-Object`, `Measure-Object`, `Sort-Object`, `Out-Null` or `Write-Output` (or their aliases) and names no Git | `git status --porcelain \| ForEach-Object { $_.Substring(3) }` |

Every argument and redirect target must be literal text, a plain variable (`$name`, `${name}`, `$env:NAME`, also inside a double-quoted string), or a `( )` or `@( )` group that stands for one value. A group's value is Git's answer when it is one plain `git rev-parse --show-toplevel`, `git branch --show-current` or `git rev-parse --abbrev-ref HEAD`, so `git push origin (git branch --show-current)` and `Push-Location (git rev-parse --show-toplevel)` pass; any other group is one unknown value. An unknown value takes its most dangerous reading: in a protected checkout it may hold any options or several arguments, so it is denied where Git would read it as an operand or option name (`git commit $x`, `git switch (Get-Content b.txt)`), and a `git worktree` command with one could remove any worktree, except `git worktree add`, which creates a new checkout. It is allowed as an option's value (`git commit -m $msg`) or a path after `--`. Anything else that names Git in a statement's own text is denied with a request to rewrite it as separate plain `git` commands: member access on a group (`(…).Name`, `(…)[0]`), splatting, `.`, `Start-Process`, `git` as a pipeline's later element or piped to other commands, a quoted token followed by more text (`'main'--force` is two arguments), and `--%`. Code Desk cannot read passes unless its readable text names Git or runs code: `iex $script`, `[scriptblock]::Create($x)`, `. $script`, `Start-Process $x`, `Get-Content s.ps1 | pwsh` and `pwsh -EncodedCommand …`. Denials in both shells name `git worktree add --detach "$HOME/<new directory>" <ref>` as the own-worktree form, because it runs as written in Bash and PowerShell.

Statements without Git are walked for what they do to the location, variables and environment those Git calls use: `sl`/`cd`/`Set-Location`/`Push-Location` with `-Path`/`-LiteralPath`, `Pop-Location`, assignments of literals and plain variables, `$env:` assignments, and nested shells. One state is kept. A `{ }` script block, a control statement, a background job, or a statement after `&&`/`||` whose status is unknown may or may not run, so every variable, environment value or location it could change becomes unknown. `( )`, `@( )`, `$( )`, `Invoke-Expression` and `[scriptblock]::Create` of a literal run in the caller's scope, and a string or here-string piped into a shell is that shell's script. An unmodeled variable setter (`Set-Variable`, `-OutVariable` and the like, `[ref]`, `variable:`) makes every variable unknown, and an unmodeled environment setter (`Set-Item env:…`, `SetEnvironmentVariable`) makes Git's location unknown. PowerShell passes no argument for `$null`; any other variable the command does not set may come from the session, so it is unknown. The [round 4 regressions](../../../tests/desk/mcp/__tests__/runtime/protected_checkout_allowlist.test.js) run the denied forms against clean-profile PowerShell when installed.

Inspection itself has a [separate trust boundary](../mcp/src/runtime/git-inspection.js). It resolves Git from standard system installation locations independently of candidate input, executes that absolute path and uses the captured host environment rather than candidate `PATH`, `HOME`, loader settings or `GIT_EXEC_PATH`. Only modeled Git location variables are admitted to the read-only inspection subprocess. An executable sentinel regression proves that proposed `PATH=... git ...` and `PATH=... /absolute/git ...` commands do not execute the candidate-selected program during inspection.

This is a guard for shell-visible Git operations, **not a sandbox against an agent deliberately rewriting its own policy or executing arbitrary code**. It does not interpret Python, JavaScript, sourced script contents, executable files or remote shell sessions,. Of Git plumbing it reads only the four commands that move HEAD or discard work (`symbolic-ref`, `update-ref`, `read-tree` and `checkout-index`); `update-ref --stdin` reads its refs from standard input and is allowed. Literal `pwd`, `echo` and `printf '%s'` substitutions resolve Bash values without executing the command; `mktemp` resolves to a new directory under its parent (`-p`, `--tmpdir`, a template's directory, the current directory for a bare template, or `TMPDIR`), so `wt=$(mktemp -d) && git worktree add --detach "$wt" HEAD && cd "$wt" && git switch -c fix` passes. PowerShell answers literal `Get-Location`/`pwd` subexpressions and `$pwd` with the current location. `pushd DIR` changes directory like `cd`; `popd` and PowerShell's `Pop-Location` leave the directory unknown.

Git itself can run code the guard does not see: hooks (`core.hooksPath`, `.git/hooks`), `rebase -i` with `GIT_SEQUENCE_EDITOR` or `sequence.editor`, filters and credential helpers. These are outside the boundary, like sourced script contents; only `git config` writes to the sections above are denied. `commit --amend` counts a commit as pushed only when a remote-tracking ref contains it, so a push to a URL or a tag name, which leaves no remote-tracking ref, is not seen.

A shell reads its script from stdin when it has no script operand, has `-s` (`bash -s -- x <<'EOF'`), or is PowerShell with `-Command -`, `-File -` or no script at all. A here-document belongs to the command whose `<<` opened it, even when that command is followed by `|`, `&&`, `||` or `;` on the same line. Inline code Desk can read is inspected like any other command: a `-c` script, a here-document, a here-string, `cat` of either, or a literal `echo` (including `-e`/`-n`) or `printf` (`%s`, `%b` and `%%` formats, with `\n` and `\t` escapes) piped into `sh`, `bash`, `zsh`, `dash`, `ksh`, `pwsh` or `powershell`. Code Desk cannot read is allowed (ruling, 2026-09-27): a script file (`sh ./x.sh`, `pwsh -File x.ps1`), `source`/`.` of a file, `cat script | bash`, `curl … | sh`, `eval "$(…)"`, `bash -c "$(…)"` and `-EncodedCommand`. PowerShell's `-Command` runs all its later arguments joined, and `-WorkingDirectory` moves the script.

### Unknown values fail closed only on a path to Git

Other computed output is **unknown**. The inspector carries an unknown value forward and fails closed only where it decides a Git operation that a rule checks ([rule](../mcp/src/runtime/guard-unknowns.js), also documented in the [hook header](../hooks/protected-checkout.cjs)):

- an unknown directory, Git subcommand, revision, branch or refspec for a Git operation the policy must check, such as `cd "$(pick)" && git checkout main`;
- `git worktree remove --force` of an unknown worktree, when any worktree of that repository is protected.

An unknown program is judged as Git only when its arguments read like Git (`-C`, `-c`, `--git-dir`, `--work-tree`, `--config-env`, or a first operand that is a checked subcommand), so `$(command -v git) checkout main` and `` `which git` stash `` are denied with the operation's own reason, while `g=$(which git); $g status` passes. A computed directory with a known name is that program: `"$(npm bin)/tsc" --build` passes. Operations that are safe in any checkout still pass when the target is unknown: `add`, `commit`, `pull --rebase` or `--ff-only` from the upstream, merges and non-force pushes. A directory that is not a Git repository, or holds a `.git` file that points nowhere, is not protected.

`git rev-parse --show-toplevel`, `git branch --show-current` and `git rev-parse --abbrev-ref HEAD` are read-only, so their substitutions are answered from the file system when no `GIT_DIR` or `GIT_WORK_TREE` is set: the top level is the nearest ancestor with a `.git` entry, and the branch is read from that checkout's `HEAD` (through a worktree's `.git` file). `cd "$(git rev-parse --show-toplevel)" && git pull` is judged in that checkout, and `git push origin "$(git branch --show-current)"` pushes the current branch. A tag that an earlier `git tag <name>` in the same checkout creates counts as a tag unless a local branch has that name: if that `git tag` is skipped or fails, Git cannot push a name nothing resolves. So `git tag v2 && git push origin v2` and `[ -z "$(git status --porcelain)" ] && git tag v2 && git push origin v2` pass, while `test … && git tag topic; git push origin topic` is judged as a push of the branch `topic`.

`cd "$(pick)" && git commit`, `echo "$(date)"`, `cd "$wt" && node x.js`, `"$(npm bin)/tsc"` and `jq . f.json | grep x` pass. Text the inspector cannot parse (or that exceeds its nesting limit) is judged from its words: it is denied only when it names a Git operation whose rule could deny it here (`git stash`, `git checkout <branch>`, `git reset --hard`), and even then allowed when it runs in a known checkout that is not protected; other unparseable text passes, including a plain `git status` or `git commit`. Running out of the step budget or the 7 s budget denies any command, with a reason that names the budget, and a Git inspection failure denies the command that needed it. Bash merges more than 16 reachable states into one whose differing directories and variables are unknown, and merges identical states after each loop iteration, so long scripts and loops stay within the budget. A loop that calls Git every iteration costs Git reads in proportion to its distinct targets, not its length: the guard's cache of already-decided Git calls is keyed on the call's target and Git's own environment (`GIT_DIR` and its siblings, `GIT_CONFIG_*` overrides), never a loop's own variables, so an identical, already-answered call reuses that answer instead of spending a fresh read. An unknown `GIT_CONFIG_*` environment value fails closed for checked operations. The checkout a Git call is judged in follows `GIT_WORK_TREE`, or the parent directory of a plain `.git` `GIT_DIR`, when the command line does not already say so with `-C`, `--git-dir` or `--work-tree`, so `GIT_DIR="$dir/.git" GIT_WORK_TREE="$dir" git reset --hard` is judged in `$dir` even from an unrelated or nonexistent working directory; a value the guard cannot compute (`GIT_DIR="$(pick)"`) is left for the read itself to reject, not resolved into that checkout early. Each inspection read gets what is left of that budget ([`readInspectionGit`](../mcp/src/runtime/git-inspection.js) defaults to 2 s for other callers and reports a timeout as `ETIMEDOUT`). Native host hook disablement and timeout behavior remain host-owned; see the [Claude hook reference](https://code.claude.com/docs/en/hooks) and [Copilot hook reference](https://docs.github.com/en/copilot/reference/hooks-reference).
