# desk plugin — changelog

## 3.2.0-alpha.112 — 2026-09-28

The one-time desk tidy no longer depends on the agent choosing to follow a skill step. A normal session skipped it on a desk where it was due, because running it was left to the session-start skill's migration step. Both startup hooks now run the Detect block of each of Desk's own migrations themselves ([pending-migrations.js](mcp/src/runtime/pending-migrations.js)) and add one `Desk migrations:` line to the startup context when one is pending. For the tidy, the line gives the exact command that prints the work, `node <desk plugin>/mcp/scripts/migrations.js run 02-tidy-desk --tools-root <root.path> --tools-person <person>`, and that command prints the tidy's full steps however long the desk's report is. A safe migration that needs no restart and no agent work runs in the hook itself; a migration that needs a restart is named with its command. With nothing pending, the hooks add nothing. [session-start](skills/session-start/SKILL.md) and [session-start-migrations](skills/session-start-migrations/SKILL.md) now point at that line.

Only one session tidies a desk at a time, and a tidy that cannot finish stops asking. The tidy's report takes a claim in the desk repository's Git folder, and while another session's claim is fresh (30 minutes) the startup line says the tidy is on hold instead of telling a second session to start it. Two sessions can never both hold the claim, even when several take over an abandoned one at the same moment: each claim is a new numbered file that appears fully written or not at all, and a session that is overtaken withdraws. When the tidy stops (no person resolves on a crew desk, the Desk tools and the tidy disagree about the desk, Git is mid-merge, or the agent defers it with the new `tidy-status.js --defer <reason>` because it cannot finish), it is held with its reason until that state changes or 7 days pass, and session start shows the reason in one line. On a crew desk, a cold GitHub identity lookup now finishes in the background instead of holding up session start. The tidy's steps also stage only the paths the tidy changed, write the record only after its checks pass, and commit only those paths ([02-tidy-desk](migrations/02-tidy-desk.md), [tidy.js](mcp/src/desk/tidy.js)).

One large task card no longer stops workspace-tidy for the whole desk. Cards were read whole and any card over 64 KiB aborted the inventory, so on a desk with a 256 KB card the boot line always read `workspace-tidy deferred (0 listed); unsafe or oversized file`. Each card is now read by its front matter alone, with one bounded read of its first 64 KiB, and removal rechecks that same front matter. A card that still cannot be used (its front matter does not close within 64 KiB, it has no readable status, it is not a regular file, or it cannot be opened) is skipped by name, for example `1 task card skipped: <path> (no readable status)`, and every other card still counts ([workspace-tidy](docs/workspace-tidy.md)). The workspace-tidy boot line also no longer repeats an issue that the last repair's line already names.

A desk counts as a crew workspace only when its `_meta/desks.md` roster names at least one person. An empty file, a heading, a prose pointer to a hub registry or an empty roster table now means a personal desk, so the tidy runs at the desk root instead of stopping on "no person resolved" ([crew-roster.js](mcp/src/desk/crew-roster.js)). A `desks/` folder still makes the desk a crew workspace.

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.110 — 2026-09-28

`desk_status` keeps its index and readiness detail on a busy machine instead of answering "unavailable". Only one [runtime status](mcp/src/runtime/desk-session.js) computation runs at a time. A call that arrives while one is running waits its own short budget for that answer. A detail that arrives late is kept, and the next call serves it marked cached, with its start time in the new `status_detail_from` field and its age in `status_detail`. A computation still running after 10 seconds is treated as stuck: the next call starts a fresh one, and the stuck one can never replace newer detail when it finishes. Before this change, each call threw away any computation that ran past about a tenth of a second and started another, so on a slow machine every call could answer "unavailable". The lexical readiness smoke test, which failed on busy CI runners for the same reason, now waits for a detail computed after the event it checks.

Ships `desk-mcp@1.4.0-alpha.6`.

**The manual work-measurement ledger is retired; the factory accounts for finished jobs instead.** The `desk_work_ledger` tool and its published input schema, the `work-measurement-ledger` skill, the batch work-profile script and their measurement code are removed, so Desk now exposes 17 tools and no tool, skill or instruction asks anyone to record work by hand. A call to `desk_work_ledger` from an old client is refused as an unknown tool and touches nothing.

**The frozen offline benchmark cannot run natively until a new dataset version drops the ledger case.** The `v2-alpha-v1` dataset still requires the `private.ledger` callback, which no Desk tool supplies now, so a native run is refused with `NATIVE_CALLBACK_UNMAPPED` ([offline evals](../../evals/offline/README.md)). The frozen dataset is not edited; [#56](https://github.com/ourostack/desk/issues/56) tracks the new version.

## 3.2.0-alpha.105 — 2026-09-28

Friction about the shared system now becomes a kaizen candidate, and the curator files candidates as kaizen cards after its signoff step. `friction_add` takes `about`: `setup` (the default) stays on the desk as before, and `system` records a candidate on the desk with a `title`, the `plugin` (default `desk`), a `friction_class`, and the `signal` and `evidence_jobs` when known; nothing leaves the machine. The `friction-management` skill says which friction is about the system, `lesson-capture` proposes candidates from the evaluator's waste without filing them, and `curator` becomes the kaizen worker: it handles open andon issues first, files candidates after signoff, ships each card's countermeasure, fills in `version` when the release lands, closes confirmed cards and reverts or re-plans not-confirmed ones.

## 3.2.0-alpha.104 — 2026-09-28

Every Desk MCP tool now advertises a real JSON input schema ([tool schemas](mcp/src/tool-schemas.js)), with its properties, required fields and `additionalProperties: false`. Before, 17 of the 18 tools were listed as `{ properties: {}, additionalProperties: true }`, so Claude Code had no shape to build arguments from and sent `task_update`'s `frontmatter` as a JSON string, which the tool spread into the card as one key per character (`"0": "{"`, `"1": "\""`, ...). A test now fails if any tool is registered without declared properties, with a required field it does not declare, or with an object or list field that has no type. Object and list fields are typed: `repos` entries carry `name`, `local_path` and `mode`, and the work ledger's `operator_go`, `task_ref`, `carry_forward` and path lists have their shapes. Only the degraded server that runs when no compatible Node is found still lists tools with an open schema, on purpose, because every call there answers with the reason and the fix.

`task_create` now accepts and keeps `initiated_by` (`operator` or `agent`) and `origin_note`, which `desk:start-task` asks for; before, both were silently dropped. `desk:start-task` also says that `created`, `updated` and `schema_version` are set by the tool.

`task_update`, `track_update` and `desk_search` also check their object arguments themselves ([object input](mcp/src/util/object-input.js)): a plain object is used as is, a string that holds a JSON object is parsed, and anything else is refused with a clear error before the card is read or written, so a corrupted card can no longer be written. A bad `desk_search` filter says that nothing was searched and shows a filter example.

Session start no longer repeats a folder name that carries a secret's value.

- The `Desk startup:` and `Desk boot:` lines both hooks inject redact to `<redacted segment>` each path segment, branch name or word that looks like a password value, a 16+ character secret run, a known token prefix or an IPv4 address ([redaction](mcp/src/util/redact.js)). A path segment is judged whole, spaces included, so a folder named `set pw hunter2` is caught, and a sentence's closing full stop stays outside the marker. The machine's own home and temporary folders are exempt, and the boot line is withheld rather than shown unredacted if the redaction cannot load.
- `desk_status` now serves the active-task listing as `active_tasks` ([listing](mcp/src/desk/active-tasks.js)): non-terminal tasks by track, with track, task and desk names, titles and repository paths redacted the same way, a count of what it hid, and each task's repositories. `desk:session-start` and `desk:status` build their status blocks from it instead of globbing task cards, so hosts that gate shell commands do not prompt for it, and they never recover or quote a redacted name.
- The session-start desk sync is now `git pull --rebase --quiet`: without `--quiet` the pull printed a diffstat and a `create mode` line naming every folder another machine had created.
- Every task and track has a stable handle (`task-` or `track-` and ten hex characters, [handles](mcp/src/desk/handles.js)) in the listing, in `desk_doctor`'s organization findings and in the tidy report. `task_move` takes `handle` in place of `track` and `slug`, and `track_rename` takes `handle` in place of `track`, so a redacted folder gets an outcome name without anyone reading the old one; the tidy renames by handle instead of listing the folder's parent. A handle is a keyed hash of the folder's path; the key lives in Desk's state folder on this machine, not in the desk. `task_move` and `track_rename` also redact credential-like names in their results and errors.

This closes the live finding where a session-start status quoted the user and password in two task folder names. A topic word such as `token` or `password` alone is not redacted, per the name rule. Out of scope: `desk_status` still reports the desk root unredacted in `root`, because the agent needs the real path to work in the desk.

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.102 — 2026-09-27

Milestone 3a, task A3b (P0 correction to the protected-checkout guard, ourostack/desk#24): the guard now denies only a Git operation that moves a protected checkout's HEAD off its state branch, rewrites pushed history, or discards other sessions' work, and everything else passes. In a protected checkout, `add`, `rm`, `mv`, `commit`, amending an unpushed commit, every merge, `pull` and `rebase` onto the state branch's own upstream (with or without `--autostash`, `-c rebase.autoStash` or `-c merge.autoStash`), non-force pushes of any branch or tag, deleting another branch on the remote, unstaging or restoring named paths (`git restore [--source <commit>] <paths>`, `git checkout -- <paths>`, `git reset -- <paths>`, including globs such as `'*.txt'` and absolute paths inside the checkout), config writes to another file, `worktree add`, `worktree prune`, read-only Git, and plumbing that leaves HEAD and the tree alone (`update-ref` of other refs included) pass. The [policy](mcp/src/runtime/git-guard-policy.js) still denies leaving the state branch, `reset --hard`/`--merge`/`--keep` and HEAD-moving resets, unstaging or restoring any pathspec that covers the checkout root (no path, `.` or `..` spelled any way, `:/`, wildcard-only patterns such as `*` and `*/`, magic and exclude pathspecs such as `':!x'`, and the root as an absolute path such as `"$PWD"`, `"$(pwd)"` or `"$(git rev-parse --show-toplevel)"`), plumbing that moves HEAD or discards work (`symbolic-ref HEAD <another ref>`, `update-ref` of `HEAD` or the current or state branch, `read-tree -u` with `--reset` or `-m`, `checkout-index -f` with `-a`, `--stdin` or root-covering paths), `clean`, `stash` (including `push`, `pop` and `drop`), forced, mirrored and pruning pushes and deleting the state branch on the remote, rebases onto anything but the upstream, force-moving or deleting the current or state branch, amending a pushed commit and forced removal of a protected worktree. Admission records the host's state branch beside the marker (`desk.stateBranch`), and it now marks a root only when it is a real desk (the desk layout, or a saved desk binding): three tests had bound `$DESK` to the checkout running the suite, which is how some code worktrees were marked protected.

Every denial names the concrete alternative, and credentials are redacted from it and from the hook's own error message: URL user information (`https://user:token@host`), token-shaped users in `url.<user>@host:` keys and scp-style addresses, `Authorization` values and tokens with a known prefix. Only a real HEAD move, rewind or discard names the worktree command, `git worktree add --detach "$HOME/<new directory>" <ref>`, which runs as written in Bash and PowerShell; ordinary desk writes are never sent to a worktree. When the target checkout is unknown or computed (`cd "$x" && git …`), operations that are safe in any checkout still pass. Code Desk cannot read (a script file, `source`, `curl … | bash`, `eval "$(…)"`) passes; inline code it can read (`bash -c "…"`, here-documents) is inspected like any other command. Text Desk cannot parse is denied only when it names a Git operation whose rule could deny it there.

The Bash inspector now reads brace expansion, process substitution, here-documents inside `$( )`, a newline after `&&`, `||` or `|`, `case` arms in groups, `set -e`, and directories the command itself creates. PowerShell Git inside groups, subexpressions, script blocks, control statements, functions and `& git` now runs as its own statement under the same rules, a group's value is its static answer or one unknown value, and code Desk cannot read passes unless its readable text names Git; a statement that names Git itself must still be a plain form, and that allowlist never fires in an unprotected checkout. One step budget (20,000 steps) and one 7 s time budget bound all inspection, and the hook answers at 9 s. Replayed against 22,880 recorded agent commands, the guard denies 6 in a protected desk (5 real HEAD moves, stashes or state-branch force-moves, and 1 whose computed directory no longer exists) and none in an ordinary repository; all 164 expected-allow rows from earlier reviews pass. The rule, threat model and command table are in the [hook header](hooks/protected-checkout.cjs) and [Protected checkouts](docs/protected-checkouts.md).

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.100 — 2026-09-27

A factory store's build now checks kaizen cards and pulls the andon cord ([factory-local-capture.md](docs/factory-local-capture.md)), and both claim a change only when the data can support it. `factory.js kaizen-check` reads each open issue labeled `kaizen`, parses its `yaml` card, and once the card names the version that first carries its countermeasure, compares the card's measure between finished jobs before and after that version. Jobs that share a session count as one independent group, and the 95% interval comes from 10,000 bootstrap resamples of those groups seeded with the card's number ([compare.js](mcp/src/factory/pipeline/compare.js)). A side needs at least 6 groups, the fewest for which a distribution-free 95% interval for a median can exist; the code derives that number from the confidence level. The card gets `confirmed` or `not-confirmed` only when the interval lies wholly on one side of zero, and its one comment otherwise says either "not enough independent jobs yet" or "no clear change so far". A card naming a job class the store cannot fill yet gets `job_class_not_published`, and a card whose calls fail is reported without stopping the others. `factory.js andon` watches only the plugins listed in the store's `factory.json`, which only a maintainer can change, and compares each one's latest version with enough jobs against the one before it on every quality measure and job class. It opens one `andon` issue per clear regression, titled with the job class, names any other plugins that changed with the same jobs, and closes the issue when the data or a later version no longer shows the regression. A reviewer can label an alarm `andon-dismissed`: the build then never reopens it but still posts its new numbers. The [store playbook](docs/factory-store-playbook.md) adds `factory.json`, a kaizen issue form, and a build whose issue steps run in their own job with only `issues: write`.

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.99 — 2026-09-27

Every fresh Desk install now has a working browser. Desk declares a `desk-browser` MCP server on Claude and on Copilot, started by the new [`mcp/browser.cjs`](mcp/browser.cjs), so a server of your own named `playwright` stays yours. The launcher starts a copy of `@playwright/mcp` installed in Desk's per-user state folder, under the same compatible Node that Desk's bootstrap picks. The first launch installs it; later launches start it with no network call and refresh it from the `@latest` channel in a detached process, with no pinned version. Installs and refreshes share one lock and switch versions with an atomic rename, so sessions that start together never race, and every npm call runs with no retries and a short timeout, so an unreachable registry fails in seconds with a message naming it. The browser runs headless, so agents never take the operator's focus, and isolated, so concurrent sessions never share a profile. Playwright MCP writes its snapshots to the state folder, never into the session's project, and the launcher logs the version it started. It uses Chrome, or Edge when Chrome is not installed, and passes Chrome's path when it is only in `~/Applications`. `SETUP.md` now lists Chrome or Edge as a prerequisite and checks that the browser opens a page. Signed-in browsing still goes through the claims-based broker, and [`desk:cdp-headed-browser`](skills/cdp-headed-browser/SKILL.md) now routes signed-in work there even when the headless browser is healthy and explains the route on an install with no overlay provider.

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.98 — 2026-09-27

The checkout guard now handles much longer shell loops before it gives up. Before a shell command runs, the guard walks its syntax to find Git calls that would move a protected checkout. A `for` loop whose body ran a command with an unknown exit status used to double the paths it walked on every iteration, so a loop over about ten values ran past the guard's 1,000-step budget and the guard blocked the whole command, which the host records as a failed tool call. The walk now merges identical states after each loop iteration (and after a `while` loop), so a loop costs steps in proportion to its length, and Git inspection stops once one Git call is denied ([shell-commands.js](mcp/src/runtime/shell-commands.js), [protected-checkout.js](mcp/src/runtime/protected-checkout.js)). The step budget itself is unchanged, so a loop still fails closed when its length times the steps per iteration passes 1,000: about 150 to 250 values, depending on the body. This is the countermeasure for kaizen card [ourostack/factory#39](https://github.com/ourostack/factory/issues/39), whose hypothesis is fewer tool failures per job.

Ships `desk-mcp@1.4.0-alpha.6`.

## 3.2.0-alpha.96 — 2026-09-27

Accepted waste labels now reach the store, and finished tasks without labels are noticed at session start. The [flush](mcp/src/factory/flush.js) delivers local labels in the same intake pull request as facts: each becomes `labels/<job>/<session-id>.json` through `toPublishedLabels`, with the job keyed as its session's facts are, and passes the labels gate; a refused one is quarantined under its local key. A rejected intake PR quarantines its labels with its facts, and a stale one sends them again. ## 1.2.0 — 2026-05-22

**`session-start-migrations` framework.** New skill that auto-heals stale machine state when a plugin's canonical names drift (workspace dir renamed, plugin clone moved, symlink target changed, etc.). Walks every enabled plugin's `migrations/<NN>-<slug>.md` dir at session start, runs each migration's Detect predicate, and (for the ones that fire) runs Safety check + Migrate + Announce, then hard-stops the session for restart.

Why this lives in desk (substrate), not in any overlay: overlays sometimes rename themselves, and a migration framework hosted inside the plugin being renamed has to rename itself mid-execution. Substrate-resident means the framework survives any overlay churn.

Design choices:

- **Self-evidencing predicates, no marker file.** Each migration's Detect block inspects actual machine state (a dir's existence, a symlink's target). Robust against restored backups, partial Time Machine snapshots, and any other path where a marker file desyncs from reality. Cost: every Detect runs on every session start; on a machine with no pending migrations (the common case) this is a few cheap bash exits.
- **Four sections (Detect / Safety check / Migrate / Announce)** map cleanly to one concern each. Detect is a pure predicate. Safety guards against partial state. Migrate does the work, idempotently. Announce is the operator-facing message.
- **Cross-plugin ordering by alphabetical filename.** The `<NN>-<slug>.md` convention plus a 2-digit prefix gives global ordering across every plugin's migrations dir; plugins coordinate by picking the next available `NN` rather than via a central registry.
- **`needs_restart: true` hard-stops the session** after the announcement. The operator restarts; the next session begins against canonical paths.

Integration: `desk:session-start` now hands off to this skill in a new Step 0.5 — after Step 0's host-identity probe, before Step 1's prereq probe. The order matters: most later steps assume `$DESK/` resolves to the canonical workspace path, so migrations run first.

This release ships the framework only; concrete migrations live in consumer overlays.

## 1.1.0 — 2026-05-22

**Archive is now searchable.** Reversed the v1.0 indexer behavior that skipped `_archive/` at index time. Archive content was always meant to be preserved for future recall — making it unsearchable defeated the purpose.

What changed:

- **Indexer**: walks under `_archive/` ancestors. Loose `.md` files there (migrated legacy filenames like `2026-02-23-planning-foo.md`) are also indexed — basename pattern infers kind (`-planning-` → planning, `-doing-` → doing, etc.) or falls back to `kind: archive`. Each indexed doc gets a new `is_archived: bool` flag.
- **Search tools**: all five accept an optional `scope: "active" | "archived" | "all"` parameter. **Per-tool defaults match each tool's purpose:**
  - `desk_search` → `active` (day-to-day signal beats archive noise)
  - `desk_recall` → `all` (this IS the historical lookback tool)
  - `desk_similar` → `all` (similarity has no time/status semantic)
  - `desk_timeline` → `all` (already temporally scoped by window)
  - `desk_thread` → no scope param; always walks across (refs don't respect archive boundaries)
- **DB schema**: new `is_archived` column on `docs` table + index. Migration is idempotent: opening an existing v1.0 DB ALTER-ADDs the column with default 0; next reindex populates correctly.

Operator-visible: `desk_recall("teams bot integration")` now finds archived planning/doing notes from months ago. `desk_search("teams bot")` still defaults to active-only — agents asking "what should I do next" get current work, not archived history. Override per-call with `scope: "all"` when historical breadth matters.

Migration: existing indexes auto-upgrade their schema on next open. To populate archive embeddings, run `ouro desk reindex --force` once per bundle (or `mcp call ... desk_reindex --args '{"force":true}'`).

## Setup (v1.0)

After `ouro plugin install github:ourostack/ouroboros-skills:plugins/desk --agent <name>`:

1. **Install plugin's MCP deps:** `cd ~/.ouro-cli/plugins/desk/mcp && npm install`
2. **Install Ollama** for full semantic surface (recall / similar). Mac one-time: `curl -L https://github.com/ollama/ollama/releases/latest/download/ollama-darwin.tgz | tar -xz` then add the binary to PATH. Linux: `curl -fsSL https://ollama.com/install.sh | sh`.
3. **Pull the embedding model:** `ollama serve &` then `ollama pull nomic-embed-text` (one-time, ~274MB).
4. **Restart daemon** so plugin MCP discovery picks up the new server: `ouro stop && ouro up`.

Without Ollama, desk_search falls back to FTS5-only (keyword) and desk_recall/desk_similar return empty. Substrate works; semantic surface is degraded.

## Known limitations (v1.0)

These do NOT block v1.0 use but are tracked for follow-ups:

- **Plugin install does not run `npm install`.** After `ouro plugin install ...`, the operator (or a v1.1 install hook) needs to `cd ~/.ouro-cli/plugins/desk/mcp && npm install`. Otherwise the server can't spawn (`@modelcontextprotocol/sdk`, `better-sqlite3`, `sqlite-vec`, `gray-matter` missing). v1.1: either auto-run install on plugin install OR vendor deps OR ship as a bundled single-file build.
- **Tool input schemas are loose.** `inputSchema: { type: "object", properties: {}, additionalProperties: true }` — agents have to infer from descriptions. Works but agents occasionally pass wrong field names on first attempt. v1.1: define explicit JSON Schema per tool.
- **`mcp__ouro-<agent>__send_message` response wrapper hangs at 600s** when the agent makes multi-tool sequences via desk MCP, even though the agent finishes successfully (artifacts on disk). This is in the **ouro MCP** comms layer, not desk. Tracked separately.
- **Ollama is a soft dep** for full semantic surface. With Ollama down, `desk_search` falls back to FTS-only (still works), `desk_recall` returns empty + a note, `desk_similar` uses stored embeddings only. For the agent-as-substrate promise, the operator should keep Ollama + `nomic-embed-text` available.
- **Daemon must be restarted** after a fresh `ouro plugin install ...` for the new plugin's MCP server to be discovered. v1.1: signal the daemon to reconcile on plugin-list change.

These are upgradable in place — none change the v1.0 wire format or storage schema.
