# Codex rollout format, as read from the Codex source

Status: evidence only, and Codex support is unproven. No Codex session exists on any of our machines, so nothing here was checked against a real rollout file. Every fact below comes from the `openai/codex` source on its `main` channel at commit `60947e234156ac12bdb7fba2477d3965f166bd34` (read 2026-09-30). The fixtures under `sessions/` are hand-written from these facts by `make.js`. Links point at that exact commit; `#L` anchors are line numbers at that commit.

Base for every link: `https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/`. To keep the table short, paths below are relative to that base.

## Where rollouts live

- One file per thread, at `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<YYYY-MM-DD>T<hh-mm-ss>-<thread-uuid>.jsonl`. The date folder and the filename timestamp use the machine's local time at creation ([recorder.rs#L1723-L1744](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L1723-L1744), [rollout_file_name.rs#L62-L76](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/rollout_file_name.rs#L62-L76)).
- The code joins `config.codex_home()` with `sessions`; the recorder's own doc comment shows `~/.codex/sessions/...` ([recorder.rs#L77-L85](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L77-L85)). Not confirmed: how `codex_home()` resolves the `CODEX_HOME` environment variable (that code is outside the files read). `~/.codex` as the default is the documented convention and is consistent with the doc comment.
- A reverted thread has a second id in its filename (`rollout-<ts>-<thread>_<rollout>.jsonl`). The deriver must take the thread id from `session_meta.payload.id`, not from the filename alone. Archived rollouts live under a separate `archived_sessions` folder, out of the `sessions` scan. Rollouts may also be stored compressed (`compression.rs`); the file-name parser strips that suffix. We do not handle compressed files and have not read that format.
- The file is created lazily: the session meta is held in memory until the first persisted item is written (`deferred_creation` in [recorder.rs#L960-L975](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L960-L975)). A thread that never persists anything has no file.
- Thread ids are UUIDs; new ones are UUID v7 ([thread_id.rs#L30](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/thread_id.rs#L30)). Ordering by id is roughly ordering by creation time, but the deriver must not rely on it.

## Line envelope

Each line is one JSON object `{"timestamp": "...", "type": "<item kind>", "payload": {...}}`, with an optional `"ordinal"` number ([history lib.rs `RolloutLine`#L350-L358](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/history/src/lib.rs#L350-L358), wire form [rollout_payload.rs#L33-L76](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/history/src/rollout_payload.rs#L33-L76), writer [recorder.rs#L2063-L2100](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L2063-L2100)).

- `timestamp` is UTC with millisecond precision, `YYYY-MM-DDThh:mm:ss.mmmZ`, stamped when the line is written (not when the event happened).
- `type` is one of: `session_meta`, `response_item`, `inter_agent_communication`, `inter_agent_communication_metadata`, `compacted`, `turn_context`, `token_usage_record`, `world_state`, `retained_context`, `security_risk_score`, `event_msg`, `realtime_item`. `response_item` also carries an optional sibling `metadata` object. New kinds can appear in later versions, so the deriver must ignore unknown `type` values.
- Only some items are written to disk ([policy.rs#L10-L24](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/policy.rs#L10-L24)). Persisted `event_msg` kinds always include `token_count`, `turn_aborted`, `task_started`, `task_complete`; `user_message`, `agent_message`, `mcp_tool_call_end`, `patch_apply_end` and a few others are persisted only in `legacy` history mode, which the source defaults to when a rollout does not say (unconfirmed that it is the mode new threads use: new threads take the configured `default_history_mode`, which was not read) ([protocol.rs#L775-L782](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L775-L782)); `exec_command_end`, `collab_agent_spawn_end`, `patch_apply_begin` and `mcp_tool_call_begin` are never persisted ([policy.rs#L94-L206](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/policy.rs#L94-L206)). So tool facts must come from `response_item` records, not from `exec_command_end` or the spawn-end event.

## `session_meta` (the first record)

`payload` is `SessionMeta` with an optional `git` object flattened beside it ([protocol.rs#L3123-L3249](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3123-L3249), built at [recorder.rs#L935-L969](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L935-L969)).

| Field | Meaning for the deriver |
| --- | --- |
| `id` | This thread's UUID. |
| `session_id` | The root thread's id ("session_id is equal to the root thread's ID"). Older rollouts lack it; the reader then uses `id`. |
| `parent_thread_id` | Optional top-level parent thread id. Present on spawned child threads. |
| `timestamp` | Thread creation instant, UTC ISO with milliseconds. |
| `cwd` | Working directory (free text, private). |
| `originator` | Client name, for example `codex_cli_rs`. |
| `cli_version` | Codex CLI version string: the harness version. |
| `source` | `cli`, `vscode`, `exec`, `mcp`, `{"custom": "..."}`, `{"internal": ...}`, `{"subagent": ...}` or an unknown string that decodes as unknown. |
| `thread_source` | Optional: `user`, `subagent`, `guardian_review`, `memory_consolidation` or a feature name. |
| `agent_nickname`, `agent_role`, `agent_path` | Set on spawned children. `agent_role` also accepts the alias `agent_type`. |
| `model_provider` | Provider id, not the model. |
| `base_instructions` | `{"text": ...}` (free text, private). |
| `git` | Optional `{commit_hash, branch, repository_url}` (branch and URL are free text). |
| `history_mode` | `legacy` or `paginated`, always serialized (`#[serde(default)]`, so an older rollout without it reads as `legacy`; the decoder rejects any other value) ([protocol.rs#L3183](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3183), enum near [#L775-L782](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L775-L782)). Decides which `event_msg` kinds are persisted, see above. The deriver does not read tool facts from `event_msg`, so it does not depend on it. |
| `multi_agent_version` | Optional `disabled`, `v1` or `v2` (confirmed at [protocol.rs#L3083-L3087](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3083-L3087) and [#L3194](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3194)). Which spawn shape the thread uses, see "Spawning child threads". Also present on `turn_context`. |
| `subagent_history_start_ordinal` | Optional number: "first rollout ordinal that belongs to this subagent's own projected history. Earlier rollout records are inherited model context" ([protocol.rs#L3188-L3193](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3188-L3193)). A child rollout may therefore begin with records copied from its parent. The deriver skips records whose `ordinal` is below this value, so a parent's tool calls are never counted twice. Not confirmed: whether a real child rollout carries such records. |

There is no model on `session_meta`; the model lives on `turn_context`. There is no `instructions` field any more (the source comment says it moved to the turn context).

### Where a child names its parent

A spawned child has both `payload.parent_thread_id` and `payload.source = {"subagent": {"thread_spawn": {"parent_thread_id", "depth", "agent_path", "agent_nickname", "agent_role"}}}` ([SubAgentSource#L2906-L2925](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2906-L2925)). The spawner passes both ([spawn.rs#L113-L133](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs#L113-L133), [recorder.rs#L935-L955](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L935-L955)). `depth` is 1 for a child of the root. The child's `session_id` is the root thread's id even for a grandchild, which is a cheap check for the R5 scan but not a substitute for the exact parent id match. A thread can also carry `forked_from_id` (a fork of another thread's history); that is not a spawn and must not join the tree. Other subagent sources (`review`, `compact`, `memory_consolidation`, `other`) have no parent field; the deriver treats them as not part of the tree.

Not confirmed: whether `parent_thread_id` can be absent while `source.subagent.thread_spawn.parent_thread_id` is present on older rollouts. The deriver should accept either.

## `turn_context` (once per real user turn)

`payload` is `TurnContextItem` ([protocol.rs#L3301-L3400](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3301-L3400)). Fields the deriver may read: `model` (the resolved model for the turn, a plain string), `effort` (reasoning effort, optional), `turn_id`, `root_turn_id` (set only on subagent turns; the originating root turn), `cwd`. Everything else (approval policy, sandbox policy, permission profile, network lists) is configuration and not needed. The record is written again after a mid-turn compaction. A child's model can differ from the root's because of a spawn-time `model` argument or a role override.

## Timing and tokens (`event_msg`)

`event_msg` payloads carry their own `type` tag in `snake_case` ([EventMsg#L1358](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L1358)).

- `task_started` (also accepts alias `turn_started`): `turn_id`, `root_turn_id?`, `started_at?` (Unix seconds), `model_context_window`, `collaboration_mode_kind` ([#L2179-L2195](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2179-L2195)).
- `task_complete` (alias `turn_complete`): `turn_id`, `last_agent_message` (free text, private), `error?`, `started_at?`, `completed_at?` (Unix seconds), `duration_ms?`, `time_to_first_token_ms?` ([#L2153-L2177](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2153-L2177)).
- `turn_aborted`: `turn_id?`, `reason` (`interrupted`, `replaced`, `review_ended`, `budget_limited`), `started_at?`, `completed_at?`, `duration_ms?` ([#L4257-L4285](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L4257-L4285)).
- `token_count`: `info` (nullable) holding `total_token_usage` and `last_token_usage`, each `{input_tokens, cached_input_tokens, cache_write_input_tokens, output_tokens, reasoning_output_tokens, total_tokens}`, plus `model_context_window`; and `rate_limits` ([#L2241-L2262](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2241-L2262), [#L2276-L2282](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2276-L2282), [#L2343-L2347](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2343-L2347)). `total_token_usage` is cumulative for the thread (each event adds the last usage to it), so the last `token_count` with a non-null `info` gives the thread total. `input_tokens` appears to include the cached share (`cached_input_tokens` is a subset); the code does not say so in the files read, so treat that as unconfirmed before pricing anything.
- `token_usage_record` (a separate top-level record type) also exists: per-response usage with `thread_id`, `turn_id`, `session_id`, `root_turn_id`, `response_id`, `usage`, `turn_token_usage`, `thread_token_usage` ([#L2264-L2274](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L2264-L2274)). Not confirmed: when it is emitted in a normal CLI session. The fixtures do not include it.
- `response_item` records have no timing of their own beyond the line `timestamp`. A tool call's duration is the gap between the call line and its output line, which reflects write times, not exact execution.

## `response_item` payloads

`payload.type` is one of `message`, `agent_message`, `reasoning`, `local_shell_call`, `function_call`, `tool_search_call`, `function_call_output`, `tool_search_output`, `custom_tool_call`, `custom_tool_call_output`, `web_search_call`, `image_generation_call`, `configuration_update`, `compaction`, `context_compaction` ([models.rs#L1012-L1215](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/models.rs#L1012-L1215), persisted set [policy.rs#L44-L66](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/policy.rs#L44-L66)).

- `message`: `role` (`user`, `assistant`, `developer`) and `content`, an array of `{type: "input_text" | "output_text" | "input_image" | "input_audio", text}` ([#L878-L900](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/models.rs#L878-L900)). Injected context (environment, AGENTS.md) also arrives as `user` or `developer` messages, so a `user` message is not proof of a human prompt. Whether a real human prompt can be told apart from injected context was not established from the source files read.
- `reasoning`: `summary` array of `{type: "summary_text", text}`, optional `content`, `encrypted_content`.
- `function_call`: `name`, optional `namespace`, `arguments` (a JSON string, not an object), `call_id`. Its result is a `function_call_output` with the same `call_id` and `output`, a plain string or an array of content items ([#L2175-L2215](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/models.rs#L2175-L2215)). Output carries no separate success or exit code on the wire; the `success` field is internal.
- `custom_tool_call`: `name`, `input` (a raw string), `call_id`, optional `status`; its result is `custom_tool_call_output` with `call_id` and `output`.
- `local_shell_call`: `call_id?`, `status`, `action: {type: "exec", command: [argv...], timeout_ms, working_directory, env, user}` ([#L1939-L1950](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/models.rs#L1939-L1950)). Its output arrives as a `function_call_output` with the same `call_id`. Whether current models still emit `local_shell_call` was not established.
- `web_search_call`: optional `status` and `action` (`search` with `query` or `queries`, `open_page`, ...) ([#L1185-L1200](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/models.rs#L1185-L1200)).

### Shell commands

The unified-exec tool is named `exec_command` with parameters `cmd` (a shell command string), `workdir`, `tty`, `yield_time_ms`, `max_output_tokens` ([shell_spec.rs#L34-L110](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/shell_spec.rs#L34-L110)). A long command returns a session id and is continued with `write_stdin` (same file, line 146). So a `git commit` is a `function_call` whose `name` is `exec_command` and whose JSON `arguments.cmd` contains the command; its `function_call_output` holds the output text. Not confirmed from the files read: the exact text layout of `exec_command` output (for example a header with exit code and wall time), and whether older or alternate tools named `shell` or `shell_command` still exist at this commit. The deriver should find commands in `exec_command.cmd`, in `local_shell_call.action.command`, and be prepared for a `command` argument on other function names. A PR URL is found by scanning the output string of the call that ran `gh pr create`.

### Apply patch

`apply_patch` is a freeform (custom) tool ([apply_patch_spec.rs#L19-L32](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/apply_patch_spec.rs#L19-L32)), so it appears as `custom_tool_call` with `name: "apply_patch"` and `input` holding the patch text (`*** Begin Patch`, then `*** Add File: <path>`, `*** Update File: <path>`, `*** Delete File: <path>`, then `*** End Patch`). The hunk-header words come from the tool's grammar file `assets/tools/apply_patch.lark`, which was not read; they are also the long-standing documented patch format. The shell path can also intercept an `apply_patch` command typed into `exec_command` (`intercept_apply_patch` is imported in [exec_command.rs#L14](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/unified_exec/exec_command.rs#L14)), so the same patch text can also appear inside an `exec_command.cmd`. The `patch_apply_end` event, which carries a `changes` map of paths, is persisted only in legacy history mode ([#L3744-L3762](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L3744-L3762)).

### MCP tools

The model-visible MCP tool name is `mcp__<server>__<tool>`: prefix `mcp`, delimiter `__` ([codex-mcp mod.rs#L66-L86](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/codex-mcp/src/mcp/mod.rs#L66-L86)). Some servers' namespaces omit the `mcp__` prefix (same file, around line 177). A tool identity is a `namespace` plus a `name` ([tool_name.rs](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/tool_name.rs), display form is `namespace` followed directly by `name`). Not confirmed: whether the rollout's `function_call` stores an MCP call as `namespace: "mcp__server__"` with `name: "tool"`, or as one joined `name`. The fixture uses the split form; the deriver should join `namespace` and `name` before matching and also accept a joined name.

## Spawning child threads

There are two multi-agent versions. `SessionMeta.multi_agent_version` and `TurnContextItem.multi_agent_version` record which one a thread uses. Both spawn through a `function_call` named `spawn_agent`.

- Version 1: `namespace: "multi_agent_v1"`, `arguments` = `{message | items, agent_type?, model?, reasoning_effort?, fork_context?}`; output JSON `{agent_id, nickname}`, where `agent_id` is the child's thread id ([multi_agents_spec.rs#L14](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L14), [#L604-L641](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L604-L641), [#L409-L425](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L409-L425), [spawn.rs#L217-L231](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs#L217-L231)).
- Version 2: no namespace, `arguments` = `{message, task_name, agent_type?, model?, reasoning_effort?, fork_turns?}`; output JSON `{task_name, nickname}` with no thread id ([multi_agents_spec.rs#L643-L681](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L643-L681), [#L427-L456](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L427-L456), [v2 spawn.rs#L261-L271](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs#L261-L271)). The message may be encrypted in the model-facing schema (`with_encrypted`); whether the rollout then stores the `message` argument in clear was not established.
- Because version 2 returns no thread id, the deriver must link children by the child's own `session_meta` (R5), never by parsing the spawn output. The spawn prompt reaches the child as its first `user` `message`, so `Desk-Task:` is searchable in either the parent's `spawn_agent` arguments or the child's first message. Neither `message` nor `items` was confirmed to be stored unmodified.
- The requested model for a child is the spawn-time `model` argument (optional); the resolved model is the child's `turn_context.model`. The spawn-end event carries the "effective model used by the spawned agent after inheritance and role overrides" ([#L4329-L4352](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L4329-L4352)), but it is not persisted.
- Other collaboration tools (`send_input`, `send_message`, `followup_task`, `wait_agent`, `resume_agent`, `close_agent`, `interrupt_agent`, `list_agents`) exist but create no threads. A `resume_agent` reopens an existing thread, which keeps its original parent.

## Built-in agent types

The `agent_type` argument and `agent_role` field carry a role name. Built-in roles at this commit: `default` (the role used when `agent_type` is omitted), `explorer` and `worker`. An `awaiter` role is defined but commented out of the built-in list ([role.rs#L33](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/agent/role.rs#L33), [#L343-L400](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/agent/role.rs#L343-L400); bundled configs `explorer.toml` and `awaiter.toml` under [assets/agent/builtins](https://github.com/openai/codex/tree/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/assets/agent/builtins)). Users can define more roles in their own config, so any other value is a custom role and must not be published raw. Suggested allowlist for `codex-cli`: `default`, `explorer`, `worker`.

## Hooks (for the capture ruling)

Codex has hooks. The event names are `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `Interrupt` ([HookEventName#L1576-L1592](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L1576-L1592)). Handlers can be command, MCP-tool or prompt hooks ([#L1594](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/protocol/src/protocol.rs#L1594)). Declarations are discovered from `hooks.json` in a config folder and from config TOML ([discovery.rs#L339-L350](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/hooks/src/engine/discovery.rs#L339-L350)).

- `Stop` fires at the end of a root turn; the child-thread equivalent is `SubagentStop` ([hook_runtime.rs#L400](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/hook_runtime.rs#L400)). Its stdin JSON is `{session_id, turn_id, transcript_path (nullable), cwd, hook_event_name, model, permission_mode, stop_hook_active, last_assistant_message}` ([schema.rs#L588-L601](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/hooks/src/schema.rs#L588-L601)).
- `SessionEnd` fires once, at root-thread shutdown, and is skipped for subagent threads ([hook_runtime.rs#L471-L499](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/hook_runtime.rs#L471-L499), called from [session/handlers.rs#L323](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/core/src/session/handlers.rs#L323)). Its stdin JSON is `{session_id, transcript_path (nullable), cwd, hook_event_name: "SessionEnd", reason: "other"}` ([schema.rs#L512-L523](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/hooks/src/schema.rs#L512-L523)). The rollout is flushed before the hook runs, so the file is complete when the hook reads it. The default timeout is 1 second and the maximum is 3 ([session_end.rs#L21-L24](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/hooks/src/events/session_end.rs#L21-L24)). `session_id` is the root thread's id.
- Consequences for capture: a hook that fires when a session ends exists (`SessionEnd`), and `Stop` fires per turn. `SessionEnd` only runs on a clean shutdown; a killed process or a crash never fires it, so the session-start sweep over `$CODEX_HOME/sessions` is still needed as a backstop. Not confirmed: the exact `hooks.json` file schema (matcher and command fields) and how a user-level hook is trusted or enabled; those live in `declarations.rs` and `discovery.rs`, which were only skimmed. Task 6 has to read them before writing the activation.

## What the fixtures assume beyond the source

- The grandchild's rollout sits in the next day's folder (`2026/09/26`, its start is after midnight) on purpose, to exercise the R5 scan's day-plus-one range. It is not something the source says a real grandchild does.

- The deriver treats `session_meta.payload.session_id` as the root thread id when present. The fixtures set it on every thread, as the recorder does.
- The fixtures' CLI version (`0.142.0`) and model names (`gpt-5.5`, `gpt-5.5-mini`) are invented; the source only says they are strings.
- The `exec_command` output strings in the fixtures are free text chosen to hold a commit line and a PR URL. A real output may have a header we have not seen.
- A truncated file is an interrupted write: the writer appends one full `json + "\n"` per item and flushes, so a half line is only possible after a crash or a copy in progress ([recorder.rs#L2091-L2098](https://github.com/openai/codex/blob/60947e234156ac12bdb7fba2477d3965f166bd34/codex-rs/rollout/src/recorder.rs#L2091-L2098)). The recorder repairs a missing final newline on reopen (`ensure_rollout_is_newline_terminated`, recorder.rs line 2043).
