# Boot roadmap

The session boot (`plugins/desk/mcp/scripts/session-boot.js`) now checks only what the first reply needs. On a desk with 80 open tasks it went from 48 to 50 s to 4 to 8 s, measured on a heavily loaded Mac. The checks below were removed from a boot that names no task, or cut short. Bring one back only when a real session needs it, and record which session.

| Removed or cut check | Problem it would solve |
| --- | --- |
| Push routes for every open task's repos | Knowing, before the operator picks a task, which account can push each repo. Today the boot checks routes only for the task named with `--task`. Once the operator picks a task, the agent runs `--task "<handle>" --task-only`, which prints only that task's routes, repos and instructions, and `git-hygiene` asks for the route before a task's first push. On a desk with many repos the all-task check was one GitHub call per account per repo and alone used the whole 45 s budget. |
| Repo state (branch, clean or dirty, fetch) for every open task's repos | Seeing every clone's state in the first status block. Today only the named task's repos are fetched and read. A cheap local-only read (no fetch) for all repos could come back if agents miss it. |
| One `gh pr list` call per repo | Nothing: one GitHub search (`author:@me`, the 100 most recently updated) replaces it. The boot says when there were more than 100. The search counts against GitHub's search limit of 30 requests a minute per account, so many sessions booting in the same minute could hit it; each repo then shows "GitHub search failed". |
| Sign-off scan run twice | Nothing: the factory status no longer scans deliveries that the sign-off step scans anyway. |
| A 45 s wall-clock budget | Waiting longer on a slow network. The budget is now 15 s for the network checks, which run while the desk syncs. The sync keeps its own 20 s limit and is never cut short. |
| Copilot session-start hook lines past 3.5 s | Only the Copilot hook has this limit, because Copilot stops a session-start hook at 5 s; the Claude hook has none. Past 3.5 s the Copilot hook prints the Desk foundation without its pre-check, migration and commit-trailer lines, and it does not start factory delivery: that delivery waits for the next session start or the next hook run. The boot script runs the migration checks again, but not the hook's pre-checks (factory finalize, labels, andon, desk health, workspace tidy), which wait for the next session start. Raising Copilot's `sessionStart` time limit would let the hook drop this cut-off. |
| Waiting for the factory status lock | Recording a boot-check skip or the sign-off count while another writer holds the lock. The hooks and the boot now skip that record instead of waiting, so a process that exits after its output never leaves the lock behind. |
| `unchecked` migration lines in the hooks | Saying that a migration's check ran out of time. The boot script runs every migration check again with its own budget and reports what it finds. |
