## What

The Copilot app keeps a skill's text in memory for as long as it runs, so the skills of MS Desk, `cit`, Crew and Desk itself stay stale until the app restarts, even after Agency has fetched a newer release. Desk's tools already update in place; skills cannot.

Boot's result and `desk_status` now carry one plain line when a plugin loaded in this process is older than the newest release Agency has fetched:

> There's an update to `<plugin>` (`<from>` → `<to>`); restart the Copilot app when it suits you to pick it up.

On a Mac where Housesitter's auto-restart job is installed, the line says Housesitter will restart the app when nobody is using it, with each session asked to reach a safe point first and resumed after.

- `src/runtime/plugin-update.js`: reads the `root-N` folders beside Desk's own session root and the newest unpinned release per plugin in Agency's `cache_index.json` for the same engine. A few local reads, no network, never throws.
- Boot prints the line under the status line and fills `plugin_update`. Desk itself is left out while the stale-Desk line is printed, so one update is not announced twice.
- `desk_status` adds `plugin_update` (compact: `line` and a `relay` note to say it once per session; full: the finding).
- Silent outside an Agency session, without a known engine, with no cache, and in a `node:test` run.

## Tests

`tests/desk/mcp/__tests__/runtime/plugin_update.test.js`: sibling roots in both manifest places, the cache (this engine only, no pinned commits, newest fetch), the manual and automatic lines, current/newer/unknown plugins, no session folder or engine or cache, the launcher root when Desk runs from a release copy, off under `node:test`, and boot's line, JSON field and failure isolation. `status_compact.test.js` covers `desk_status`.

`node scripts/skill-evals.cjs run --changed` reports no suite's contract or reviewed sources differ, so no eval needed a rerun.
